## @description

### Контекст
В истории заказов «Ложка» показывает, за сколько минут привезли еду, и рядом — короткую оценку скорости. Менеджер продукта прислал правила:

- до 25 минут включительно — «Молниеносно»;
- от 26 до 45 минут — «Вовремя»;
- от 46 до 60 минут — «С небольшой задержкой»;
- дольше часа — «Опоздали».

И одно исключение: «В плохую погоду курьерам тяжело. Если шёл дождь или снег, доставку за 46–60 минут не считаем задержкой — пишем "Вовремя, несмотря на погоду"».

Минут может быть сколько угодно: 7, 38, 52. Перечислять в `case` каждое число через запятую слишком долго. К счастью, `switch` умеет работать с целыми промежутками чисел.

### Новое в Swift
**Диапазон** — это все числа от одного до другого. Записывается через три точки: `1...5` означает «от 1 до 5 включительно», то есть 1, 2, 3, 4 и 5. Обе границы входят.

Диапазон можно поставить в `case` вместо отдельного значения. Ветка сработает, если число попало в промежуток:

```swift
let dishesInOrder = 7
var kitchenLoad = ""

switch dishesInOrder {
case 1...3:
    kitchenLoad = "Маленький заказ"
case 4...8:
    kitchenLoad = "Средний заказ"
default:
    kitchenLoad = "Большой заказ, готовим дольше"
}
```

Здесь `7` попадает в `4...8`. Числа за пределами обоих диапазонов уходят в `default` — он по-прежнему обязателен, ведь целых чисел бесконечно много.

Следи, чтобы диапазоны стыковались без дыр: после `1...3` идёт `4...8`, а не `5...8`. Иначе число 4 молча попадёт в `default`.

**Дополнительное условие `where`.** Иногда попадания в диапазон мало: ветка должна сработать, только когда верно что-то ещё. Тогда после значения пишут слово `where` («где», «при условии») и условие типа `Bool`:

```swift
let guests = 6
let hasBigTable = false
var answer = ""

switch guests {
case 1...4:
    answer = "Столик найдётся"
case 5...8 where hasBigTable:
    answer = "Посадим за большой стол"
case 5...8:
    answer = "Сдвинем два столика"
default:
    answer = "Позвоните в ресторан"
}
```

Ветка с `where` срабатывает, когда выполнено и то и другое: гостей от 5 до 8 **и** большой стол свободен. Здесь стол занят, поэтому Swift пропускает эту ветку и идёт дальше — к обычной `case 5...8`.

Отсюда правило: **ветка с `where` стоит выше** обычной ветки с тем же диапазоном. Swift берёт первую подходящую, и если обычная окажется первой, до особого случая очередь не дойдёт никогда.

> 💡 Бывает и диапазон, в который правая граница не входит: `1..<5` — это «от 1 до 5, не включая 5», то есть 1, 2, 3 и 4. Он пригодится позже, а в этой задаче удобнее три точки.

### Задача
В редакторе есть время доставки в минутах `deliveryMinutes`, признак плохой погоды `isBadWeather`, переменная `speedLabel` и два готовых `print`. Не переименовывай данные — проверка подставит другие значения.

Между объявлением `speedLabel` и последним `print` напиши `switch` по `deliveryMinutes`. Он кладёт в `speedLabel` оценку:

1. от 0 до 25 минут — `Молниеносно`
2. от 26 до 45 минут — `Вовремя`
3. от 46 до 60 минут **в плохую погоду** — `Вовремя, несмотря на погоду`. Это ветка с `where`.
4. от 46 до 60 минут в обычную погоду — `С небольшой задержкой`
5. всё остальное — `Опоздали`

На остальные оценки погода не влияет: 30 минут — это «Вовремя» при любой погоде, а 70 минут — «Опоздали» даже в ливень.

### Пример
Для данных из редактора (52 минуты, плохая погода):

```text
Доставили за 52 мин.
Оценка: Вовремя, несмотря на погоду
```

Те же 52 минуты в ясный день:

```text
Доставили за 52 мин.
Оценка: С небольшой задержкой
```

## @solution
```swift
// Входные данные (их подменяет проверка — не переименовывай)
let deliveryMinutes = 52
let isBadWeather = true

print("Доставили за \(deliveryMinutes) мин.")

// Оценка скорости для истории заказов
var speedLabel = ""

// Напиши switch по deliveryMinutes: диапазоны минут и одна ветка с where
switch deliveryMinutes {
case 0...25:
    speedLabel = "Молниеносно"
case 26...45:
    speedLabel = "Вовремя"
case 46...60 where isBadWeather:
    speedLabel = "Вовремя, несмотря на погоду"
case 46...60:
    speedLabel = "С небольшой задержкой"
default:
    speedLabel = "Опоздали"
}

print("Оценка: \(speedLabel)")
```

## @rules
- must: /\bswitch\b/ :: В этой задаче минуты нужно разобрать оператором `switch`.
- must: /\bcase\s+\d+\s*\.\.[.<]/ :: В ветках `case` должны стоять диапазоны минут, например `case 0...25:`.
- must: /\bwhere\b/ :: Особый случай плохой погоды оформи отдельной веткой с `where`: `case 46...60 where isBadWeather:`.

## @hint1
Тебе нужен один `switch` из пяти веток — по одной на каждую строку списка из задания. Разбирается константа `deliveryMinutes`.

Первые две ветки простые: после `case` стоит диапазон минут — начальное число, три точки, конечное число — и двоеточие. Под ним — присваивание текста в `speedLabel`. Границы бери прямо из правил: первый диапазон заканчивается на 25, второй начинается с 26 и заканчивается на 45.

Третья и четвёртая ветки — про один и тот же промежуток, от 46 до 60. Отличаются они только погодой. В особой ветке после диапазона допиши слово `where` и имя константы `isBadWeather`: она и есть условие. Обычная ветка — тот же диапазон без `where`.

Порядок здесь важен. Swift берёт первую подходящую ветку, поэтому ветка с `where` должна стоять выше обычной. Иначе обычная перехватит все значения от 46 до 60, и до погоды дело не дойдёт.

Последняя ветка — `default`: туда попадёт всё, что больше 60.

## @hint2
Диапазон в `case` и ветка с дополнительным условием выглядят так:

```swift
switch guests {
case 1...4:
    answer = "Столик найдётся"
case 5...8 where hasBigTable:
    answer = "Посадим за большой стол"
case 5...8:
    answer = "Сдвинем два столика"
default:
    answer = "Позвоните в ресторан"
}
```

Ветка с `where` и обычная ветка используют один и тот же диапазон, и особая стоит первой.

## @hint3
Первые две ветки готовы. Допиши остальные:

```swift
switch deliveryMinutes {
case 0...25:
    speedLabel = "Молниеносно"
case 26...45:
    speedLabel = "Вовремя"
case 46...60 where ___:
    speedLabel = "Вовремя, несмотря на погоду"
case ___:
    speedLabel = "С небольшой задержкой"
default:
    speedLabel = ___
}
```

В первом пропуске — константа типа `Bool`, которая говорит о плохой погоде. Во втором — тот же диапазон, что и строкой выше, но уже без условия. В третьем — текст для доставки дольше часа.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Swift берёт `deliveryMinutes` — в редакторе это 52 — и идёт по веткам сверху вниз. В `0...25` число не попадает, в `26...45` тоже. Третья ветка: 52 лежит в `46...60`, но этого мало — нужно проверить условие после `where`. В `isBadWeather` лежит `true`, значит, ветка подходит. В `speedLabel` попадает «Вовремя, несмотря на погоду», и Swift выходит из `switch`. В ясный день условие `where` было бы ложным: Swift пропустил бы эту ветку и остановился на следующей, обычной `case 46...60`.

**Почему ветка с `where` стоит выше.** `switch` всегда выбирает первую подходящую ветку. Поменяй третью и четвёртую местами — и обычная `case 46...60` будет забирать все значения от 46 до 60 при любой погоде. Особая ветка останется в коде, но не сработает ни разу. Правило: частный случай — выше общего.

**Почему `where` только в одной ветке.** Погода меняет оценку лишь для промежутка 46–60. На 30 минут и на 70 минут она не влияет, поэтому в остальных ветках условия нет. Сценарии проверки это учитывают: 45 минут в дождь — просто «Вовремя», 61 минута в дождь — «Опоздали».

**Почему диапазоны, а не `else if`.** Цепочка `if deliveryMinutes <= 25 { ... } else if deliveryMinutes <= 45 { ... }` дала бы тот же результат. Но в `switch` каждая ветка показывает промежуток целиком — и начало, и конец. Таблицу из задания можно сверить с кодом построчно.

**Типичные ошибки:**

- дыра или наложение между диапазонами: `0...25` и `25...45` или `0...25` и `27...45`. Границы должны идти подряд: 25, затем 26;
- две точки вместо трёх: `0..25` — такого оператора нет;
- после `where` написано `isBadWeather = true` с одним знаком равенства. Достаточно просто имени константы;
- забыт `default` — Swift не соберёт код, потому что числа больше 60 остались без ответа.
