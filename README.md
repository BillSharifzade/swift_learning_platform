# Bonnie's Learning Platform — a Swift course made for one person

An interactive, Russian-language Swift course that runs as a plain static site (GitHub Pages friendly).
She writes code in the browser, presses **Проверить**, and the code is compiled and run by the real
Swift 6.2 compiler. Every error is explained in Russian — where it is, what happened, why it is an error and
how to fix it — followed by a handwritten note from you. Every solved task opens a gift.

- 18 modules, from the first `print` to concurrency and capstone projects (see `content/SYLLABUS.md`)
- every task is a slice of a real app: a coffee shop, a store, food delivery, a music player, payments…
- 4 hint levels per task: words → code fragment → almost complete → full solution with explanation
- progress, streak, lit stars and the gift collection are stored in her browser

## Publish on GitHub Pages

```bash
git init
git add .
git commit -m "Bonnie's Learning Platform"
git branch -M main
git remote add origin git@github.com:<you>/<repo>.git
git push -u origin main
```

Then on GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch → `main` / `(root)`**.
The site appears at `https://<you>.github.io/<repo>/` in a minute or two. There is no build step on GitHub:
the repository root *is* the site (`.nojekyll` tells Pages to serve files as they are).

The repository can be private only on a paid GitHub plan; on a free plan Pages needs a public repo.
The page carries `noindex`, so search engines will not list it.

## Run locally

```bash
python3 -m http.server 4173
# open http://localhost:4173
```

Opening `index.html` straight from disk will not work (browsers block module scripts on `file://`).

## Make it yours

| What | Where |
|---|---|
| Pet names for her, your signatures, the title | `config.js` |
| Notes shown under errors, "stuck" notes, daily lines on the home page | `config.js` → `notes` |
| Gifts: picture, name and your message for each task and each module | `assets/js/data/gifts.js` |
| Open all tasks at once instead of one by one | `config.js` → `unlock: 'free'` |

`{her}` inside a note is replaced with a random pet name from `config.js`. After editing, just reload the page.
New gift pictures: add the entry to `gifts.js`, then `node tools/fetch-gifts.mjs`.

## How checking works

`assets/js/engine/` is the judge. On **Проверить** it:

1. runs a local pre-check (unclosed brackets or quotes, curly quotes, a Russian letter inside an English word);
2. sends her code plus the task's hidden tests to **Compiler Explorer** (`godbolt.org`, compiler `swift624`);
3. turns compiler diagnostics and runtime crashes into Russian explanations (`explain.js`, about 150 patterns)
   and maps them back to the exact line and column in her code;
4. compares program output and test results, and for early modules re-runs the program with different input
   data so that a hard-coded answer does not pass.

So the site needs an internet connection, and the text of her solutions is sent to godbolt.org
(no account, no name, nothing else). If that service is down, she sees a "try again" message and nothing is lost.
The compiler endpoint is configurable in `config.js` if you ever want to point it at your own runner.

## Progress

Stored in `localStorage` of her browser — there is no server. **Настройки → Сохранить прогресс в файл** exports
it; the same dialog imports it on another device. Clearing site data erases it, so an occasional export is wise.

## Editing or adding tasks

Tasks live in `content/<module>/<NN-name>.md`; the format and the quality rules are in `content/README.md`.

```bash
node tools/validate.mjs 03-conditions      # reference solution passes, starter does not, format is right
node tools/try.mjs content/03-conditions/02-open-or-closed.md attempt.swift   # judge any code like the site does
node tools/build.mjs                       # content/ → data/ (what the site loads); commit data/ too
```

Validation compiles with the same Swift version as the site, in Docker (`swift:6.2` image, started automatically).

## Layout

```
index.html, config.js        the page and your personal settings
assets/js/engine/            judge: harness, pre-check, compiler output parser, explanations, runner
assets/js/views/, ui/        screens (home, task, gifts) and UI pieces (sky, gift reveal, effects)
assets/js/data/gifts.js      gift catalogue
assets/gifts/, fonts/, vendor/   pictures, fonts and libraries, all local (no CDN)
content/                     task sources (Markdown) + authoring guide + syllabus
data/                        built course data (generated by tools/build.mjs)
tools/                       build, validate, try, fetch-gifts
```
