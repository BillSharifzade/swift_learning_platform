## @description

### Контекст
Над списком товаров в каталоге есть выпадающий список «Сортировка»: сначала дешёвые, сначала дорогие, по рейтингу, по названию. Покупатель выбирает вариант — список перестраивается.

Дизайнер уже нарисовала этот список, а в коде для него есть перечисление `SortOption`. Не хватает главного — самой сортировки. Тимлид добавляет: «Замыкания пиши коротко, через `$0` и `$1`. Так принято, и так легче читать».

### Новое в Swift
Метод `sorted()` тебе знаком: он сортирует числа и строки. Но как сравнить два товара? По цене? По рейтингу? Swift этого не знает, поэтому для массива структур `sorted()` не работает.

На такой случай есть `sorted(by:)`. Он принимает замыкание с двумя параметрами — двумя элементами массива. Замыкание отвечает `true` или `false` на вопрос: «первый должен стоять раньше второго?»

Возьмём магазины продавцов:

```swift
struct Shop {
    let title: String
    let reviews: Int
}

let shops = [
    Shop(title: "Тёплый дом", reviews: 120),
    Shop(title: "Глина и огонь", reviews: 340),
    Shop(title: "Бусинка", reviews: 85)
]
```

Отсортируем их по числу отзывов, от большего к меньшему. Полная запись:

```swift
let popular = shops.sorted(by: { (a: Shop, b: Shop) -> Bool in
    return a.reviews > b.reviews
})
```

Теперь будем сокращать — шаг за шагом. Смысл при этом не меняется.

**Шаг 1. Убираем типы.** Swift и так знает, что в массиве лежат `Shop`, а ответ должен быть `Bool`:

```swift
shops.sorted(by: { a, b in return a.reviews > b.reviews })
```

**Шаг 2. Убираем `return`.** Если в теле одно выражение, его результат возвращается сам — как в коротких функциях:

```swift
shops.sorted(by: { a, b in a.reviews > b.reviews })
```

**Шаг 3. Убираем имена параметров.** У параметров замыкания есть готовые имена: `$0` — первый, `$1` — второй. Если пользоваться ими, список параметров и слово `in` не нужны:

```swift
shops.sorted(by: { $0.reviews > $1.reviews })
```

**Шаг 4. Выносим замыкание в хвост.** Замыкание — единственный аргумент, поэтому круглые скобки можно не писать совсем:

```swift
shops.sorted { $0.reviews > $1.reviews }
```

Все пять записей дают один и тот же результат: «Глина и огонь», «Тёплый дом», «Бусинка».

Направление сортировки задаёт знак: `<` — по возрастанию (от меньшего к большему), `>` — по убыванию. Строки сравниваются так же: `$0.title < $1.title` — по алфавиту, от А до Я.

> 💡 `sorted` не меняет исходный массив. Он возвращает новый, отсортированный, а `shops` остаётся как был.

> ⚠️ `$0` и `$1` хороши для коротких замыканий в одну строку. Если тело длиннее, лучше дать параметрам понятные имена.

### Задача
В редакторе есть структура `Product`, перечисление `SortOption` и заготовка функции `sortedCatalog(_:by:)`. Она принимает массив товаров и вариант сортировки, а возвращает новый массив.

Допиши тело функции. Внутри — `switch` по `option`, в каждой ветке возвращается результат `sorted`:

1. `.cheapFirst` — по цене, от дешёвых к дорогим.
2. `.expensiveFirst` — по цене, от дорогих к дешёвым.
3. `.topRated` — по рейтингу, от высокого к низкому.
4. `.byName` — по названию, от А до Я.

Замыкания записывай коротко — через `$0` и `$1`. Циклы в этой задаче не нужны.

### Пример
```swift
let products = [
    Product(name: "Плед вязаный", price: 2400, rating: 4.9),
    Product(name: "Свеча соевая", price: 650, rating: 4.6),
    Product(name: "Кружка керамическая", price: 890, rating: 4.8)
]

sortedCatalog(products, by: .cheapFirst)
// Свеча соевая, Кружка керамическая, Плед вязаный

sortedCatalog(products, by: .topRated)
// Плед вязаный, Кружка керамическая, Свеча соевая

sortedCatalog(products, by: .byName)
// Кружка керамическая, Плед вязаный, Свеча соевая
```

## @solution
```swift
struct Product {
    let name: String
    let price: Int
    let rating: Double
}

// Варианты из выпадающего списка «Сортировка»
enum SortOption {
    case cheapFirst      // сначала дешёвые
    case expensiveFirst  // сначала дорогие
    case topRated        // сначала с высоким рейтингом
    case byName          // по названию, от А до Я
}

// Возвращает каталог, отсортированный выбранным способом
func sortedCatalog(_ products: [Product], by option: SortOption) -> [Product] {
    // Напиши switch по option.
    // В каждой ветке верни products.sorted { ... } с коротким замыканием
    switch option {
    case .cheapFirst:
        return products.sorted { $0.price < $1.price }
    case .expensiveFirst:
        return products.sorted { $0.price > $1.price }
    case .topRated:
        return products.sorted { $0.rating > $1.rating }
    case .byName:
        return products.sorted { $0.name < $1.name }
    }
}
```

## @rules
- must: /\.sorted\s*(\{|\(\s*by\s*:)/ :: Для сортировки используй метод `sorted` с замыканием: `products.sorted { ... }`.
- must: /\$0/ :: Запиши замыкания коротко: первый параметр — это `$0`.
- must: /\$1/ :: Запиши замыкания коротко: второй параметр — это `$1`.
- mustnot: /\b(for|while|repeat)\b/ :: Циклы здесь не нужны — всю работу делает `sorted` с замыканием.

## @hint1
Функция уже объявлена, нужно написать её тело. Оно состоит из одного `switch` по параметру `option`. У перечисления `SortOption` четыре варианта — значит, в `switch` будет четыре ветки `case`. Ветка `default` не нужна: все варианты перечислены.

В каждой ветке одна строка: `return` и вызов `sorted` у массива `products`. После слова `sorted` сразу открывается фигурная скобка — это замыкание в хвосте. Внутри него сравнение двух товаров: `$0` — первый, `$1` — второй. У каждого берёшь нужное свойство через точку.

Какое свойство и какой знак ставить, подскажет вопрос: «что должно быть правдой, чтобы первый товар стоял раньше второго?» Для «сначала дешёвые» — цена первого меньше цены второго. Для «сначала дорогие» — наоборот, больше. Для рейтинга — у первого он выше. Для названия — первое название по алфавиту раньше, а строки сравниваются тем же знаком «меньше».

## @hint2
Короткая запись сортировки по убыванию числа отзывов:

```swift
let popular = shops.sorted { $0.reviews > $1.reviews }
```

Здесь `$0` и `$1` — два магазина, которые Swift сравнивает между собой. Знак `>` означает «сначала большие». Со знаком `<` получилось бы «сначала маленькие».

Одна ветка твоего `switch` выглядит так:

```swift
case .cheapFirst:
    return products.sorted { $0.price < $1.price }
```

Остальные три отличаются только свойством и знаком.

## @hint3
Две ветки готовы, допиши остальные:

```swift
switch option {
case .cheapFirst:
    return products.sorted { $0.price < $1.price }
case .expensiveFirst:
    return products.sorted { $0.price ___ $1.price }
case .topRated:
    return products.sorted { $0.___ > $1.___ }
case .byName:
    return products.sorted { ___ }
}
```

В первом пропуске — знак для сортировки по убыванию. Во втором и третьем — имя свойства с рейтингом. В последнем — сравнение названий двух товаров, чтобы получился порядок от А до Я.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** `switch` выбирает ветку по значению `option`. В каждой ветке вызывается `products.sorted { ... }`. Во время сортировки Swift много раз берёт пару товаров и спрашивает у замыкания: «первый должен идти раньше второго?» Первый товар попадает в `$0`, второй — в `$1`. По ответам `true` и `false` Swift расставляет весь массив. Сам алгоритм сортировки писать не нужно — ты описываешь только правило сравнения.

**Почему запись такая короткая.** Полная форма первой ветки — `products.sorted(by: { (a: Product, b: Product) -> Bool in return a.price < b.price })`. Swift знает типы из массива, поэтому их можно не писать. Выражение в теле одно, поэтому `return` не нужен. Параметры заменены на `$0` и `$1`, поэтому исчезли имена и слово `in`. А замыкание — единственный аргумент, поэтому исчезли круглые скобки и метка `by:`. Осталось только главное: что с чем сравнивается.

**Почему в `switch` нет `default`.** Все четыре варианта `SortOption` перечислены. Если позже в перечисление добавят пятый вариант, Swift сам напомнит, что его нужно обработать здесь.

**Типичные ошибки:**

- перепутан знак: `<` даёт порядок по возрастанию, `>` — по убыванию. Для «сначала дорогие» и «по рейтингу» нужен `>`;
- сравниваются товары целиком: `$0 < $1`. Swift не знает, как сравнить две структуры, — нужно указать свойство;
- в одном замыкании смешаны имена и `$0`: либо `{ a, b in a.price < b.price }`, либо `{ $0.price < $1.price }`;
- вызван `products.sorted()` без замыкания — для массива структур он не работает.
