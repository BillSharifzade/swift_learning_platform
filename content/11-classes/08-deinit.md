## @description

### Контекст
К охранной панели «Гнезда» подключены датчики движения. Датчики объединены в зоны: «Первый этаж», «Второй этаж», «Гараж». Каждое подключение и отключение датчика записывается в журнал охраны — его показывает экран «События».

С подключением всё просто: датчик появился — пишем в журнал. С отключением сложнее. Датчик могут убрать из зоны, снять с охраны всю зону, закрыть экран проверки связи. «Если вписывать строку журнала в каждое такое место, однажды мы её забудем, — говорит тимлид. — Пусть датчик сам сообщает, что его больше нет. Для этого у класса есть `deinit`».

### Новое в Swift
**Объект живёт, пока на него есть ссылка.** Объект класса появляется, когда вызван его инициализатор. Дальше на него ведут ссылки: переменные, константы, элементы массивов, свойства других объектов. Пока есть хотя бы одна ссылка, объект жив. Как только исчезает последняя, Swift уничтожает объект и освобождает память. Следить за этим вручную не нужно: Swift сам считает ссылки на каждый объект.

**`deinit` — последнее слово объекта.** Это блок кода, который Swift вызывает сам, прямо перед уничтожением объекта. Пишется без `func`, без скобок и параметров. Вызвать `deinit` самой нельзя:

```swift
class Camera {
    let name: String

    init(name: String) {
        self.name = name
        print("\(name): запись началась")
    }

    deinit {
        print("\(name): запись остановлена")
    }
}
```

В настоящих приложениях в `deinit` закрывают соединения, отписываются от событий и пишут журналы — убирают за объектом.

Последняя ссылка исчезает в трёх частых случаях.

**Закончился блок.** Переменная, объявленная внутри фигурных скобок, существует только до закрывающей скобки. Блок `do { ... }` — просто отдельный кусок кода со своими переменными:

```swift
do {
    let doorbell = Camera(name: "Дверной звонок")
    print("Смотрим, кто пришёл: \(doorbell.name)")
}
// Дверной звонок: запись началась
// Смотрим, кто пришёл: Дверной звонок
// Дверной звонок: запись остановлена
```

**Опционалу присвоили `nil`.** Но объект уничтожается, только когда исчезнет последняя ссылка:

```swift
var garage: Camera? = Camera(name: "Гараж")
var monitor = garage     // вторая ссылка на ту же камеру
garage = nil             // ничего не происходит: камеру держит monitor
monitor = nil            // Гараж: запись остановлена
```

**Элемент убрали из массива.** Массив тоже держит ссылки на свои объекты:

```swift
var cameras = [Camera(name: "Двор"), Camera(name: "Подъезд")]
cameras.remove(at: 0)    // Двор: запись остановлена
```

> 💡 Если тот же объект лежит ещё где-то — в другом массиве или переменной, — удаление из одного места его не уничтожит. Подробно о том, как Swift считает ссылки и где здесь ловушки, — в модуле про управление памятью.

### Задача
Журнал охраны — массив `securityLog` в начале кода. Пиши в него методом `append`.

1. В инициализаторе `MotionSensor`, после того как название сохранено, добавь в журнал строку `Подключение: ` и название датчика — `Подключение: Кухня`.
2. Добавь датчику `deinit`, который пишет в журнал `Отключение: ` и название — `Отключение: Кухня`.
3. Допиши метод `removeSensor(named:)` у `SecurityZone`: он убирает из массива `sensors` все датчики с таким названием. Если таких нет, ничего не меняется.
4. Допиши метод `disarm()`: он убирает из зоны все датчики — зону сняли с охраны.

В `removeSensor` и `disarm` в журнал ничего не пиши. Если на датчик больше никто не ссылается, строку `Отключение` добавит его `deinit`. А если датчик входит ещё в одну зону, он остаётся на связи — и журнал не должен говорить обратное.

### Пример
```swift
let garage = SecurityZone(title: "Гараж")
garage.add(MotionSensor(name: "Ворота"))   // в журнале: Подключение: Ворота
garage.removeSensor(named: "Ворота")       // в журнале: Отключение: Ворота
garage.sensors.count                       // 0
```

Сценарий из редактора должен вывести:

```text
Связь с датчиком Пробный есть
Журнал охраны:
Подключение: Входная дверь
Подключение: Кухня
Подключение: Пробный
Отключение: Пробный
Подключение: Запасной
Отключение: Запасной
Отключение: Кухня
Датчиков в зоне: 1
```

## @solution
```swift
// Журнал охраны. Его показывает экран "События"
var securityLog: [String] = []

class MotionSensor {
    let name: String

    init(name: String) {
        self.name = name
        // 1. Запиши в журнал строку о подключении
        securityLog.append("Подключение: \(name)")
    }

    // 2. deinit: запиши в журнал строку об отключении
    deinit {
        securityLog.append("Отключение: \(name)")
    }
}

// Зона охраны: держит свои датчики в массиве
class SecurityZone {
    let title: String
    var sensors: [MotionSensor] = []

    init(title: String) {
        self.title = title
    }

    func add(_ sensor: MotionSensor) {
        sensors.append(sensor)
    }

    // 3. Убирает из зоны все датчики с таким названием
    func removeSensor(named name: String) {
        sensors = sensors.filter { $0.name != name }
    }

    // 4. Снимает зону с охраны: убирает все датчики
    func disarm() {
        sensors = []
    }
}

// Сценарий: день на охранной панели. Этот код менять не нужно
let firstFloor = SecurityZone(title: "Первый этаж")
firstFloor.add(MotionSensor(name: "Входная дверь"))
firstFloor.add(MotionSensor(name: "Кухня"))

// Проверка связи: временный датчик живёт только внутри блока do
do {
    let probe = MotionSensor(name: "Пробный")
    print("Связь с датчиком \(probe.name) есть")
}

// Запасной датчик лежит в опционале, пока его не убрали
var spareSensor: MotionSensor? = MotionSensor(name: "Запасной")
spareSensor = nil

firstFloor.removeSensor(named: "Кухня")

print("Журнал охраны:")
for line in securityLog {
    print(line)
}
print("Датчиков в зоне: \(firstFloor.sensors.count)")
```

## @rules
- must: /\bdeinit\s*\{/ :: Строку об отключении должен писать сам датчик — в блоке `deinit { ... }`.

## @hint1
Начни с журнала. В инициализаторе, после строки с `self.name`, добавь в массив `securityLog` строку с подключением: слово «Подключение», двоеточие, пробел и название через интерполяцию.

Потом `deinit`. Он пишется внутри класса датчика, после инициализатора: слово `deinit` и сразу фигурные скобки — без `func`, без круглых скобок. Внутри такая же строка, только со словом «Отключение». Название датчика в `deinit` ещё доступно: объект пока жив.

Метод `removeSensor(named:)`: нужно оставить в массиве только датчики с другим названием и положить результат обратно в `sensors`. Для этого подходит `filter`. Убранные датчики исчезнут сами, если их больше никто не держит.

Метод `disarm()`: положи в `sensors` пустой массив.

В обоих методах про журнал не думай вовсе — его допишет `deinit`.

## @hint2
Так выглядят запись в журнал при создании и `deinit`:

```swift
init(name: String) {
    self.name = name
    eventLog.append("Камера включена: \(name)")
}

deinit {
    eventLog.append("Камера выключена: \(name)")
}
```

А так из массива убирают элементы по условию:

```swift

```

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Инициализатор пишет в журнал строку о подключении, `deinit` — строку об отключении. Вызывать `deinit` никто не должен: Swift вызывает его сам, в момент, когда на датчик не остаётся ни одной ссылки.

**Разберём сценарий.** «Входная дверь» и «Кухня» живут в массиве зоны: ссылки на них держит `sensors`. «Пробный» объявлен внутри `do`: на закрывающей скобке константа `probe` исчезает, и датчик отключается. «Запасной» живёт в опционале. Когда в него записали `nil`, последняя ссылка пропала. Наконец, `removeSensor` убирает «Кухню» из массива — и только тогда в журнале появляется её отключение. «Входная дверь» остаётся на связи до конца программы.

**Почему `removeSensor` не пишет в журнал.** Удалить датчик из зоны и уничтожить его — разные вещи. Проверка положила один датчик в две зоны и убрала его из одной. Датчик всё ещё нужен второй зоне, значит, он жив и на связи. Строка «Отключение» в `removeSensor` соврала бы. А `deinit` знает точно: если он сработал, датчика больше нет нигде.

**Почему `filter`, а не поиск одного элемента.** Датчиков с одинаковым названием может быть несколько, и убрать нужно все. `filter` оставляет только те, что не совпали, — за один проход.

**Типичные ошибки:**

- `func deinit()` — у `deinit` нет ни `func`, ни скобок;
- строка об отключении пишется в `removeSensor` — датчик из двух зон «отключится», оставаясь на связи;
- в `removeSensor` условие `$0.name == name` — в зоне останутся как раз удаляемые датчики;
- `deinit` пишет через `print`, а не в `securityLog` — экран «События» ничего не увидит.
