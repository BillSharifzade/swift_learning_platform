## @description

### Контекст
Главный экран «Горизонта» начинается со строки с температурой: `Сочи: +14`. Число приходит с сервера погоды, а сервер отвечает не сразу. Пока ответа нет, приложение не должно замирать: человек в это время листает новости и переключает вкладки.

Коллега из серверной команды уже написал функцию `downloadTemperature(city:)`, которая ходит на сервер. Тимлид просит: «Сделай функцию, которая собирает строку для экрана. Пиши сразу на `async` и `await` — замыкания-обработчики, как в старых проектах, мы в новом коде больше не используем».

### Новое в Swift
Представь кофейню. Ты сделала заказ, и бариста начал готовить. Ты не стоишь у стойки, уставившись в одну точку: садишься за столик, читаешь, переписываешься. Когда назовут номер заказа, ты забираешь стакан и продолжаешь с того места, где остановилась.

Приложение ждёт сервер точно так же. Функцию, внутри которой есть такое ожидание, помечают словом `async` («асинхронная»). Оно пишется после круглых скобок с параметрами, перед стрелкой:

```swift
func loadAvatar(userId: Int) async -> String {
    // ... ждём сервер ...
    return "avatar-\(userId).png"
}
```

Вызывая асинхронную функцию, пишут `await` («дождаться»):

```swift
let avatar = await loadAvatar(userId: 7)
print(avatar)   // avatar-7.png
```

Слово `await` отмечает **точку ожидания**. На ней функция приостанавливается, пока не придёт результат. Но приложение не стоит: в это время оно рисует экран и отвечает на нажатия. Когда результат готов, выполнение продолжается со следующей строки, и в `avatar` уже лежит ответ.

Где можно писать `await`:

- внутри другой `async`-функции;
- в коде верхнего уровня, то есть не внутри функций. В тренажёре это разрешено, поэтому проверять асинхронные функции можно прямо внизу программы.

Если вызвать асинхронную функцию без `await`, Swift не соберёт код. И наоборот: в обычной функции без `async` слово `await` писать нельзя. Асинхронность «заразна»: кто ждёт, тот и сам становится асинхронным.

Как устроена `downloadTemperature`, можно посмотреть в редакторе. Строка `try? await Task.sleep(for: .milliseconds(30))` — это пауза на 30 миллисекунд, так в тренажёре изображается дорога до сервера и обратно. Почему перед ней стоит `try?`, ты узнаешь в следующей задаче.

> 💡 Ответ сервера — `Int?`: если о городе на сервере ничего нет, придёт `nil`. С таким значением ты уже умеешь работать.

### Задача
1. Напиши асинхронную функцию `forecastText(for:)`. Параметр `city` типа `String`, при вызове метка `for`. Функция возвращает `String`.
2. Внутри дождись ответа `downloadTemperature(city:)` через `await`. Значения не придумывай и данные сервера не копируй.
3. Собери строку для экрана:
   - температура выше нуля — со знаком плюс: `Сочи: +14`;
   - ноль и ниже — как есть: `Мурманск: 0`, `Казань: -3`;
   - сервер вернул `nil` — `Тверь: нет данных`.
4. Внизу программы выведи строки для Сочи и для Казани — две команды `print` с `await`.

### Пример
```swift
await forecastText(for: "Сочи")       // "Сочи: +14"
await forecastText(for: "Мурманск")   // "Мурманск: 0"
await forecastText(for: "Тверь")      // "Тверь: нет данных"
```

Вывод программы:

```text
Сочи: +14
Казань: -3
```

## @solution
```swift
// Сервер погоды (заглушка). Отвечает через 30 мс.
// Функция уже готова — вызывай её через await.
func downloadTemperature(city: String) async -> Int? {
    try? await Task.sleep(for: .milliseconds(30))   // дорога до сервера и обратно
    let serverData = ["Москва": 5, "Сочи": 14, "Казань": -3, "Мурманск": 0, "Калининград": 1, "Якутск": -1]
    return serverData[city]
}

// 1. Напиши асинхронную функцию forecastText(for:) -> String
func forecastText(for city: String) async -> String {
    guard let temperature = await downloadTemperature(city: city) else {
        return "\(city): нет данных"
    }
    if temperature > 0 {
        return "\(city): +\(temperature)"
    }
    return "\(city): \(temperature)"
}

// 2. Выведи строки для Сочи и для Казани
print(await forecastText(for: "Сочи"))
print(await forecastText(for: "Казань"))
```

## @rules
- must: /func\s+forecastText\s*\([^)]*\)\s*async\b/ :: Объяви `forecastText` асинхронной: слово `async` пишется после скобок с параметрами, перед стрелкой.
- must: /\bawait\s+downloadTemperature\s*\(/ :: Температуру нужно получить с «сервера»: вызови `downloadTemperature(city:)` через `await`.

## @hint1
Начни с объявления функции. Всё как обычно: `func`, имя, в скобках внешняя метка `for`, внутреннее имя `city` и тип `String`. После закрывающей скобки — слово `async`, потом стрелка и тип результата `String`.

В теле первым делом дождись ответа сервера: вызови `downloadTemperature`, передай ей город и поставь перед вызовом `await`. Ответ — опционал, его нужно развернуть. Удобнее всего через `guard let`: если там `nil`, сразу верни строку с текстом «нет данных».

Дальше обычное условие. Если температура больше нуля, верни строку с плюсом перед числом. Во всех остальных случаях — строку с числом как есть: минус у отрицательных чисел появится сам.

Внизу программы вызови свою функцию для Сочи и для Казани. Она асинхронная, поэтому и здесь перед вызовом нужен `await`. Результат сразу передай в `print`.

## @hint2
Объявление и вызов асинхронной функции выглядят так:

```swift
func loadAvatar(userId: Int) async -> String {
    return "avatar-\(userId).png"
}

print(await loadAvatar(userId: 7))
```

Ответ сервера разворачивается так же, как любой опционал, только перед вызовом стоит `await`:

```swift
guard let temperature = await downloadTemperature(city: city) else {
    return "\(city): нет данных"
}
```

## @hint3
Осталось заполнить пропуски:

```swift
func forecastText(for city: String) ___ -> String {

        return "\(city): нет данных"
    }
    if temperature > 0 {
        return "\(city): +\(temperature)"
    }
    return ___
}

print(await forecastText(for: "Сочи"))
print(await forecastText(for: "Казань"))
```

В первом пропуске — слово, которое делает функцию асинхронной. Во втором — слово, которым дожидаются ответа. В третьем — строка для нуля и мороза: город, двоеточие и число без плюса.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Слово `async` в объявлении говорит: «внутри этой функции есть ожидание». Строка `await downloadTemperature(city: city)` — точка ожидания. Здесь `forecastText` приостанавливается примерно на 30 миллисекунд, пока «сервер» не ответит. Как только ответ пришёл, выполнение продолжается: `guard let` разворачивает опционал, а `if` выбирает, ставить ли плюс.

**Почему внизу тоже `await`.** `forecastText` асинхронная, значит, и её вызов — точка ожидания. Код верхнего уровня в тренажёре умеет ждать, поэтому `print(await forecastText(for: "Сочи"))` работает. Сначала программа дожидается строки для Сочи и печатает её, потом так же для Казани. Порядок вывода всегда один и тот же.

**Почему плюс только для `temperature > 0`.** Так принято в прогнозах погоды: `+5`, `0`, `-3`. Минус у отрицательного числа уже есть, интерполяция напечатает его сама. А у нуля знака нет вовсе. Поэтому граница проходит ровно по нулю: строгое «больше».

**Чем это лучше замыкания-обработчика.** Раньше то же самое писали так: `downloadTemperature(city: city) { temperature in ... }`. Результат приходил в замыкание, и код уезжал в него вправо. С `await` код читается сверху вниз, как обычный: вызвали, получили, обработали. Ответ можно положить в константу, развернуть через `guard`, вернуть через `return`.

**Типичные ошибки:**

- `async` поставлен перед `func` или после стрелки — его место между скобками с параметрами и стрелкой;
- забыт `await` перед `downloadTemperature` или перед `forecastText` внизу — Swift сообщит, что асинхронный вызов должен быть отмечен;
- условие `temperature >= 0` — тогда ноль получит лишний плюс: `Мурманск: +0`;
- данные сервера скопированы в свою функцию — на экране появятся устаревшие цифры, когда сервер начнёт отвечать по-другому.
