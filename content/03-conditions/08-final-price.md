## @description

### Контекст
Финальная задача спринта — экран «Оформление заказа». На нём гость видит чек: сколько стоят блюда, какая скидка, сколько за доставку и сколько платить в итоге. От этих чисел зависят деньги, поэтому правила прислал сам финансовый менеджер:

- **Промокод.** `LOZHKA10` даёт скидку 10% от суммы блюд. `FIRST` и `WELCOME` дают скидку 200 руб. Любой другой текст и пустая строка — скидки нет. Гости набирают промокод как придётся: `first`, `First`, `FIRST` — всё должно работать.
- **Доставка** стоит 199 руб. Но если блюд **после скидки** набралось на 1500 руб. или больше, она бесплатная.
- **Ночная наценка** — 150 руб., если заказ оформлен с 23:00 до 5:59.

Коллега начал этот файл: завёл переменные со значениями «по умолчанию» и написал вывод чека. Сами правила он оставил тебе. Тимлид говорит: «Всё нужное ты уже умеешь. Здесь просто несколько решений подряд».

### Что пригодится
Нового в этой задаче нет. Вспомни, что уже было в модуле.

**`switch` с несколькими значениями и `default`.** После слова `switch` может стоять не только имя, но и выражение — например, вызов `lowercased()` или `uppercased()`. Так удобно сравнивать текст, не думая о больших и маленьких буквах:

```swift
let cuisine = "Sushi"
var cookingMinutes = 20

switch cuisine.lowercased() {
case "sushi", "poke":
    cookingMinutes = 15
case "pizza":
    cookingMinutes = 30
default:
    cookingMinutes = 20
}
```

**`if` без `else`.** Когда у переменной уже есть значение по умолчанию, условие нужно только для особого случая. Нет особого случая — значение остаётся прежним:

```swift
let dishesCount = 7
var packagingFee = 0

if dishesCount > 5 {
    packagingFee = 30
}
```

**Составное условие.** «Или одно, или другое» записывается через `||`, «и то, и другое» — через `&&`. Часы в сутках идут по кругу: после 23 наступает 0. Поэтому «ночь» — это два отдельных куска: поздний вечер и раннее утро.

**Тернарный оператор.** Выбор одного из двух текстов умещается в строку: `let badge = isVegan ? "Веганское" : "Обычное"`.

**Порядок важен.** Бесплатная доставка зависит от суммы после скидки. Значит, сначала нужно посчитать скидку, и только потом решать про доставку.

### Задача
В редакторе есть входные данные: сумма блюд `subtotal`, промокод `promoCode` и час оформления заказа `hour` (от 0 до 23). Ниже объявлены переменные `discount`, `deliveryCost` и `nightFee`, а в конце — готовый чек. Не переименовывай данные и не меняй готовые строки чека.

1. **Скидка.** Напиши `switch` по промокоду, приведённому к заглавным буквам методом `uppercased()`. Он кладёт в `discount`:
   - для `"LOZHKA10"` — 10% от суммы блюд: `subtotal * 10 / 100`;
   - для `"FIRST"` или `"WELCOME"` — `200`;
   - для всего остального — `0`.
2. **Доставка.** Если `subtotal` минус `discount` не меньше `1500`, положи в `deliveryCost` ноль.
3. **Ночная наценка.** Если `hour` равен 23 или находится в промежутке от 0 до 5 включительно, положи в `nightFee` число `150`.
4. **Строка про доставку.** В чеке между строками «Скидка» и «Ночная наценка» выведи `Доставка: бесплатно`, если `deliveryCost` равна нулю, а иначе — `Доставка: 199 руб.` со стоимостью из `deliveryCost`.

### Пример
Для данных из редактора (блюда на 1480 руб., промокод `LOZHKA10`, 23 часа):

```text
Блюда: 1480 руб.
Скидка: 148 руб.
Доставка: 199 руб.
Ночная наценка: 150 руб.
Итого: 1681 руб.
```

Для заказа на 1700 руб. с промокодом `FIRST` в полдень:

```text
Блюда: 1700 руб.
Скидка: 200 руб.
Доставка: бесплатно
Ночная наценка: 0 руб.
Итого: 1500 руб.
```

## @solution
```swift
// Входные данные (их подменяет проверка — не переименовывай)
let subtotal = 1480
let promoCode = "LOZHKA10"
let hour = 23

// Значения по умолчанию: скидки нет, доставка платная, ночной наценки нет
var discount = 0
var deliveryCost = 199
var nightFee = 0

// 1. Скидка по промокоду: switch кладёт в discount сумму скидки
switch promoCode.uppercased() {
case "LOZHKA10":
    discount = subtotal * 10 / 100
case "FIRST", "WELCOME":
    discount = 200
default:
    discount = 0
}

// 2. Бесплатная доставка: если после скидки осталось 1500 руб. или больше
if subtotal - discount >= 1500 {
    deliveryCost = 0
}

// 3. Ночная наценка: если заказ оформлен с 23:00 до 5:59
if hour == 23 || hour <= 5 {
    nightFee = 150
}

// Чек
let total = subtotal - discount + deliveryCost + nightFee
print("Блюда: \(subtotal) руб.")
print("Скидка: \(discount) руб.")
// 4. Выведи строку про доставку: "Доставка: бесплатно" или "Доставка: 199 руб."
let deliveryText = deliveryCost == 0 ? "бесплатно" : "\(deliveryCost) руб."
print("Доставка: \(deliveryText)")
print("Ночная наценка: \(nightFee) руб.")
print("Итого: \(total) руб.")
```

## @rules
- must: /\bswitch\b/ :: Промокод разбери оператором `switch` — так, как ты разбирала код статуса заказа.

## @hint1
В задаче четыре независимых шага. Делай их по одному и после каждого нажимай «Проверить»: по чеку будет видно, какие числа уже сошлись.

Шаг первый — скидка. Это `switch`, очень похожий на разбор статуса заказа. Разбирать нужно не сам `promoCode`, а его вариант из заглавных букв: метод для этого ты знаешь по модулю про «Гардероб». Веток три. Первая — для кода с десятью процентами: в `discount` кладётся результат формулы из задания. Вторая — сразу для двух кодов через запятую, в ней число 200. Третья — `default` с нулём.

Шаг второй — доставка. По умолчанию она уже стоит 199, поэтому нужен только `if` без `else`. Условие: сумма блюд минус скидка не меньше 1500. Внутри блока — присваивание нуля.

Шаг третий — ночная наценка. Тоже `if` без `else`. Ночь состоит из двух кусков: час равен 23 или час не больше 5. Два сравнения соединяются оператором «или».

Шаг четвёртый — строка чека. Нужно выбрать один из двух текстов в зависимости от того, равна ли `deliveryCost` нулю. Это работа для тернарного оператора. Строку поставь там, где в чеке оставлен комментарий с цифрой 4.

## @hint2
Самая длинная часть — `switch`. Он устроен так же, как в этом примере: выражение после `switch`, ветка с двумя значениями и `default`.

```swift
switch cuisine.lowercased() {
case "sushi", "poke":
    cookingMinutes = 15
case "pizza":
    cookingMinutes = 30
default:
    cookingMinutes = 20
}
```

А особый случай при готовом значении по умолчанию — это короткий `if`:

```swift
if dishesCount > 5 {
    packagingFee = 30
}
```

В твоей задаче таких `if` два: один про сумму после скидки, другой про ночные часы.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Программа принимает четыре решения подряд. `switch` берёт промокод в заглавных буквах и ищет подходящую ветку. Для `LOZHKA10` в `discount` попадает `1480 * 10 / 100`, то есть `148`. Затем первый `if` считает сумму после скидки: `1480 - 148` — это `1332`. До 1500 не хватает, условие ложно, и `deliveryCost` остаётся равной 199. Второй `if` проверяет час: `23 == 23` — истина, поэтому `nightFee` становится 150. Готовая строка `total` складывает всё вместе, а тернарный оператор выбирает текст для строки про доставку.

**Почему `uppercased()`.** Гость может набрать `first`, `First` или `FIRST`. Для Swift это три разные строки. Проще всего привести ввод к одному виду и сравнивать только с ним. Сама константа `promoCode` при этом не меняется: `uppercased()` создаёт новую строку.

**Почему `if` без `else`.** У `deliveryCost` и `nightFee` уже есть значения по умолчанию. Условие описывает только исключение из правила. Такой код легко читать: «доставка стоит 199, но если набрали 1500 — ноль».

**Почему порядок шагов именно такой.** Бесплатная доставка зависит от суммы после скидки. Если поставить проверку доставки выше `switch`, в `discount` в этот момент ещё лежит ноль, и заказ на 1660 руб. с промокодом на 10% получит бесплатную доставку, хотя после скидки в нём 1494 руб.

**Почему `||` в ночном условии.** Час не может быть одновременно равен 23 и не больше 5. С оператором `&&` условие было бы ложным всегда. Ночь — это «или поздний вечер, или раннее утро». То же самое можно записать через `switch hour` с веткой `case 23, 0...5:` — выбирай вариант, который тебе понятнее.

**Типичные ошибки:**

- в условии доставки стоит `subtotal >= 1500` без вычитания скидки;
- `>` вместо `>=`: заказ ровно на 1500 руб. после скидки остаётся с платной доставкой;
- `hour < 5` вместо `hour <= 5` — заказы с 5:00 до 5:59 теряют ночную наценку;
- коды в `case` написаны маленькими буквами при `uppercased()` — ни один не совпадёт, и скидка всегда будет нулевой;
- строка про доставку выведена не между «Скидка» и «Ночная наценка», а в конце чека.
