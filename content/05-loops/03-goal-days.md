## @description

### Контекст
У каждого пользователя «Пульса» есть дневная цель по шагам. Дизайнер добавила на экран недели две плашки: сколько дней цель была выполнена и какой результат стал рекордом недели.

Аналитик уточняет в задаче: «Цель выполнена, если шагов не меньше цели. Ровно десять тысяч при цели десять тысяч — это тоже выполнено».

### Новое в Swift
Тело цикла — обычный код, и в нём можно писать условия. Тогда цикл проходит по всем элементам, а `if` решает, что делать с каждым. На этом приёме держатся две самые частые задачи с массивами.

**Счётчик: сколько элементов подходит под условие.** Перед циклом заводят переменную с нулём, а внутри увеличивают её на единицу — но только когда условие выполнено:

```swift
let pulses = [72, 95, 130, 88, 141]

var highCount = 0
for pulse in pulses {
    if pulse > 120 {
        highCount += 1
    }
}
print("Высокий пульс: \(highCount) раз")
```

Цикл посмотрит все пять значений. Условие сработает дважды — для 130 и для 141, поэтому в `highCount` окажется 2.

**Поиск самого большого значения.** Приём похож на соревнование. В переменной лежит лучший результат из тех, что уже встретились. Каждое новое значение сравнивается с ним, и если оно больше — занимает его место:

```swift
var peakPulse = 0
for pulse in pulses {
    if pulse > peakPulse {
        peakPulse = pulse
    }
}
print("Пик: \(peakPulse)")
```

Проследим по шагам. Вначале в `peakPulse` лежит 0. Значение 72 больше нуля — запоминаем 72. Потом 95 больше 72 — запоминаем 95. Потом 130. Значение 88 меньше 130 — ничего не меняем. Наконец, 141 больше 130 — запоминаем 141. Цикл закончился, в переменной остался максимум.

Почему начинаем с нуля? Пульс не бывает отрицательным, поэтому первое же настоящее значение окажется не меньше нуля и займёт его место. А если массив пуст, в переменной так и останется 0 — для экрана «данных нет» это разумный ответ.

Оба приёма можно выполнять в одном цикле: в теле просто будет два `if` подряд.

### Задача
В редакторе есть массив `steps` — шаги по дням, константа `dailyGoal` — дневная цель, и вывод первой строки. Не переименовывай входные данные: проверка подставит другие.

1. Объяви переменную `goalDays` — счётчик дней, когда цель выполнена. Цель выполнена, если шагов **не меньше** `dailyGoal`.
2. Объяви переменную `bestSteps` — самое большое число шагов за один день. Если данных нет, в ней должен остаться `0`.
3. Заполни обе переменные в цикле по массиву `steps`.
4. Выведи две строки, как в примере. Первая: `Цель выполнена:`, счётчик, слово `из`, общее количество дней (`steps.count`) и `дн.` Вторая: `Рекорд недели:`, рекорд и слово `шагов`.

### Пример
Для данных из редактора:

```text
Цель: 10000 шагов в день
Цель выполнена: 3 из 7 дн.
Рекорд недели: 12100 шагов
```

Если данных нет:

```text
Цель: 10000 шагов в день
Цель выполнена: 0 из 0 дн.
Рекорд недели: 0 шагов
```

## @solution
```swift
// Входные данные (их подменяет проверка — не переименовывай)
let steps = [8200, 10450, 6300, 12100, 9800, 4050, 10000]
let dailyGoal = 10000

print("Цель: \(dailyGoal) шагов в день")

// 1. Объяви счётчик goalDays и переменную bestSteps для рекорда
var goalDays = 0
var bestSteps = 0

// 2. Пройди по массиву steps: посчитай дни с выполненной целью и найди рекорд
for daySteps in steps {
    if daySteps >= dailyGoal {
        goalDays += 1
    }
    if daySteps > bestSteps {
        bestSteps = daySteps
    }
}

// 3. Выведи две строки с результатами
print("Цель выполнена: \(goalDays) из \(steps.count) дн.")
print("Рекорд недели: \(bestSteps) шагов")
```

## @rules
- must: /\bfor\s+\w+\s+in\b/ :: Пройди по массиву `steps` циклом `for-in`: и счётчик, и рекорд считаются внутри него.

## @hint1
Тебе нужны две переменные, и обе объявляются до цикла с нулём внутри. `goalDays` — счётчик: пока мы не посмотрели ни одного дня, удачных дней ноль. `bestSteps` — рекорд: пока не видели ни одного результата, лучший результат тоже ноль.

Дальше один цикл `for-in` по массиву `steps`. В его теле два независимых условия, одно за другим.

Первое условие — про цель. Если шагов за день не меньше, чем `dailyGoal`, счётчик увеличивается на единицу. Обрати внимание на слова «не меньше»: ровно столько же шагов, сколько в цели, тоже подходит. Значит, нужен оператор «больше или равно».

Второе условие — про рекорд. Если шагов за день больше, чем лежит в `bestSteps`, значит, нашёлся новый рекорд, и его нужно положить в `bestSteps`.

После цикла — два `print`. В первой строке две вставки: счётчик и общее количество дней, то есть `steps.count`. Во второй — одна: рекорд.

## @hint2
Счётчик и поиск самого большого значения можно совместить в одном цикле:

```swift
var highCount = 0
var peakPulse = 0

for pulse in pulses {
    if pulse > 120 {
        highCount += 1
    }
    if pulse > peakPulse {
        peakPulse = pulse
    }
}
```

В твоей задаче первое условие сравнивает шаги с `dailyGoal`, и сравнение нестрогое: `>=`.

## @hint3
Заполни три пропуска:

```swift
var goalDays = 0
var bestSteps = 0

for daySteps in steps {
    if daySteps ___ dailyGoal {
        goalDays += 1
    }
    if daySteps > ___ {
        bestSteps = ___
    }
}

print("Цель выполнена: \(goalDays) из \(steps.count) дн.")
print("Рекорд недели: \(bestSteps) шагов")
```

В первом пропуске — оператор сравнения «не меньше». Во втором — переменная, где хранится текущий рекорд. В третьем — значение, которое становится новым рекордом.

## @hint4
Вот готовое решение:

{{solution}}

**Как работает счётчик.** Цикл по очереди кладёт в `daySteps` шаги каждого дня. Условие `daySteps >= dailyGoal` истинно для трёх дней: 10450, 12100 и 10000. Каждый раз `goalDays` увеличивается на 1, и после цикла в ней лежит 3. Остальные дни условие не проходят, и счётчик их не замечает.

**Почему `>=`, а не `>`.** В последний день пройдено ровно 10000 шагов. По условию аналитика это выполненная цель. Со строгим `>` такой день потерялся бы, и получилось бы 2 дня вместо 3. Граничные значения — самое частое место для ошибок, поэтому их всегда проверяют отдельно.

**Как работает поиск рекорда.** В `bestSteps` хранится лучший результат из уже просмотренных. 8200 больше нуля — запомнили. 10450 больше 8200 — запомнили. 6300 меньше — пропустили. 12100 больше 10450 — запомнили. Дальше значения меньше, и рекорд не меняется. Сравнение здесь строгое: если встретится такой же результат, перезаписывать нечего.

**Почему обе переменные начинаются с нуля.** Шагов не бывает меньше нуля, поэтому любой настоящий результат победит стартовое значение. А для пустого массива цикл не выполнится ни разу, и на экране честно окажутся нули.

**Типичные ошибки:**

- `bestSteps = daySteps` без условия — в переменной окажется последний день, а не лучший;
- переменные объявлены внутри цикла — они обнуляются на каждом повторе;
- `goalDays += daySteps` — счётчик должен расти на единицу, а не на число шагов;
- в строке вывода написано `из 7` цифрой вместо `steps.count`.
