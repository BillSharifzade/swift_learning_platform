## @description

### Контекст
Хозяева сами меняют цену своего жилья. Вчера один из них промахнулся по клавише и вместо 3500 поставил 350. Квартиру тут же забронировали на две недели, поддержка разбиралась полдня.

Тимлид ставит задачу: «Нужны три вещи. Журнал для поддержки: какая цена была и какую запросили. Нижняя граница: цена не опускается ниже минимальной. И признак "цена снижена" — для значка на карточке. Цену в приложении меняют из пяти разных мест, искать их все не хочется. Пусть модель сама реагирует на любое изменение».

### Новое в Swift
К хранимому свойству можно прикрепить **наблюдателей**. Это блоки кода, которые Swift сам выполняет при каждом присваивании — откуда бы оно ни пришло. Наблюдателей два:

- `willSet` срабатывает **перед** изменением. В свойстве ещё лежит старое значение, а новое доступно под именем `newValue`.
- `didSet` срабатывает **сразу после** изменения. В свойстве уже новое значение, а прежнее доступно под именем `oldValue`.

Записываются они в фигурных скобках после типа свойства:

```swift
struct GuestCounter {
    let maxGuests: Int

    var guests: Int {
        willSet {
            print("Было гостей: \(guests), просят: \(newValue)")
        }
        didSet {
            if guests > maxGuests {
                guests = maxGuests
            }
            print("Изменение: \(guests - oldValue)")
        }
    }
}

var counter = GuestCounter(maxGuests: 4, guests: 2)
counter.guests = 9
print(counter.guests)
```

```text
Было гостей: 2, просят: 9
Изменение: 2
4
```

Вот что произошло при `counter.guests = 9`:

1. Сработал `willSet`: в `guests` пока 2, в `newValue` — 9.
2. Swift записал в `guests` число 9.
3. Сработал `didSet`: 9 больше максимума, значение исправлено на 4. Потом итог сравнили с `oldValue`, где лежит 2.

Несколько правил:

- свойство с наблюдателями остаётся хранимым: оно по-прежнему заполняется при создании экземпляра;
- при создании экземпляра наблюдатели **не срабатывают** — только при последующих присваиваниях;
- внутри `didSet` можно присвоить свойству исправленное значение — наблюдатели от этого повторно не запустятся;
- из наблюдателя можно менять другие свойства той же структуры;
- если нужен только один из двух блоков, второй не пишут.

> 💡 Не путай с вычисляемым свойством. Там были `get` и `set`, и значение нигде не хранилось. Здесь значение хранится как обычно, а `willSet` и `didSet` только следят за его изменением.

### Задача
В редакторе есть структура `Apartment`. Свойство `pricePerNight` — обычное хранимое. Прикрепи к нему наблюдателей:

1. В `willSet` добавь в массив `changeLog` строку вида `Было 3200, запрошено 3500`: текущая цена и та, которую хотят поставить.
2. В `didSet` проверь границу: если цена оказалась меньше `minPrice`, замени её на `minPrice`.
3. Там же, в `didSet`, после проверки границы запиши в `isPriceReduced`, стала ли цена в итоге меньше прежней: `true` — стала, `false` — нет.

Остальные свойства и сценарий под структурой менять не нужно.

### Пример
```swift
var apartment = Apartment(title: "Студия у набережной", minPrice: 1000, pricePerNight: 3200)
apartment.pricePerNight = 3500    // цена 3500, isPriceReduced == false
apartment.pricePerNight = 350     // опечатка: цена стала 1000, isPriceReduced == true
apartment.changeLog               // ["Было 3200, запрошено 3500", "Было 3500, запрошено 350"]
```

Сценарий должен вывести:

```text
Цена: 1000 руб.
Цена снижена: true
Было 3200, запрошено 3500
Было 3500, запрошено 350
```

struct Apartment {

    let minPrice: Int

    // Прикрепи к этому свойству наблюдателей willSet и didSet

## @solution
```swift
struct Apartment {
    let title: String
    let minPrice: Int

    // Прикрепи к этому свойству наблюдателей willSet и didSet
    var pricePerNight: Int {
        willSet {
            changeLog.append("Было \(pricePerNight), запрошено \(newValue)")
        }
        didSet {
            if pricePerNight < minPrice {
                pricePerNight = minPrice
            }
            isPriceReduced = pricePerNight < oldValue
        }
    }

    var changeLog: [String] = []
    var isPriceReduced = false
}

// Случай из обращения в поддержку. Этот код уже готов — менять его не нужно
var apartment = Apartment(title: "Студия у набережной", minPrice: 1000, pricePerNight: 3200)
apartment.pricePerNight = 3500
apartment.pricePerNight = 350

print("Цена: \(apartment.pricePerNight) руб.")
print("Цена снижена: \(apartment.isPriceReduced)")
for line in apartment.changeLog {
    print(line)
}
```

## @output
```
Цена: 1000 руб.
Цена снижена: true
Было 3200, запрошено 3500
Было 3500, запрошено 350
```

## @rules
- must: /\bwillSet\b/ :: Запись в журнал сделай в наблюдателе `willSet` — до того, как цена изменится.
- must: /\bdidSet\b/ :: Границу и признак снижения проверь в наблюдателе `didSet` — после изменения цены.

## @hint1
Менять нужно одно место — объявление `pricePerNight`. Сейчас оно заканчивается типом. После типа открой фигурные скобки, а внутри напиши два блока с именами наблюдателей. У каждого блока свои фигурные скобки.

В первом блоке, который срабатывает до изменения, одна строка: в журнал `changeLog` добавляется текст. Массивы ты уже пополняла через `append`. В тексте две вставки. Прежняя цена в этот момент всё ещё лежит в самом свойстве, а запрошенная доступна под особым именем — тем, что означает «новое значение».

Во втором блоке, который срабатывает после изменения, два действия, и их порядок важен. Сначала условие: если цена получилась меньше минимальной, свойству присваивается минимальная. Потом в `isPriceReduced` записывается результат сравнения: текущая цена меньше прежней или нет. Прежняя доступна под именем, которое означает «старое значение». Результат сравнения — это уже готовое `true` или `false`, его можно присвоить напрямую.

## @hint2
Наблюдатели пишутся в фигурных скобках сразу после типа свойства. В `willSet` доступно `newValue`, в `didSet` — `oldValue`:

```swift
struct GuestCounter {
    let maxGuests: Int
    var notes: [String] = []

    var guests: Int {
        willSet {
            notes.append("Просят гостей: \(newValue)")
        }
        didSet {
            if guests > maxGuests {
                guests = maxGuests
            }
        }
    }
}
```

У тебя граница не верхняя, а нижняя, в строке журнала две вставки, а в `didSet` после условия есть ещё одна строка — про `isPriceReduced`.

## @hint3
Каркас готов, заполни пропуски:

```swift
    var pricePerNight: Int {
        willSet {
            changeLog.append("Было \(pricePerNight), запрошено \(___)")
        }
        didSet {
            if pricePerNight < ___ {
                pricePerNight = minPrice
            }
            isPriceReduced = pricePerNight < ___
        }
    }
```

В первом пропуске — имя, под которым в `willSet` доступна запрошенная цена. Во втором — свойство с нижней границей. В третьем — имя, под которым в `didSet` доступна прежняя цена.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Возьмём строку `apartment.pricePerNight = 350`. Сначала Swift запускает `willSet`. В этот момент в свойстве ещё 3500, а в `newValue` — 350, и в журнал уходит строка «Было 3500, запрошено 350». Затем значение меняется на 350. После этого запускается `didSet`: 350 меньше минимума 1000, поэтому цена исправляется на 1000. Последняя строка сравнивает итоговые 1000 с `oldValue` (3500) и записывает в `isPriceReduced` значение `true`.

**Почему наблюдатели, а не метод.** Можно было написать `mutating`-метод `changePrice(to:)` с теми же проверками. Но тогда всё держится на дисциплине: стоит кому-то написать `apartment.pricePerNight = 350` напрямую — и защита обойдена. Наблюдатели прикреплены к самому свойству, мимо них не пройти.

**Почему журнал в `willSet`, а граница в `didSet`.** Поддержке важно знать, что именно запросил хозяин, — даже если запрос потом исправили. В `willSet` есть и прежняя цена, и запрошенная. А исправлять значение можно только после того, как оно записано, то есть в `didSet`. Присваивание внутри собственного `didSet` наблюдателей повторно не запускает, поэтому лишняя строка в журнале не появляется.

**Почему порядок строк в `didSet` важен.** Если сначала сравнить с `oldValue`, а потом исправить границу, то при цене 2000, минимуме 2000 и запросе 1999 получится `true`. Но цена-то осталась прежней, и значок «цена снижена» обманет гостя.

**Типичные ошибки:**

- в `willSet` написано `\(pricePerNight)` дважды — новая цена там ещё не записана, она в `newValue`;
- `if newValue < minPrice` внутри `didSet` — имени `newValue` там нет, новое значение уже лежит в самом свойстве;
- `if pricePerNight < oldValue { isPriceReduced = true }` без ветки `else` — после повышения цены значок останется включённым;
- наблюдатели написаны отдельно от свойства, ниже по коду, — они должны стоять в фигурных скобках сразу после `var pricePerNight: Int`.
