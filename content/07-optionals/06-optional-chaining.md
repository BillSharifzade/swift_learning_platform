## @description

### Контекст
Дизайнер обновила экран профиля и прислала три мелкие задачи:

- под полем «О себе» нужен счётчик символов. Если поле не заполнено, счётчик показывает 0;
- над именем появляется главный тег — первый из списка интересов, заглавными буквами. Нет тегов — нет и плашки;
- сотрудникам «Рядом» рисуем значок команды. Сотрудника узнаём по почте: она заканчивается на `ryadom.team`.

В каждой из них нужно что-то сделать со значением, которого может не быть: посчитать длину, перевести в заглавные, проверить окончание.

### Новое в Swift
Вызвать метод прямо у опционала нельзя: `bio.count` не соберётся, ведь `bio` — коробочка. Можно развернуть её через `if let`, но ради одного действия это длинно. Есть короткий путь — поставить **вопросительный знак перед точкой**:

```swift
let nickname: String? = "Sunny_Bilol"
let length = nickname?.count           // Optional(11)
let lower = nickname?.lowercased()     // Optional("sunny_bilol")
```

Знак `?` здесь — вопрос: «значение есть?» Если да, выполняется то, что после точки. Если в коробочке `nil`, Swift ничего не вызывает, и всё выражение сразу становится `nil`. Ничего не падает. Это называется **optional chaining** — опциональная цепочка.

**Результат всегда опционал.** `count` возвращает `Int`, но у `nickname?.count` тип `Int?` — ведь значения могло и не быть. Поэтому `?.` часто идёт в паре с `??`:

```swift
let length = nickname?.count ?? 0      // обычный Int
```

**Цепочку можно продолжать.** После `?.` дальше пишут обычные точки. Если значения нет, вся цепочка целиком пропускается:

```swift
let website: String? = "HTTPS://bilol.example.ru"
let isSecure = website?.lowercased().hasPrefix("https") ?? false
```

Вопрос задаётся один раз — там, где стоит опционал. Метод `lowercased()` возвращает обычную строку, поэтому перед `hasPrefix` второй вопросительный знак не нужен.

**Опционал посреди цепочки.** Свойство `first` у массива само возвращает опционал. Чтобы продолжить цепочку после него, снова нужен `?.`:

```swift
let drafts = ["план на лето", "список книг"]
let title = drafts.first?.uppercased()     // Optional("ПЛАН НА ЛЕТО")

let empty: [String] = []
let nothing = empty.first?.uppercased()    // nil
```

> 💡 `?.` не заменяет `if let`, а дополняет его. Он хорош, когда нужно одно действие «если значение есть». Если действий несколько или для `nil` нужна своя логика — `if let` и `guard let` понятнее.

### Задача
1. Допиши функцию `bioLength(_:)`. Параметр — `String?` без метки. Она возвращает `Int`: количество символов в тексте, а если передан `nil` — `0`.
2. Напиши функцию `mainTag(_:)`. Параметр — массив `[String]` без метки. Она возвращает `String?`: первый тег заглавными буквами, а если массив пуст — `nil`.
3. Напиши функцию `isStaff(email:)`. Параметр — `String?` с меткой `email`. Она возвращает `Bool`: `true`, если почта заканчивается на `ryadom.team`. Большие и маленькие буквы в почте не различаются. Если почты нет — `false`.
4. В каждой функции используй `?.`. Слова `if` и `guard` в этой задаче не понадобятся.

### Пример
```swift
bioLength("Люблю горы и кофе")     // 17
bioLength(nil)                     // 0

mainTag(["путешествия", "кофе"])   // Optional("ПУТЕШЕСТВИЯ")
mainTag([])                        // nil

isStaff(email: "Design@Ryadom.Team")     // true
isStaff(email: "bilol@example.com")      // false
isStaff(email: nil)                      // false
```

## @solution
```swift
// Счётчик символов под полем "О себе"
func bioLength(_ bio: String?) -> Int {
    return bio?.count ?? 0
}

// Главный тег профиля: первый из списка, заглавными буквами.
func mainTag(_ tags: [String]) -> String? {
    return tags.first?.uppercased()
}

// Значок сотрудника: почта заканчивается на ryadom.team.
func isStaff(email: String?) -> Bool {
    return email?.lowercased().hasSuffix("ryadom.team") ?? false
}
```

## @rules
- must: /\?\.[\s\S]*\?\.[\s\S]*\?\./ :: Используй `?.` в каждой из трёх функций — в коде должно быть три таких обращения.
- mustnot: /\b(if|guard)\b/ :: Эта задача решается без `if` и `guard`: хватит `?.` и `??`.

## @hint1
Каждая функция — одна строка с `return`. Во всех трёх ты обращаешься к свойству или методу значения, которого может не быть. Значит, перед точкой нужен вопросительный знак.

В `bioLength` обратись к свойству `count` у параметра `bio` — через `?.`. Получится число-опционал. Функция должна вернуть обычное число, поэтому в конце добавь оператор из двух вопросительных знаков и запасное значение — ноль.

В `mainTag` сам массив не опционал, поэтому после `tags` стоит обычная точка и `first`. А вот `first` возвращает коробочку — и уже после него нужен `?.` с вызовом метода для заглавных букв. Запасное значение здесь не требуется: функция по условию возвращает `String?`, так что `nil` для пустого массива — это и есть нужный ответ.

В `isStaff` цепочка самая длинная. Сначала `?.` и перевод почты в маленькие буквы. Потом обычная точка и проверка окончания строки. Результат — `Bool?`, поэтому в конце снова `??` и запасное `false`.

## @hint3
Остались пропуски — по одному в каждой функции:

```swift
func bioLength(_ bio: String?) -> Int {
    return bio?.count ?? ___
}

func mainTag(_ tags: [String]) -> String? {
    return tags.first___uppercased()
}

func isStaff(email: String?) -> Bool {
    return email?.lowercased().___("ryadom.team") ?? false

```

В первом пропуске — длина для случая, когда текста нет. Во втором — два символа, которыми обращаются к методу опционала. В третьем — метод строки, который проверяет её окончание.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** `bio?.count` спрашивает: «в `bio` есть текст?» Если да — берёт его длину, если нет — даёт `nil`. Оператор `??` превращает этот `nil` в ноль. В `mainTag` выражение `tags.first` возвращает первый тег или `nil` для пустого массива, а `?.uppercased()` переводит тег в заглавные буквы, только если он нашёлся. В `isStaff` цепочка из трёх звеньев: почта, если она есть, переводится в маленькие буквы, потом проверяется её окончание. Если почты нет, оба вызова пропускаются, и `??` подставляет `false`.

**Почему в `mainTag` нет `??`.** Функция возвращает `String?`. Пустой массив тегов — нормальная ситуация, и `nil` честно сообщает о ней тому, кто вызывает функцию. Экран сам решит, что делать: скрыть плашку или показать что-то другое. Не всякий опционал нужно разворачивать немедленно.

**Почему перед `hasSuffix` обычная точка.** Вопросительный знак нужен там, где слева стоит опционал. `email` — опционал, поэтому `email?.lowercased()`. А `lowercased()` возвращает обычную строку, и следующий метод вызывается у неё обычной точкой. Если `email` пуст, до этого места выполнение просто не доходит.

**Зачем `lowercased()`.** В адресах почты большие и маленькие буквы не различаются. `Support@Ryadom.Team` и `support@ryadom.team` — один и тот же ящик. Перед сравнением текст приводят к одному виду.

**Типичные ошибки:**

- `bio.count` без вопросительного знака — Swift не даст обратиться к свойству коробочки;
- `tags?.first` — массив `tags` не опционал, вопрос нужен после `first`, а не перед ним;
- забыт `?? 0` или `?? false` — функция обещала обычное значение, а цепочка даёт опционал;
- `contains` вместо `hasSuffix` — почта `ryadom.team@example.com` ошибочно получит значок.
