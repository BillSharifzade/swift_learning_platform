## @description

### Контекст
Утро понедельника. После пятничного релиза в трекере три жалобы с одинаковым смыслом: «Открываю вкладку "Статистика" в профиле — приложение закрывается». Все три — от людей, которые зарегистрировались на выходных.

Тимлид нашёл виноватый код: «Статистику писал Билол и проверял её на своём профиле. У него сотня постов, место в рейтинге и указан год рождения. У новичков ничего этого нет. Посмотри на его функции — они усыпаны восклицательными знаками. Перепиши так, чтобы не осталось ни одного».

### Новое в Swift
Есть ещё один способ достать значение из коробочки — самый короткий и самый опасный. После опционала ставят восклицательный знак:

```swift
let text: String? = "42"
let value = text!       // обычный String
```

Это **принудительная развёртка**. Восклицательный знак — обещание компилятору: «значение там точно есть, не проверяй». Компилятор верит на слово и защищать тебя перестаёт. Пока обещание выполняется, всё работает. Но стоит в коробочке оказаться `nil` — и программа мгновенно останавливается:

```text
Fatal error: Unexpectedly found nil while unwrapping an Optional value
```

Пользователь при этом не видит никакого сообщения. Приложение просто закрывается.

**Почему такие ошибки доходят до релиза.** На данных разработчика код работает: у него заполнен профиль, есть посты и фотографии. Падение случается у других людей — у тех, чьи данные неполные. Именно это и произошло со статистикой.

**Чем заменить `!`.** Любым способом, который ты уже знаешь. Выбор зависит от того, что должно произойти при `nil`:

```swift
let size = Int(text)!           // было: упадёт, если в тексте не число
let size = Int(text) ?? 16      // стало: есть разумное значение по умолчанию
```

```swift
let top = scores.max()!         // было: упадёт на пустом массиве

guard let top = scores.max() else {    // стало: без значения продолжать незачем
    return "Оценок пока нет"
}
```

Если для `nil` нужно другое действие — подойдёт `if let`. Если нужно вызвать метод — `?.`.

Вспомни, какие операции из этой задачи возвращают опционал: `max()` — наибольший элемент массива или `nil` для пустого; `firstIndex(of:)` — номер элемента или `nil`, если его нет; словарь по ключу и `Int("...")`.

> ⚠️ В чужом коде ты можешь встретить тип с восклицательным знаком: `var title: String!`. Это **неявно развёрнутый опционал** — коробочка, которая при каждом обращении разворачивается сама, будто к ней дописали `!`. Если внутри `nil`, программа упадёт точно так же. Такие типы остались от старых библиотек. В своём коде их лучше не заводить.

### Задача
1. Нажми «Проверить», ничего не меняя. Код соберётся и даже напечатает статистику Билола, а потом упадёт на данных новичка. Прочитай объяснение: в нём указана строка, на которой это случилось.
2. Перепиши три функции так, чтобы в них не осталось принудительной развёртки `!`:
   - `bestPostLine(likes:)` — если постов нет (массив пуст), возвращает `Постов пока нет`;
   - `rankLine(nickname:ranking:)` — если ника нет в рейтинге, возвращает `Вне рейтинга`;
   - `birthYearLine(profile:)` — если ключа `"birthYear"` нет или по нему лежит не число, возвращает `Год рождения скрыт`.
3. Для полных данных функции должны работать как раньше. Названия, параметры и тексты не меняй.

### Пример
```swift
bestPostLine(likes: [12, 120, 45])   // "Лайков у лучшего поста: 120"
bestPostLine(likes: [])              // "Постов пока нет"

rankLine(nickname: "sunny_day", ranking: ["night_owl", "sunny_day"])   // "Место в рейтинге: 2"
rankLine(nickname: "new_user", ranking: ["night_owl", "sunny_day"])    // "Вне рейтинга"

birthYearLine(profile: ["birthYear": "1996"])       // "Год рождения: 1996"
birthYearLine(profile: ["nickname": "night_owl"])   // "Год рождения скрыт"
```

## @starter
```swift
// Вкладка "Статистика" в профиле

// Лайки у самого популярного поста. likes — лайки каждого поста пользователя
func bestPostLine(likes: [Int]) -> String {
    let best = likes.max()!
    return "Лайков у лучшего поста: \(best)"
}

// Место в рейтинге района. ranking — ники по порядку, от первого места
func rankLine(nickname: String, ranking: [String]) -> String {
    let index = ranking.firstIndex(of: nickname)!
    return "Место в рейтинге: \(index + 1)"
}

// Год рождения. profile — профиль с сервера, год лежит по ключу "birthYear"
func birthYearLine(profile: [String: String]) -> String {
    let year = Int(profile["birthYear"]!)!
    return "Год рождения: \(year)"
}

// Билол проверял экран на своём профиле — на нём всё работает
print(bestPostLine(likes: [12, 120, 45]))
print(rankLine(nickname: "bilol_dev", ranking: ["night_owl", "bilol_dev", "coffee_lover"]))
print(birthYearLine(profile: ["name": "Билол", "birthYear": "1994"]))
```

## @solution
```swift
// Вкладка "Статистика" в профиле

// Лайки у самого популярного поста. likes — лайки каждого поста пользователя
func bestPostLine(likes: [Int]) -> String {
    guard let best = likes.max() else {
        return "Постов пока нет"
    }
    return "Лайков у лучшего поста: \(best)"
}

// Место в рейтинге района. ranking — ники по порядку, от первого места
func rankLine(nickname: String, ranking: [String]) -> String {
    guard let index = ranking.firstIndex(of: nickname) else {
        return "Вне рейтинга"
    }
    return "Место в рейтинге: \(index + 1)"
}

// Год рождения. profile — профиль с сервера, год лежит по ключу "birthYear"
func birthYearLine(profile: [String: String]) -> String {
    guard let text = profile["birthYear"], let year = Int(text) else {
        return "Год рождения скрыт"
    }
    return "Год рождения: \(year)"
}

// Билол проверял экран на своём профиле — на нём всё работает
print(bestPostLine(likes: [12, 120, 45]))
print(rankLine(nickname: "bilol_dev", ranking: ["night_owl", "bilol_dev", "coffee_lover"]))
print(birthYearLine(profile: ["name": "Билол", "birthYear": "1994"]))
```

## @rules
- mustnot: /[\w\)\]]!(?!=)/ :: В коде осталась принудительная развёртка: восклицательный знак после значения, например `likes.max()!`. Замени каждую на `guard let`, `if let` или `??`.

## @hint1
Объяснение ошибки после первой проверки показывает строку, на которой программа упала. В каждой из трёх функций есть такая строка: в ней после значения стоит восклицательный знак. А в третьей функции их даже два.

Действуй одинаково во всех трёх случаях. Найди выражение, после которого стоит `!`, — именно оно возвращает опционал. Убери восклицательный знак и разверни опционал безопасно. Здесь удобнее всего `guard let`: без значения строить строку не из чего, поэтому в блоке `else` сразу возвращается запасной текст из условия. А после `guard` остаётся та же строка с `return`, что и была.

В `bestPostLine` опционал возвращает метод `max()`: у пустого массива наибольшего элемента нет. В `rankLine` — метод `firstIndex(of:)`: ника может не быть в списке. В `birthYearLine` опционалов два, и они идут друг за другом: сначала словарь по ключу отдаёт текст или `nil`, потом `Int` превращает текст в число или в `nil`. Оба шага можно записать в одном `guard` через запятую.

## @hint2
Вот как строка с `!` превращается в безопасную — на примере с оценками:

```swift
// было
let top = scores.max()!
return "Лучшая оценка: \(top)"

// стало
guard let top = scores.max() else {
    return "Оценок пока нет"
}
return "Лучшая оценка: \(top)"
```

Имя константы и строка с результатом остались прежними. Изменился только способ достать значение. А два опционала подряд разворачиваются так: `guard let text = settings["fontSize"], let size = Int(text) else { ... }`.

## @hint4
Вот готовое решение:

{{solution}}

**Что было не так.** В каждой функции стояла принудительная развёртка. `likes.max()!` падала на пустом массиве: у новичка нет постов, `max()` возвращает `nil`. `ranking.firstIndex(of: nickname)!` падала, когда ника нет в рейтинге. А в строке `Int(profile["birthYear"]!)!` было сразу два рискованных места: ключа могло не быть в словаре, а текст мог оказаться не числом. Компилятор молчал, потому что `!` — это просьба не проверять.

**Как работает решение.** Каждый `!` заменён на `guard let`. Он делает то же самое — достаёт значение, — но сначала проверяет, есть ли оно. Если значения нет, функция возвращает спокойный текст: «Постов пока нет», «Вне рейтинга», «Год рождения скрыт». Если есть — выполнение идёт дальше, и строка результата собирается точно так же, как раньше. В `birthYearLine` два шага объединены через запятую: второй использует `text`, развёрнутый первым.

**Почему `guard let`, а не проверка перед `!`.** Можно написать `if likes.max() != nil { ... likes.max()! ... }`, и программа не упадёт. Но восклицательный знак останется в коде. Завтра кто-нибудь изменит условие или перенесёт строку — и защита исчезнет, а `!` продолжит стоять. Безопасная развёртка не оставляет такой возможности: значение либо получено, либо обработано его отсутствие.

**Как привыкнуть.** Каждый раз, когда рука тянется поставить `!`, задай себе вопрос: «А что увидит человек, если значения не окажется?» Ответ на него и есть то, что нужно написать в `else` или после `??`.

**Типичные ошибки:**

- исправлена только та функция, на которой программа упала первой, — остальные упадут на следующих проверках;
- в `birthYearLine` убран один восклицательный знак из двух;
- запасной текст возвращается всегда, даже когда данные есть, — проверка для полных данных это заметит;
- `index + 1` заменён на `index` — места в рейтинге считаются с единицы, а индексы массива с нуля.
