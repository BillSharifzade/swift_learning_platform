## @description

### Контекст
Ты пришла в команду приложения такси «Ветер». Перед заказом пассажир выбирает класс автомобиля: эконом, комфорт или бизнес. От класса зависит многое — например, сколько минут водитель ждёт пассажира бесплатно.

Сейчас класс хранится обычной строкой: `"economy"`, `"comfort"`, `"business"`. На прошлой неделе в одном месте кода появилась опечатка — `"bussiness"`. Для Swift это просто другой текст, поэтому он промолчал. А пассажиры бизнес-класса увидели на экране пустое место вместо названия.

Тимлид просит: «Давай заведём для класса автомобиля свой тип. Пусть опечатки ловит компилятор, а не пассажиры».

### Новое в Swift
**Перечисление** (в коде — `enum`, от английского enumeration) — это свой тип с коротким списком возможных значений. Строка может быть какой угодно. А значение перечисления — только одним из вариантов, которые ты сама перечислила.

```swift
enum DriverStatus {
    case offline
    case free
    case busy
}
```

Имя типа пишется с большой буквы, как у структур. Каждый вариант начинается со слова `case` и пишется с маленькой буквы.

Значение создаётся через точку: тип, точка, вариант.

```swift
var status = DriverStatus.free
```

Когда Swift уже знает тип, имя типа можно не повторять. Достаточно точки и варианта:

```swift
status = .busy
let another: DriverStatus = .offline
```

Написать `.bisy` не получится: такого варианта нет, и Swift сразу покажет ошибку. Именно этого и хочет тимлид.

Значения перечисления можно сравнивать: `status == .busy` даст `true`.

**switch по перечислению.** Чтобы для каждого варианта сделать что-то своё, используют уже знакомый `switch`:

```swift
func canTakeOrder(_ status: DriverStatus) -> Bool {
    switch status {
    case .offline:
        return false
    case .free:
        return true
    case .busy:
        return false
    }
}

print(canTakeOrder(.free))   // true
```

Точка перед вариантом обязательна: `case .free:`. Без неё Swift решит, что `free` — это имя какой-то переменной, и не найдёт её.

Обрати внимание: здесь нет `default`. Swift знает все варианты `DriverStatus` и сам проверяет, что ни один не забыт. Такой `switch` называют **исчерпывающим**.

> 💡 Не добавляй `default` в `switch` по перечислению. Если завтра появится вариант `onBreak`, Swift укажет на каждый `switch`, где его забыли обработать. С `default` он бы промолчал — и ошибка снова дошла бы до пассажиров.

### Задача
1. Объяви перечисление `CarClass` с тремя вариантами: `economy`, `comfort`, `business`.
2. Допиши функцию `title(for:)`. Она принимает `CarClass` и возвращает название для экрана: `"Эконом"`, `"Комфорт"` или `"Бизнес"`.
3. Напиши функцию `freeWaitingMinutes(for:)`. Она принимает `CarClass` и возвращает `Int` — сколько минут водитель ждёт бесплатно: `3` для эконома, `5` для комфорта, `10` для бизнеса.
4. В обеих функциях разбирай варианты через `switch` без `default`.

Последние строки в редакторе — проба: так функции вызываются из других частей приложения. Менять их не нужно.

### Пример
```swift
title(for: .economy)                 // "Эконом"
title(for: .business)                // "Бизнес"
freeWaitingMinutes(for: .comfort)    // 5
```

Проба в конце кода напечатает:

```text
Комфорт: бесплатное ожидание 5 мин.
```

## @solution
```swift
// 1. Объяви перечисление CarClass с вариантами economy, comfort, business
enum CarClass {
    case economy
    case comfort
    case business
}

// 2. Название класса для экрана: "Эконом", "Комфорт" или "Бизнес"
func title(for car: CarClass) -> String {
    // Напиши здесь switch по параметру car
    switch car {
    case .economy:
        return "Эконом"
    case .comfort:
        return "Комфорт"
    case .business:
        return "Бизнес"
    }
}

// 3. Бесплатное ожидание в минутах: 3, 5 или 10.
//    Напиши функцию freeWaitingMinutes(for:) сама, по образцу первой
func freeWaitingMinutes(for car: CarClass) -> Int {
    switch car {
    case .economy:
        return 3
    case .comfort:
        return 5
    case .business:
        return 10
    }
}

// Проба: так функции вызываются из других частей приложения
let selected = CarClass.comfort
print("\(title(for: selected)): бесплатное ожидание \(freeWaitingMinutes(for: selected)) мин.")
```

## @rules
- must: /\benum\s+CarClass\b/ :: Класс автомобиля должен быть перечислением: `enum CarClass { ... }`.
- must: /\bswitch\b[\s\S]*\bswitch\b/ :: Разбери варианты через `switch` в обеих функциях — в коде должно быть два `switch`.
- mustnot: /\bdefault\s*:/ :: В `switch` по перечислению `default` не нужен. Перечисли все три варианта — тогда Swift сам проверит, что ни один не забыт.

## @hint1
Начни с типа. Перечисление объявляется словом `enum`, за ним идёт имя `CarClass` и фигурные скобки. Внутри скобок — три строки, по одной на вариант, и каждая начинается со слова `case`. Пока перечисления нет, Swift не понимает слово `CarClass` в заголовке функции — отсюда и ошибка при первой проверке.

Теперь функция `title(for:)`. Внутри неё нужен `switch` по параметру `car`. В нём три ветки — по одной на каждый вариант. Вариант в ветке пишется с точкой в начале. Каждая ветка возвращает свой текст через `return`.

Вторую функцию напиши целиком сама, по образцу первой: слово `func`, имя `freeWaitingMinutes`, в скобках метка `for`, имя параметра и тип `CarClass`. Отличие одно: после стрелки стоит `Int`, и ветки возвращают числа, а не текст.

Ветку `default` не добавляй. Когда перечислены все три варианта, она не нужна.

## @hint2
Вот как объявляется перечисление и как функция разбирает его варианты — на примере статуса водителя:

```swift
enum DriverStatus {
    case offline
    case free
    case busy
}

func statusTitle(for status: DriverStatus) -> String {
    switch status {
    case .offline:
        return "Не на линии"
    case .free:
        return "Свободен"
    case .busy:
        return "Выполняет заказ"
    }
}
```

У тебя всё устроено так же: три варианта и по одной ветке `switch` на каждый.

## @hint3
Перечисление и первая функция почти готовы. Заполни пропуски, а во второй функции допиши две ветки:

```swift

    case economy
    case ___
    case ___
```

В первых двух пропусках — оставшиеся варианты. В следующих двух — названия в кавычках. В последнем — имя параметра, по которому идёт разбор.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** `enum CarClass` создаёт новый тип, у которого ровно три возможных значения. Функция `title(for:)` получает одно из них в параметре `car`. `switch` сравнивает его с вариантами по очереди и выполняет подходящую ветку. Запись `.economy` — это сокращение от `CarClass.economy`: Swift знает тип параметра, поэтому имя типа можно не повторять. Функция `freeWaitingMinutes(for:)` устроена так же, только возвращает числа.

**Почему перечисление, а не строка.** Строке `"bussiness"` Swift не удивится: текст может быть любым. А значения `CarClass.bussiness` не существует, и код с такой опечаткой просто не соберётся. Ошибку увидит разработчик через секунду, а не пассажир через неделю.

**Почему нет `default`.** `switch` обязан предусмотреть все возможные значения. У строки их бесконечно много, поэтому там без `default` не обойтись. У `CarClass` значений три, и все три перечислены. Если команда добавит четвёртый класс, например `minivan`, Swift откажется собирать обе функции, пока в них не появится новая ветка. С `default` он бы промолчал, и минивэн получил бы чужое название.

**Типичные ошибки:**

- вариант в ветке написан без точки: `case economy:` — Swift ищет переменную с таким именем и не находит;
- название варианта написано с большой буквы или с опечаткой — имена должны совпадать с объявлением буква в букву;
- пропущена одна из веток — Swift сообщит, что `switch` должен быть исчерпывающим;
- во второй функции после стрелки оставлен `String`, хотя возвращаются числа.
