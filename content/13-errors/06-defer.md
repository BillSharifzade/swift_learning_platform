## @description

### Контекст
Чтобы деньги не списались дважды, когда человек нервно жмёт «Оплатить» два раза подряд, счёт в «Монете» на время операции блокируется. Пока идёт одно списание, второе получает отказ. Когда операция закончена, счёт разблокируется. Каждый шаг пишется в журнал — служба безопасности его читает.

В поддержку пришло обращение: «Билол пытался оплатить покупку, но денег не хватило. Он пополнил карту, а платить всё равно не может — приложение пишет, что счёт заблокирован».

Ты открываешь `withdraw` и видишь причину. Разблокировка стоит в самом конце функции. Если по дороге брошена ошибка, функция заканчивается раньше, и до разблокировки дело не доходит. Счёт остаётся заблокированным навсегда.

Тимлид просит: «Почини `withdraw` и сразу напиши `deposit` по тому же принципу. Разблокировка должна происходить при любом исходе — и при успехе, и при ошибке».

### Новое в Swift
Можно было бы разблокировать счёт перед каждым `throw`. Но таких мест три, завтра появится четвёртое, и про него обязательно забудут. Для «уборки при любом исходе» в Swift есть `defer`.

`defer` — «отложить». Код в его фигурных скобках выполняется **в момент выхода из функции**, как бы она ни закончилась: через `return`, через `throw` или просто дойдя до конца.

Пример на другом устройстве — кассовом принтере в магазине, который принимает оплату через «Монету»:

```swift
enum PrinterError: Error {
    case emptyReceipt
}

final class ReceiptPrinter {
    var isBusy = false
    var printedLines: [String] = []

    func printReceipt(_ lines: [String]) throws {
        isBusy = true
        defer {
            isBusy = false
        }
        guard !lines.isEmpty else {
            throw PrinterError.emptyReceipt
        }
        printedLines += lines
    }
}
```

Пустой чек — ошибка, но принтер всё равно освободится: `defer` выполнится и при броске ошибки. Удачная печать тоже освободит принтер — уже после того, как строки добавлены.

Три правила `defer`:

1. **Выполняется последним.** Всё, что написано в функции после `defer`, выполнится раньше, чем код внутри него. Пишут `defer` в одном месте, а срабатывает он в самом конце.
2. **Работает, только если до него дошли.** Если функция вышла раньше строки с `defer`, отложенный код не выполнится — его ещё никто не «записал».
3. **Несколько `defer` выполняются в обратном порядке**: последний записанный — первым. Как стопка тарелок.

Из второго правила главный совет: ставь `defer` **сразу после** того, что нужно будет отменить. Заняла ресурс — тут же, следующей строкой, напиши, как его освободить.

> ⚠️ Если поставить `defer` с разблокировкой раньше самой блокировки — например, в самое начало функции, — он сработает и тогда, когда счёт заблокировала **другая** операция. Чужая блокировка снимется, и защита от двойного списания перестанет работать.

### Задача
В редакторе есть перечисление `AccountError` и класс `Account` со свойствами `balance`, `isLocked` и `log`.

1. Почини метод `withdraw(_:)`. Разблокировка счёта — `isLocked = false` и запись `Счёт разблокирован` в `log` — должна происходить при любом выходе из метода **после того, как счёт заблокирован**. Сделай это через `defer`. Остальное поведение не меняй:
   - если счёт уже заблокирован — бросить `AccountError.accountLocked`, ничего не трогая;
   - иначе заблокировать счёт и добавить в `log` запись `Счёт заблокирован`;
   - сумма не больше нуля — `AccountError.invalidAmount`;
   - сумма больше баланса — `AccountError.insufficientFunds` с тем, сколько не хватает;
   - иначе уменьшить `balance` и добавить в `log` запись `Списано 300 руб.` (с нужной суммой).
2. Допиши метод `deposit(_:)` — пополнение счёта. Он помечен `throws` и работает по тому же принципу:
   - если счёт уже заблокирован — бросить `AccountError.accountLocked`, ничего не трогая;
   - заблокировать счёт, записать в `log` `Счёт заблокирован`, через `defer` разблокировать и записать `Счёт разблокирован`;
   - сумма не больше нуля — `AccountError.invalidAmount`;
   - иначе увеличить `balance` и записать в `log` `Зачислено 250 руб.` (с нужной суммой).

### Пример
```swift
let account = Account(balance: 1000)
try account.withdraw(1500)   // ошибка insufficientFunds(missing: 500)
account.isLocked             // false — счёт разблокирован, несмотря на ошибку
account.log                  // ["Счёт заблокирован", "Счёт разблокирован"]

try account.deposit(250)
account.balance              // 1250
account.log                  // [..., "Счёт заблокирован", "Зачислено 250 руб.", "Счёт разблокирован"]
```

// Почему операция со счётом не прошла
enum AccountError: Error {
    case accountLocked
    case invalidAmount
    case insufficientFunds(missing: Int)
}

// Счёт клиента. Это класс: одним счётом пользуются сразу несколько экранов
final class Account {
    var balance: Int
    var isLocked = false
    var log: [String] = []

    init(balance: Int) {
        self.balance = balance
    }

    // Списание. Пока оно идёт, счёт заблокирован,
    // чтобы повторное нажатие не списало деньги дважды.
    // Ошибка: при отказе счёт остаётся заблокированным — почини через defer
    func withdraw(_ amount: Int) throws {
        guard !isLocked else {
            throw AccountError.accountLocked
        }
        isLocked = true
        log.append("Счёт заблокирован")

        guard amount > 0 else {
            throw AccountError.invalidAmount
        }
        guard amount <= balance else {
            throw AccountError.insufficientFunds(missing: amount - balance)
        }
        balance -= amount
        log.append("Списано \(amount) руб.")

        isLocked = false
        log.append("Счёт разблокирован")
    }

    // Пополнение: та же блокировка на время операции
    func deposit(_ amount: Int) throws {

    }
}

// Так выглядит обращение в поддержку
let account = Account(balance: 1000)
do {
    try account.withdraw(1500)
} catch {
    print("Отказ: \(error)")
}
print("Счёт заблокирован: \(account.isLocked)")

## @solution
```swift
// Почему операция со счётом не прошла
enum AccountError: Error {
    case accountLocked
    case invalidAmount
    case insufficientFunds(missing: Int)
}

// Счёт клиента. Это класс: одним счётом пользуются сразу несколько экранов
final class Account {
    var balance: Int
    var isLocked = false
    var log: [String] = []

    init(balance: Int) {
        self.balance = balance
    }

    // Списание. Пока оно идёт, счёт заблокирован,
    // чтобы повторное нажатие не списало деньги дважды.
    // Ошибка: при отказе счёт остаётся заблокированным — почини через defer
    func withdraw(_ amount: Int) throws {
        guard !isLocked else {
            throw AccountError.accountLocked
        }
        isLocked = true
        log.append("Счёт заблокирован")
        defer {
            isLocked = false
            log.append("Счёт разблокирован")
        }

        guard amount > 0 else {
            throw AccountError.invalidAmount
        }
        guard amount <= balance else {
            throw AccountError.insufficientFunds(missing: amount - balance)
        }
        balance -= amount
        log.append("Списано \(amount) руб.")
    }

    // Пополнение: та же блокировка на время операции
    func deposit(_ amount: Int) throws {
        guard !isLocked else {
            throw AccountError.accountLocked
        }
        isLocked = true
        log.append("Счёт заблокирован")
        defer {
            isLocked = false
            log.append("Счёт разблокирован")
        }

        guard amount > 0 else {
            throw AccountError.invalidAmount
        }
        balance += amount
        log.append("Зачислено \(amount) руб.")
    }
}

// Так выглядит обращение в поддержку
let account = Account(balance: 1000)
do {
    try account.withdraw(1500)
} catch {
    print("Отказ: \(error)")
}
print("Счёт заблокирован: \(account.isLocked)")
```

## @rules
- must: /\bdefer\s*\{[\s\S]*\bdefer\s*\{/ :: Разблокировку в обоих методах, `withdraw` и `deposit`, нужно записать через `defer { ... }`.

## @hint1
Начни с `withdraw`. Найди две строки, которые разблокируют счёт, в самом конце метода. Вырежи их оттуда и оберни в блок `defer` с фигурными скобками. Вставь этот блок сразу после строки, которая пишет в журнал «Счёт заблокирован». Теперь при любом выходе из метода, даже через `throw`, счёт разблокируется.

Не ставь `defer` выше блокировки. Если счёт уже занят другой операцией, метод должен выйти через первый `guard` и ничего не трогать — в том числе не снимать чужую блокировку.

`deposit` устроен так же, как исправленный `withdraw`: тот же первый `guard`, та же блокировка с записью в журнал, тот же `defer`. Дальше одна проверка суммы — она должна быть больше нуля. Потом увеличь баланс и сделай запись о зачислении.

## @hint2
Блокировка и `defer` идут парой, одна за другой:

```swift
isLocked = true
log.append("Счёт заблокирован")
defer {
    isLocked = false
    log.append("Счёт разблокирован")
}
```

Всё, что ниже, может бросать ошибки: разблокировка всё равно произойдёт, причём в самом конце.

## @hint3
`withdraw` уже исправлен. Допиши пропуски в `deposit`:

```swift
func deposit(_ amount: Int) throws {
    guard !isLocked else {
        throw AccountError.accountLocked
    }
    isLocked = true
    log.append("Счёт заблокирован")
    ___ {
        isLocked = false
        log.append("Счёт разблокирован")
    }

    guard ___ else {
        throw AccountError.invalidAmount
    }
    balance ___ amount
    log.append("Зачислено \(amount) руб.")
}
```

В первом пропуске — слово, которое откладывает код до выхода из метода. Во втором — условие правильной суммы. В третьем — оператор, увеличивающий баланс.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** В обоих методах сразу за блокировкой стоит `defer`. С этого момента Swift помнит: «при выходе из метода разблокировать счёт и записать это в журнал». Дальше может случиться что угодно. Сумма неправильная — `throw`, и перед выходом выполнится `defer`. Денег не хватает — то же самое. Всё хорошо — метод дойдёт до конца, запишет «Списано 300 руб.», и только потом сработает `defer`. Поэтому в журнале запись о разблокировке всегда последняя.

**Почему `defer` именно после блокировки.** Первый `guard` срабатывает, когда счёт уже занят другой операцией. В этот момент `defer` ещё не встретился, и метод выходит, ничего не меняя. Так и должно быть: снимать чужую блокировку нельзя. Если бы `defer` стоял в самом начале, он выполнился бы и здесь — и защита от двойного списания сломалась бы.

**Почему не разблокировать перед каждым `throw`.** Так тоже будет работать, но только до первого нового `guard`, про который кто-нибудь забудет. `defer` записывает правило один раз: «заняла — освободи», и оно выполняется при любом исходе. Тот же приём используют для закрытия файлов, соединений с сервером и индикаторов загрузки.

**Типичные ошибки:**

- старые строки разблокировки остались в конце `withdraw` вместе с `defer` — в журнале будет две записи «Счёт разблокирован»;
- `defer` стоит перед первым `guard` — снимается чужая блокировка;
- в `deposit` нет проверки `isLocked` — пополнение пройдёт посреди другой операции.
