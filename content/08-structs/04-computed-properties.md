## @description

### Контекст
Дизайнер обновила карточку жилья. Рядом с ценой теперь написано, сколько выходит на одного гостя, а рядом с рейтингом стоит слово — «Превосходно» или «Хорошо». Хозяевам добавили поле «Цена за неделю»: многие сдают жильё неделями, и считать в ночах им неудобно.

Тимлид предупреждает: «Только не заводи под это новые хранимые поля. Поменяют цену за ночь — и цена за гостя устареет. Пусть всё считается на лету из того, что уже есть».

### Новое в Swift
Свойства, которые ты объявляла до сих пор, называются **хранимыми**: в каждом лежит значение. Бывает и другой вид — **вычисляемое свойство**. Оно ничего не хранит, а при каждом обращении вычисляет значение по другим свойствам.

```swift
struct Review {
    let author: String
    let cleanliness: Int
    let location: Int

    var average: Double {
        Double(cleanliness + location) / 2
    }
}

let review = Review(author: "Билол", cleanliness: 5, location: 4)
print(review.average)     // 4.5
```

Что здесь важно:

- вычисляемое свойство всегда объявляют через `var` и всегда указывают тип;
- после типа нет знака `=`, сразу идут фигурные скобки с кодом. Он работает как тело функции: одно выражение можно написать без `return`, а если строк несколько — `return` нужен;
- читают его без круглых скобок, как обычное свойство: `review.average`;
- при создании экземпляра его не указывают — заполнять нечего.

Когда писать свойство, а когда метод? Ориентир такой. Если это характеристика экземпляра, которая считается быстро и без параметров, — свойство (`average`). Если это действие или нужны параметры — метод (`totalPrice(nights:)`).

**Запись в вычисляемое свойство.** Иногда удобно, чтобы такому свойству можно было ещё и присваивать значение. Тогда внутри пишут два блока: `get` — как прочитать, `set` — что сделать при присваивании. Новое значение доступно в `set` под именем `newValue`:

```swift
struct Deposit {
    var rubles: Int

    var kopecks: Int {
        get {
            rubles * 100
        }
        set {
            rubles = newValue / 100
        }
    }
}

var deposit = Deposit(rubles: 5000)
print(deposit.kopecks)      // 500000
deposit.kopecks = 250000
print(deposit.rubles)       // 2500
```

Хранится только `rubles`. Платёжному сервису сумма нужна в копейках, и `kopecks` пересчитывает её туда и обратно. Два числа не могут разойтись, потому что на самом деле число одно.

> 💡 Есть ещё `lazy var` — «ленивое» хранимое свойство. Его значение вычисляется один раз, при первом обращении, и запоминается. Так откладывают дорогие вычисления. Подробно о нём будет ближе к концу курса, пока достаточно знать, что оно существует.

### Задача
В редакторе есть структура `Apartment` с хранимыми свойствами `title`, `pricePerNight`, `maxGuests` и `rating`. Добавь три вычисляемых свойства:

1. `pricePerGuest` типа `Int` — цена за ночь, делённая нацело на `maxGuests`. Жилья с нулём гостей в каталоге не бывает.
2. `ratingLabel` типа `String` — оценка словом:
   - рейтинг `4.8` и выше — `Превосходно`;
   - от `4.0` включительно и до `4.8` — `Хорошо`;
   - ниже `4.0` — `Нормально`.
3. `weeklyPrice` типа `Int` с блоками `get` и `set`:
   - при чтении возвращает цену за 7 ночей;
   - при записи пересчитывает `pricePerNight`: новая цена за неделю, делённая нацело на 7.

Код карточки под структурой менять не нужно. Он уже обращается к новым свойствам, поэтому не соберётся, пока ты их не добавишь.

### Пример
```swift
var apartment = Apartment(title: "Студия у набережной", pricePerNight: 3200, maxGuests: 2, rating: 4.9)
apartment.pricePerGuest        // 1600
apartment.ratingLabel          // "Превосходно"
apartment.weeklyPrice          // 22400
apartment.weeklyPrice = 21000
apartment.pricePerNight        // 3000
apartment.pricePerGuest        // 1500
```

Код карточки должен вывести:

```text
Студия у набережной: Превосходно
На гостя: 1600 руб. за ночь
За неделю: 22400 руб.
После изменения: 3000 руб. за ночь, на гостя 1500 руб.
```

## @solution
```swift
struct Apartment {
    let title: String
    var pricePerNight: Int
    let maxGuests: Int
    let rating: Double

    // Добавь сюда вычисляемые свойства pricePerGuest, ratingLabel и weeklyPrice
    var pricePerGuest: Int {
        pricePerNight / maxGuests
    }

    var ratingLabel: String {
        if rating >= 4.8 {
            return "Превосходно"
        } else if rating >= 4.0 {
            return "Хорошо"
        } else {
            return "Нормально"
        }
    }

    var weeklyPrice: Int {
        get {
            pricePerNight * 7
        }
        set {
            pricePerNight = newValue / 7
        }
    }
}

// Карточка жилья. Этот код уже готов — менять его не нужно
var apartment = Apartment(title: "Студия у набережной", pricePerNight: 3200, maxGuests: 2, rating: 4.9)
print("\(apartment.title): \(apartment.ratingLabel)")
print("На гостя: \(apartment.pricePerGuest) руб. за ночь")
print("За неделю: \(apartment.weeklyPrice) руб.")

// Хозяин указал новую цену за неделю
apartment.weeklyPrice = 21000
print("После изменения: \(apartment.pricePerNight) руб. за ночь, на гостя \(apartment.pricePerGuest) руб.")
```

## @hint1
Все три свойства пишутся внутри структуры, после хранимых. Каждое начинается со слова `var`, затем идут имя, двоеточие и тип, а потом сразу фигурные скобки с кодом — без знака равенства.

Цена за гостя — одно выражение: цена за ночь делится на число гостей. Оба свойства целые, поэтому деление получится нацело само.

Оценка словом — это выбор из трёх вариантов по значению `rating`. Здесь подойдёт цепочка `if`, `else if`, `else`, как в модуле про условия. Проверяй от большего к меньшему: сначала самую высокую границу, потом следующую. В каждой ветке нужно вернуть свою строку через `return`. Обе границы входят в свой диапазон.

Цена за неделю устроена сложнее: внутри её фигурных скобок два блока. Блок чтения возвращает цену за ночь, умноженную на семь. Блок записи делает обратное: берёт пришедшее значение (оно доступно под специальным именем) и кладёт в `pricePerNight` его седьмую часть.

## @hint2
Свойство только для чтения — это код в фигурных скобках после типа. Если свойству нужно ещё и присваивать, внутри появляются блоки `get` и `set`:

```swift
struct Deposit {
    var rubles: Int

    var isLarge: Bool {
        rubles >= 10000
    }

    var kopecks: Int {
        get {
            rubles * 100
        }
        set {
            rubles = newValue / 100
        }
    }
}
```

`newValue` — то, что написано справа от знака `=` при присваивании. У тебя `pricePerGuest` и `ratingLabel` устроены как `isLarge`, а `weeklyPrice` — как `kopecks`.

## @hint3
Цена за гостя готова. В двух других свойствах заполни пропуски:

```swift
    var pricePerGuest: Int {
        pricePerNight / maxGuests
    }

    var ratingLabel: String {
        if rating >= ___ {
            return "Превосходно"
        } else if rating >= 4.0 {
            return ___
        } else {
            return "Нормально"
        }
    }

    var weeklyPrice: Int {
        get {
            pricePerNight * 7
        }
        set {
            pricePerNight = ___ / 7
        }
    }
```

В первом пропуске — граница для «Превосходно». Во втором — слово для среднего диапазона, в кавычках. В третьем — имя, под которым в `set` доступно присвоенное значение.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** `pricePerGuest` и `ratingLabel` выглядят снаружи как обычные свойства, но памяти под них нет. Каждый раз, когда карточка обращается к `apartment.pricePerGuest`, Swift выполняет код в фигурных скобках и отдаёт результат. Поэтому после изменения цены карточка показала уже 1500, хотя `pricePerGuest` никто не трогал.

**Почему не хранимые свойства.** Представь, что `pricePerGuest` — обычное хранимое свойство. Тогда при каждом изменении цены кто-то должен помнить, что его надо пересчитать. Забыл — и гость видит одну цену, а платит другую. Вычисляемое свойство устареть не может: оно всегда считается из актуальных данных.

**Как устроен `weeklyPrice`.** Строка `apartment.weeklyPrice = 21000` выглядит как присваивание, но хранить 21000 негде. Вместо этого запускается блок `set`: число 21000 приходит под именем `newValue`, делится на 7, и результат 3000 записывается в настоящее хранимое свойство `pricePerNight`. Блок `get` при чтении умножает цену за ночь обратно на 7.

**Почему в `ratingLabel` порядок проверок от большего к меньшему.** Рейтинг 4.9 больше и 4.8, и 4.0. Если сначала проверить `>= 4.0`, для него сработает ветка «Хорошо», и до «Превосходно» дело не дойдёт.

**Типичные ошибки:**

- `var pricePerGuest: Int = pricePerNight / maxGuests` — со знаком `=` это попытка объявить хранимое свойство, и Swift её не примет;
- `func pricePerGuest() -> Int` — это метод, а карточка обращается к свойству, без круглых скобок;
- `let` вместо `var` — вычисляемое свойство всегда объявляют через `var`;
- `rating > 4.8` — жильё с рейтингом ровно 4.8 потеряет свою оценку «Превосходно»;
- в `set` написано `weeklyPrice = newValue` — свойство присваивает значение самому себе, блок `set` без конца вызывает сам себя, и программа аварийно завершается.
