## @description

### Контекст
Из тикета тестировщика: «Открыла 30 фото подряд в редакторе — приложение стало тормозить и закрылось». Фото в полном размере занимает в памяти десятки мегабайт. Если снимки не выгружаются после закрытия редактора, память быстро заканчивается, и система телефона закрывает приложение.

Тимлид просит начать с наблюдения: «Добавь в классы `deinit`, который пишет в журнал. И воспроизведи сценарий из тикета: фото открыто в редакторе и попало в ленту недавних. Посмотрим, когда оно на самом деле выгружается».

### Новое в Swift
В «Гнезде» ты уже писала `deinit` — код, который выполняется, когда объект исчезает. Теперь разберёмся, **кто и когда** решает, что объект больше не нужен.

Каждый объект класса занимает место в памяти. Его нужно освободить, как только объект перестанет быть нужен. Swift делает это сам, с помощью механизма **ARC** (Automatic Reference Counting — автоматический подсчёт ссылок).

Идея простая. У каждого объекта есть невидимый **счётчик сильных ссылок**. Сильная ссылка — это любое обычное место, где лежит объект: переменная, константа, свойство другого объекта, элемент массива.

- Объект положили ещё в одно место — счётчик **+1**.
- Одно из мест перестало его хранить — счётчик **−1**.
- Счётчик стал **0** — выполняется `deinit`, и память освобождается.

Проследим за счётчиком шаг за шагом:

```swift
class Sticker {
    let name: String

    init(name: String) {
        self.name = name
    }

    deinit {
        print("Стикер удалён: \(name)")
    }
}

var selected: Sticker? = Sticker(name: "Сердечко")   // счётчик: 1
var favorite = selected                                // счётчик: 2
selected = nil                                         // счётчик: 1, объект жив
print("Выбор сброшен")
favorite = nil                                         // счётчик: 0, срабатывает deinit
```

```text
Выбор сброшен
Стикер удалён: Сердечко
```

Обрати внимание: `selected = nil` объект не удалил. Он только убрал одну ссылку. Объект исчез, когда пропала **последняя**.

Переменные здесь опциональные не случайно. Чтобы отпустить объект, в переменную кладут `nil`, а в обычную, не опциональную переменную `nil` не положить.

**Как ещё исчезает ссылка.** Не только через `nil`:

- в переменную положили другой объект — старый получил −1;
- закончился блок `{ }`, в котором объявлена константа, например тело функции;
- элемент убрали из массива или массив очистили: `stickers = []`;
- исчез объект, который хранил ссылку в своём свойстве.

Последний пункт важен. Когда счётчик объекта падает до нуля, сначала выполняется его `deinit`. Потом объект отпускает всё, что держал в свойствах, и их счётчики уменьшаются. Так одно закрытие может по цепочке освободить много объектов, а может и не освободить — если кто-то ещё держит их.

> 💡 Объекты в константах верхнего уровня, вроде `let photo = ...` в начале программы, живут до самого конца. Поэтому в сценариях этого модуля объекты хранятся в опциональных `var`: так их можно отпустить.

### Задача
В редакторе есть журнал `lifecycleLog` и два класса: `LoadedPhoto` — фото в памяти и `EditorScreen` — экран редактора, который держит фото в свойстве `photo`. Их `init` уже пишут в журнал.

1. Допиши `deinit` в `LoadedPhoto`: он добавляет в `lifecycleLog` строку `Выгружено: ` и имя файла, например `Выгружено: IMG_2041.jpg`.
2. Допиши `deinit` в `EditorScreen`: он добавляет строку `Закрыт редактор: ` и имя файла его фото.
3. В сценарии после записи «Пользователь закрывает редактор» отпусти экран: положи `nil` в `editor`.
4. После записи «Пользователь очищает ленту недавних» очисти массив `recentPhotos`.

В `deinit` ничего не печатай — только добавляй строки в журнал. Его выводит сценарий в конце.

### Пример
Сценарий должен вывести:

```text
Загружено: IMG_2041.jpg
Открыт редактор: IMG_2041.jpg
Пользователь закрывает редактор
Закрыт редактор: IMG_2041.jpg
Пользователь очищает ленту недавних
Выгружено: IMG_2041.jpg
```

Экран закрылся, а фото осталось: его ещё держит лента. Выгрузилось оно, только когда исчезла последняя ссылка.

```swift
class LoadedPhoto {
    let fileName: String

    init(fileName: String) {
        self.fileName = fileName
        lifecycleLog.append("Загружено: \(fileName)")
    }

    // 1. Допиши deinit: строка "Выгружено: " и имя файла

}

// Экран редактора. Пока он открыт, он держит фото в свойстве photo
class EditorScreen {
    let photo: LoadedPhoto

    init(photo: LoadedPhoto) {
        self.photo = photo
        lifecycleLog.append("Открыт редактор: \(photo.fileName)")
    }

    // 2. Допиши deinit: строка "Закрыт редактор: " и имя файла фото

}

// Сценарий из тикета: фото открыли в редакторе, и оно попало в ленту недавних
var editor: EditorScreen? = EditorScreen(photo: LoadedPhoto(fileName: "IMG_2041.jpg"))
var recentPhotos: [LoadedPhoto] = []
if let screen = editor {
    recentPhotos.append(screen.photo)
}

lifecycleLog.append("Пользователь закрывает редактор")
// 3. Отпусти экран редактора


lifecycleLog.append("Пользователь очищает ленту недавних")
// 4. Очисти ленту недавних


// Выводим журнал
for entry in lifecycleLog {
    print(entry)
}
```

## @solution
```swift
// Журнал памяти: сюда init и deinit записывают, что происходит с объектами
var lifecycleLog: [String] = []

// Фото, загруженное в память в полном размере
class LoadedPhoto {
    let fileName: String

    init(fileName: String) {
        self.fileName = fileName
        lifecycleLog.append("Загружено: \(fileName)")
    }

    // 1. Допиши deinit: строка "Выгружено: " и имя файла
    deinit {
        lifecycleLog.append("Выгружено: \(fileName)")
    }
}

// Экран редактора. Пока он открыт, он держит фото в свойстве photo
class EditorScreen {
    let photo: LoadedPhoto

    init(photo: LoadedPhoto) {
        self.photo = photo
        lifecycleLog.append("Открыт редактор: \(photo.fileName)")
    }

    // 2. Допиши deinit: строка "Закрыт редактор: " и имя файла фото
    deinit {
        lifecycleLog.append("Закрыт редактор: \(photo.fileName)")
    }
}

// Сценарий из тикета: фото открыли в редакторе, и оно попало в ленту недавних
var editor: EditorScreen? = EditorScreen(photo: LoadedPhoto(fileName: "IMG_2041.jpg"))
var recentPhotos: [LoadedPhoto] = []
if let screen = editor {
    recentPhotos.append(screen.photo)
}

lifecycleLog.append("Пользователь закрывает редактор")
// 3. Отпусти экран редактора
editor = nil

lifecycleLog.append("Пользователь очищает ленту недавних")
// 4. Очисти ленту недавних
recentPhotos = []

// Выводим журнал
for entry in lifecycleLog {
    print(entry)
}
```

## @rules
- must: /\bdeinit\s*\{[^}]*Выгружено/ :: В классе `LoadedPhoto` нужен `deinit`, который добавляет в журнал строку `Выгружено: ` и имя файла.
- mustnot: /\bprint\s*\(\s*"(?:Закрыт редактор|Выгружено)/ :: Строки `Закрыт редактор` и `Выгружено` не печатай через `print` — их добавляет в `lifecycleLog` сам `deinit`.

## @hint1
Начни с двух `deinit`. Он пишется внутри класса, рядом с `init`: слово `deinit` и фигурные скобки, без круглых скобок и параметров. Внутри — одна строка: добавить в `lifecycleLog` нужный текст через `append`, как это уже делает `init`. Имя файла вставляй интерполяцией. У `LoadedPhoto` оно лежит в свойстве `fileName`, а у `EditorScreen` — в свойстве `fileName` его фото, то есть в `photo`.

Теперь сценарий. Экран редактора хранится в опциональной переменной `editor`. Чтобы отпустить его, положи в неё `nil` — прямо под комментарием про шаг 3. Ленту недавних очищает присваивание пустого массива — под комментарием про шаг 4.

Сами `deinit` не вызывай: Swift вызовет их сам, когда исчезнет последняя ссылка. Если журнал получился правильным, значит, ты верно поняла, в какой момент это происходит.

## @hint2
`deinit` выглядит так — без скобок и параметров:

```swift
deinit {
    print("Стикер удалён: \(name)")
}
```

У тебя вместо `print` будет `lifecycleLog.append(...)`, как в `init`. А отпускают объект и очищают массив вот так:

```swift
selected = nil
stickers = []
```

## @hint3
Оба `deinit` почти готовы, осталось заполнить пропуски:

```swift
// в классе LoadedPhoto
deinit {
    lifecycleLog.append("Выгружено: \(fileName)")
}

// в классе EditorScreen
deinit {
    lifecycleLog.append("Закрыт редактор: \(___)")
}
```

```swift
lifecycleLog.append("Пользователь закрывает редактор")
editor = ___

lifecycleLog.append("Пользователь очищает ленту недавних")
recentPhotos = ___
```

В первом пропуске — имя файла фото, которое держит экран. Во втором — «пусто». В третьем — пустой массив.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Проследим за счётчиками. `LoadedPhoto(fileName:)` создаёт фото, и экран сразу кладёт его в своё свойство `photo`: у фото одна ссылка. Экран попадает в `editor`: у экрана одна ссылка. Строка `recentPhotos.append(screen.photo)` добавляет фото в массив: у фото уже две ссылки. Константа `screen` живёт только внутри `if let` и исчезает вместе с его скобками.

`editor = nil` убирает единственную ссылку на экран. Его счётчик становится нулём, и выполняется `deinit` экрана — в журнале появляется «Закрыт редактор». После этого экран отпускает своё свойство `photo`: у фото остаётся одна ссылка, от ленты. Поэтому фото пока в памяти.

`recentPhotos = []` убирает последнюю ссылку. Счётчик фото становится нулём, выполняется его `deinit`, и в журнале появляется «Выгружено».

**Почему «Закрыт редактор» стоит раньше, чем «Выгружено».** Объект сначала выполняет свой `deinit`, а уже потом отпускает свойства. Поэтому в `deinit` экрана можно спокойно читать `photo.fileName`: фото ещё живо.

**Почему в журнал, а не через `print`.** Журнал — это данные, их можно проверить. Проверка создаёт свои фото и экраны и смотрит, что в журнале появилось и чего нет. Так и ищут утечки в настоящих проектах: если записи об освобождении нет, объект утёк.

**Типичные ошибки:**

- в `deinit` написали круглые скобки, как у функции: `deinit()` — Swift их не принимает;
- `editor = nil` и `recentPhotos = []` поставлены рядом, до записи «Пользователь закрывает редактор» — журнал покажет неверный порядок;
- забыли очистить ленту — фото так и не выгрузится, и строки «Выгружено» в журнале не будет. Это и есть утечка.
