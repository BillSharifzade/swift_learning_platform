## @description

### Контекст
Сразу три команды жалуются на повторы. В «Ярмарке» история поиска показывает «кроссовки» три раза подряд. В «Почтальоне» у сообщения два одинаковых тега. А сервер «Монеты» иногда присылает одну и ту же операцию дважды, и её нужно поймать до того, как она попадёт в выписку.

Тимлид: «Нужна функция, которая убирает повторы из массива любого типа. Ещё одна — которая просто сообщает, есть ли повторы. И третья — для фильтров на экране: без повторов и по порядку».

### Новое в Swift
Внутри обобщённой функции с параметром `T` можно делать только то, что умеет любой тип. Но повторы так не найти: чтобы понять, что два элемента одинаковые, их нужно сравнить.

Пример: убрать товар из списка избранного.

```swift
func removing<Item>(_ item: Item, from items: [Item]) -> [Item] {
    return items.filter { $0 != item }   // ошибка!
}
```

Swift откажется собирать этот код. Вместо `Item` могут подставить любой тип, в том числе такой, который не умеет сравниваться через `!=`. Компилятор не может пообещать, что код сработает, — значит, не пропустит его.

**Ограничение** (constraint) говорит: «подставлять можно не любой тип, а только тот, который соответствует протоколу». Оно пишется через двоеточие прямо в угловых скобках:

```swift
func removing<Item: Equatable>(_ item: Item, from items: [Item]) -> [Item] {
    return items.filter { $0 != item }
}

removing("Плед", from: ["Плед", "Свеча", "Плед"])   // ["Свеча"]
removing(42, from: [7, 42, 13])                     // [7, 13]
```

Теперь Swift уверен: что бы ни подставили на место `Item`, оно умеет `==` и `!=`. А попытка передать тип без `Equatable` не соберётся уже в месте вызова.

Какое ограничение выбрать, подсказывает то, что ты делаешь с элементами. Эти протоколы ты знаешь по модулю про протоколы:

- **`Equatable`** — нужны `==` и `!=`, `contains(_:)`;
- **`Hashable`** — элемент кладётся в `Set` или служит ключом словаря;
- **`Comparable`** — нужны `<`, `>` или `sorted()`.

Если нужно несколько умений сразу, протоколы соединяют знаком `&`:

```swift
func cheapestFirst<Price: Hashable & Comparable>(_ prices: [Price]) -> [Price] { ... }
```

Пустое множество с элементами параметра типа создаётся так же, как обычное: `var seen: Set<Item> = []`.

> ⚠️ Если положить `Item` в `Set` без ограничения, Swift сообщит: type 'Item' does not conform to protocol 'Hashable'. Это значит, что не хватает `: Hashable` в угловых скобках функции.

### Задача
Объяви три обобщённые функции. Список элементов везде передаётся без метки.

1. `uniqued(_:)` — возвращает массив без повторов. Из одинаковых элементов остаётся первый, порядок сохраняется: `["кроссовки", "куртка", "кроссовки"]` → `["кроссовки", "куртка"]`. Ограничение параметра типа — `Hashable`.
2. `hasDuplicates(_:)` — возвращает `Bool`: `true`, если хотя бы один элемент встречается больше одного раза. Ограничение — `Hashable`.
3. `uniqueSorted(_:)` — возвращает массив без повторов, отсортированный по возрастанию. Ограничение — `Hashable` и `Comparable` одновременно.

Проверка вызовет функции со строками, с числами и со своими структурами.

### Пример
```swift
uniqued(["кроссовки", "куртка", "кроссовки", "шапка", "куртка"])
// ["кроссовки", "куртка", "шапка"]

hasDuplicates([1043, 1044, 1043])   // true — операция 1043 пришла дважды
hasDuplicates([1043, 1044])         // false
let noTags: [String] = []
hasDuplicates(noTags)               // false

uniqueSorted(["работа", "важное", "работа", "отпуск"])
// ["важное", "отпуск", "работа"]
```

## @solution
```swift
// 1. Убрать повторы, сохранив порядок первых появлений
func uniqued<Item: Hashable>(_ items: [Item]) -> [Item] {
    var seen: Set<Item> = []
    var result: [Item] = []
    for item in items {
        if !seen.contains(item) {
            seen.insert(item)
            result.append(item)
        }
    }
    return result
}

// 2. Есть ли в массиве повторы
func hasDuplicates<Item: Hashable>(_ items: [Item]) -> Bool {
    return Set(items).count < items.count
}

// 3. Без повторов и по возрастанию
func uniqueSorted<Item: Hashable & Comparable>(_ items: [Item]) -> [Item] {
    return Set(items).sorted()
}
```

## @hint1
Все три функции обобщённые, и у каждой в угловых скобках после имени — параметр типа с ограничением через двоеточие.

`uniqued`. Тебе нужно запоминать, какие элементы уже встречались, — для этого идеально подходит множество. Заведи пустое множество элементов и пустой массив для результата. Пройди по входному массиву циклом. Если элемента ещё нет во множестве — добавь его и во множество, и в результат. Если уже есть — пропусти. Множество отвечает на вопрос «уже было?», а массив хранит порядок. Множество требует, чтобы элементы были `Hashable`, — это и есть ограничение.

`hasDuplicates`. Подумай, что происходит с количеством элементов, если превратить массив во множество. Повторы схлопываются. Значит, если во множестве элементов меньше, чем в массиве, повторы были.

`uniqueSorted`. Здесь два умения: множество (нужен `Hashable`) и сортировка (нужен `Comparable`). Оба протокола пишутся в угловых скобках через `&`. Сама функция — одна строка: множество из массива, отсортированное по возрастанию. У множества тоже есть `sorted()`, и он возвращает массив.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Запись `<Item: Hashable>` — это обещание в обе стороны. Функция обещает компилятору, что будет получать только `Hashable`-типы, и за это может класть элементы во множество. Тот, кто вызывает, обязан передать подходящий тип: строки, числа и структуры с `Hashable` пройдут, а тип без него не соберётся уже в месте вызова.

В `uniqued` множество `seen` и массив `result` работают в паре. Множество быстро отвечает «встречался ли элемент», но порядка не хранит. Массив хранит порядок, но искать в нём медленнее. Вместе они дают то, что нужно: каждый элемент один раз, в порядке первых появлений.

`hasDuplicates` пользуется свойством множества: одинаковые элементы в нём схлопываются в один. Если после превращения в множество элементов стало меньше — значит, что-то повторялось. Для пустого массива оба количества равны нулю, и ответ `false` получается сам.

В `uniqueSorted` нужны два умения сразу, поэтому `Hashable & Comparable`. `Set(items)` убирает повторы, `sorted()` возвращает отсортированный массив. Порядок исходного массива здесь не важен, поэтому можно обойтись без `seen`.

**Почему не `Equatable` для `uniqued`.** Можно было бы проверять `result.contains(item)` — для этого хватило бы `Equatable`. Но тогда для каждого элемента пришлось бы просматривать весь результат. На списке из тысяч операций это заметно медленнее. Множество ищет почти мгновенно, а цена — более строгое ограничение `Hashable`.

**Типичные ошибки:**

- забыто ограничение — Swift сообщит, что `Item` не соответствует `Hashable`;
- в `uniqued` вернули `Array(Set(items))` — повторы ушли, но порядок стал случайным;
- в `uniqueSorted` протоколы перечислены через запятую — в угловых скобках запятая отделяет разные параметры типа, а для «оба сразу» нужен `&`.
