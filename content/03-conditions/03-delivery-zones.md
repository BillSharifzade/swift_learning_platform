## @description

### Контекст
Стоимость доставки в «Ложке» зависит от того, как далеко гость живёт от ресторана. Менеджер по логистике прислала таблицу тарифов:

- до 3 км включительно — 99 руб.;
- дальше 3 км, но не дальше 7 км — 199 руб.;
- дальше 7 км — 349 руб.

Экран оформления заказа уже показывает расстояние. Твоя задача — научить его считать стоимость доставки. Вариантов теперь не два, а три, и пары `if` / `else` уже не хватает.

### Новое в Swift
Когда вариантов больше двух, между `if` и `else` добавляют промежуточные проверки — `else if` («иначе если»). Получается цепочка:

```swift
let ordersCount = 12
var level = ""

if ordersCount >= 50 {
    level = "Гурман"
} else if ordersCount >= 10 {
    level = "Постоянный гость"
} else {
    level = "Новичок"
}

print("Ваш уровень: \(level)")
```

Swift идёт по цепочке **сверху вниз** и останавливается на **первом** истинном условии. Его блок выполняется, а всё, что ниже, пропускается — даже если там тоже есть подходящие условия. Если не подошло ни одно, срабатывает `else`.

Из этого следуют две важные вещи.

**Порядок проверок имеет значение.** У гостя с 60 заказами истинны оба условия: и `>= 50`, и `>= 10`. Он получает уровень «Гурман» только потому, что эта проверка стоит первой. Поменяй проверки местами — и «Гурманом» не станет никто.

**Повторять уже проверенное не нужно.** Если Swift дошёл до второго условия, значит, первое было ложным: заказов точно меньше 50. Писать `ordersCount >= 10 && ordersCount < 50` незачем.

Веток `else if` может быть сколько угодно. Последний `else` необязателен, но с ним не остаётся «забытых» случаев.

**Почему переменная объявлена до `if`.** Всё, что объявлено внутри фигурных скобок, существует только до закрывающей скобки. Снаружи такого имени уже нет. Поэтому `level` создана заранее, с пустым начальным значением, а в ветках ей только присваивается новый текст. После цепочки переменная на месте, и её можно вывести.

> ⚠️ Между `else` и `if` обязателен пробел. `elseif` одним словом Swift не поймёт.

### Задача
В редакторе есть расстояние до гостя `distanceKm` типа `Double`. Строка с расстоянием уже выводится. Не переименовывай данные — проверка подставит другие значения.

1. Объяви **переменную** `deliveryCost` с начальным значением `0`.
2. Цепочкой `if` / `else if` / `else` положи в неё стоимость доставки по таблице из раздела «Контекст»: `99`, `199` или `349`.
3. После цепочки выведи строку `Доставка: N руб.`, где N — значение `deliveryCost`.

Границы входят в ближнюю зону: ровно 3 км — это ещё 99 руб., ровно 7 км — ещё 199 руб.

Пороги можно писать просто как `3` и `7`. Число, написанное прямо в коде, Swift сам превратит в `Double`, чтобы сравнить его с `distanceKm`.

### Пример
Для данных из редактора (4.5 км):

```text
Расстояние: 4.5 км
Доставка: 199 руб.
```

Для гостя, который живёт в 3 км от ресторана:

```text
Расстояние: 3.0 км
Доставка: 99 руб.
```

## @solution
```swift
// Входные данные (их подменяет проверка — не переименовывай)
let distanceKm = 4.5

print("Расстояние: \(distanceKm) км")

// 1. Объяви переменную deliveryCost с начальным значением 0
var deliveryCost = 0

// 2. Положи в неё стоимость: до 3 км — 99, до 7 км — 199, дальше — 349
if distanceKm <= 3 {
    deliveryCost = 99
} else if distanceKm <= 7 {
    deliveryCost = 199
} else {
    deliveryCost = 349
}

// 3. Выведи строку со стоимостью доставки
print("Доставка: \(deliveryCost) руб.")
```

## @rules
- must: /\belse\s+if\b/ :: Зон три, поэтому здесь нужна цепочка: `if`, затем `else if` и в конце `else`.

## @hint1
Иди по шагам из комментариев.

Сначала переменная. Стоимость станет известна только после проверок, но вывести её нужно уже после них. Поэтому `deliveryCost` объявляется заранее, до условий, через `var` и с числом ноль.

Потом цепочка из трёх веток. Начни с самой ближней зоны: расстояние не больше трёх километров. Знак — «меньше или равно», потому что ровно 3 км ещё входят в эту зону. В блоке присвой переменной 99.

Вторая ветка начинается словами `else if`. Сюда Swift попадёт, только если первая проверка не прошла, то есть расстояние уже точно больше трёх. Поэтому достаточно спросить одно: не больше ли оно семи. В блоке — 199.

Третья ветка — просто `else`, без условия: это все остальные расстояния. В блоке — 349.

В конце, после последней закрывающей скобки, один `print` со вставкой `deliveryCost`.

## @hint2
Цепочка проверок выглядит так. Переменная объявлена до неё, а в ветках только меняется:

```swift
let ordersCount = 12
var level = ""

if ordersCount >= 50 {
    level = "Гурман"
} else if ordersCount >= 10 {
    level = "Постоянный гость"
} else {
    level = "Новичок"
}
```

У тебя вместо текста будут числа, а сравнения пойдут от меньшего расстояния к большему: сначала порог 3, потом порог 7.

## @hint3
Первая ветка готова. Допиши вторую и третью:

```swift
var deliveryCost = 0

if distanceKm <= 3 {
    deliveryCost = 99
} else if distanceKm ___ {
    deliveryCost = ___
} else {
    deliveryCost = ___
}

print("Доставка: \(deliveryCost) руб.")
```

В первом пропуске — сравнение с порогом средней зоны. Во втором и третьем — цены средней и дальней зон.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Для 4.5 км Swift сначала проверяет `4.5 <= 3`. Это ложно, и он переходит к следующему условию: `4.5 <= 7`. Оно истинно — в `deliveryCost` попадает `199`, а ветка `else` пропускается. Для 0.8 км истинным оказалось бы уже первое условие, и до второго Swift даже не дошёл бы. Для 12 км ложны оба, поэтому сработал бы `else`.

**Почему во второй ветке нет проверки «больше 3».** До `else if` Swift добирается, только когда первое условие ложно. Значит, расстояние уже больше трёх километров, и спрашивать об этом второй раз не нужно. Запись `distanceKm > 3 && distanceKm <= 7` тоже сработает, но она длиннее и её проще испортить при изменении тарифов.

**Почему порядок именно такой.** Если поставить проверку `distanceKm <= 7` первой, то гость, живущий в 2 км, тоже попадёт в неё — ведь 2 меньше 7 — и заплатит 199 руб. вместо 99. Правило простое: в цепочке с `<=` пороги идут от меньшего к большему.

**Почему `var` и почему до `if`.** Значение `deliveryCost` меняется — значит, это переменная. А объявлена она до цепочки, потому что имя, созданное внутри фигурных скобок, исчезает вместе с закрывающей скобкой, и `print` в конце его бы не увидел.

**Типичные ошибки:**

- `<` вместо `<=` — тогда гость ровно в 3 км от ресторана попадает в среднюю зону и переплачивает;
- `var deliveryCost = 99` внутри ветки — это новая переменная, которая живёт только внутри блока, а внешняя остаётся нулём;
- три отдельных `if` вместо цепочки — Swift проверит каждое условие, и последнее присваивание затрёт предыдущие;
- `print` поставлен внутрь последнего блока — тогда строка появится только для дальней зоны.
