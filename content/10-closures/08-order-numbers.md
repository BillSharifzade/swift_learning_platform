## @description

### Контекст
Каждый оформленный заказ на «Ярмарке» получает номер: `ЯР-1001`, `ЯР-1002` и дальше по порядку. У заказов из пунктов выдачи своя нумерация с префиксом `ПВЗ`, и она не должна сбиваться из-за обычных заказов.

Вторая просьба от маркетинга: новым покупателям доставка бесплатна на первые несколько заказов. Для каждого нового заказа приложение спрашивает: «Этому заказу доставка бесплатна?»

Тимлид предлагает: «Сделай две функции-фабрики. Каждая создаёт замыкание со своим собственным счётчиком внутри. Нужен новый счётчик — вызвал фабрику ещё раз».

### Новое в Swift
**Замыкание помнит переменные вокруг себя.** В задаче про фильтры замыкание пользовалось параметром функции `maxPrice`. Но замыкание может не только читать такие переменные, а ещё и менять их:

```swift
var likes = 0

let likeTapped = {
    likes += 1
    print("Нравится: \(likes)")
}

likeTapped()   // Нравится: 1
likeTapped()   // Нравится: 2
```

У замыкания `likeTapped` нет параметров, поэтому нет ни заголовка, ни слова `in` — только тело. Его тип — `() -> Void`: пустые скобки значат «ничего не принимает».

**Функция может вернуть замыкание.** Тип результата тогда — тип функции. Вот фабрика счётчиков просмотров карточки товара:

```swift
func makeViewCounter() -> () -> Int {
    var views = 0
    return {
        views += 1
        return views
    }
}
```

Заголовок читается так: `makeViewCounter()` ничего не принимает, а после первой стрелки стоит тип результата — `() -> Int`, «замыкание, которое ничего не принимает и возвращает `Int`».

Самое интересное начинается при вызове:

```swift
let blanketViews = makeViewCounter()
let candleViews = makeViewCounter()

print(blanketViews())   // 1
print(blanketViews())   // 2
print(candleViews())    // 1
print(blanketViews())   // 3
```

Функция `makeViewCounter` давно закончила работу, а переменная `views` продолжает жить: её держит возвращённое замыкание. Это называется **захват значений** (capturing). Замыкание захватывает переменную и работает с ней самой, а не с копией. Поэтому каждый вызов видит результат предыдущего.

И второе важное следствие. Каждый вызов `makeViewCounter()` создаёт **новую** переменную `views`. Поэтому у `blanketViews` и `candleViews` свои отдельные счётчики, и они не мешают друг другу.

Захватываются и параметры фабрики. Но параметр функции — константа, его нельзя менять. Если счёт должен начинаться с переданного числа, скопируй его в переменную:

```swift
func makeViewCounter(startingAt start: Int) -> () -> Int {
    var views = start
    return {
        views += 1
        return views
    }
}
```

> ⚠️ Если объявить счётчик снаружи функции, все замыкания будут делить одну переменную на всех. Тогда счётчики начнут сбивать друг друга.

### Задача
1. Допиши функцию `makeOrderNumberGenerator(prefix:start:)`. Параметры: `prefix` типа `String` и `start` типа `Int`. Она возвращает замыкание типа `() -> String`. Каждый вызов замыкания возвращает очередной номер заказа в виде `префикс-число`, например `ЯР-1001`. Первый вызов возвращает номер с числом `start`, каждый следующий — с числом на единицу больше.
2. Напиши функцию `makeFreeDeliveryCounter(orders:)`. Параметр `orders` типа `Int` — на сколько первых заказов доставка бесплатна. Функция возвращает замыкание типа `() -> Bool`. Каждый вызов замыкания означает новый заказ. Первые `orders` вызовов возвращают `true`, все следующие — `false`. Если `orders` равно `0`, замыкание всегда возвращает `false`.

У каждого созданного замыкания должен быть свой счётчик: вызовы одного не должны влиять на другое.

### Пример
```swift
let nextOrderNumber = makeOrderNumberGenerator(prefix: "ЯР", start: 1001)
let nextPickupNumber = makeOrderNumberGenerator(prefix: "ПВЗ", start: 1)

nextOrderNumber()    // "ЯР-1001"
nextOrderNumber()    // "ЯР-1002"
nextPickupNumber()   // "ПВЗ-1"
nextOrderNumber()    // "ЯР-1003"

let isDeliveryFree = makeFreeDeliveryCounter(orders: 2)
isDeliveryFree()     // true
isDeliveryFree()     // true
isDeliveryFree()     // false
```

## @solution
```swift
// 1. Генератор номеров заказов: "ЯР-1001", "ЯР-1002", ...
func makeOrderNumberGenerator(prefix: String, start: Int) -> () -> String {
    // Заведи переменную-счётчик и верни замыкание,
    // которое отдаёт очередной номер и увеличивает счётчик
    var nextNumber = start
    return {
        let orderNumber = "\(prefix)-\(nextNumber)"
        nextNumber += 1
        return orderNumber
    }
}

// 2. Бесплатная доставка на первые несколько заказов
// Напиши функцию makeFreeDeliveryCounter(orders:), которая возвращает () -> Bool
func makeFreeDeliveryCounter(orders: Int) -> () -> Bool {
    var freeOrdersLeft = orders
    return {
        if freeOrdersLeft > 0 {
            freeOrdersLeft -= 1
            return true
        }
        return false
    }
}
```

## @hint1
Обе функции устроены одинаково. В начале тела заведи переменную-счётчик через `var`. Потом верни замыкание: оно пишется сразу после `return`, в фигурных скобках, без параметров и без слова `in`.

В `makeOrderNumberGenerator` счётчик — число, с которого начинается нумерация. Скопируй в него `start`: сам параметр менять нельзя. В замыкании сначала собери строку номера интерполяцией: префикс, дефис, текущее число. Сохрани её в константу. Потом увеличь счётчик на единицу и верни сохранённую строку. Порядок важен: если увеличить счётчик раньше, первый номер окажется на единицу больше.

`makeFreeDeliveryCounter` пишется полностью: имя, параметр `orders` типа `Int`, а после стрелки тип результата — замыкание, которое ничего не принимает и возвращает `Bool`. Счётчик здесь — сколько бесплатных заказов осталось. В замыкании проверь через `if`, больше ли он нуля. Если да — уменьши его и верни `true`. Иначе верни `false`.

## @hint4
Вот готовое решение:

{{solution}}

**Как работает генератор номеров.** При вызове `makeOrderNumberGenerator` создаётся переменная `nextNumber` со значением `start`. Возвращённое замыкание захватывает её вместе с параметром `prefix`. Функция заканчивает работу, но `nextNumber` не исчезает: её держит замыкание. При каждом вызове замыкание собирает номер из текущего значения и только потом увеличивает счётчик. Поэтому первым приходит `ЯР-1001`, а не `ЯР-1002`.

**Почему генераторы не мешают друг другу.** Переменная `nextNumber` объявлена внутри функции. Каждый вызов функции создаёт новую переменную, и каждое замыкание держит свою. Если бы счётчик был объявлен снаружи, оба генератора увеличивали бы одно и то же число, и после `ЯР-1001` появился бы `ПВЗ-1002`.

**Как работает бесплатная доставка.** `freeOrdersLeft` — сколько бесплатных заказов осталось. Пока он больше нуля, замыкание тратит одну доставку и отвечает `true`. Когда дошли до нуля, ветка `if` больше не выполняется, и ответ всегда `false`. Для `orders: 0` условие ложно с самого начала. Счётчик никогда не уходит в минус, потому что уменьшается только внутри `if`.

**Почему копия параметра.** Параметры функции — константы. Строка `start += 1` внутри замыкания не скомпилируется. Поэтому значение копируется в `var`, и меняется уже копия.

**Типичные ошибки:**

- счётчик увеличивается до того, как собран номер, — нумерация начинается со `start + 1`;
- переменная-счётчик объявлена вне функции — все генераторы делят её между собой;
- в `makeFreeDeliveryCounter` написано `freeOrdersLeft >= 0` — тогда бесплатных заказов окажется на один больше;
- счётчик объявлен внутри замыкания, а не в функции — тогда он создаётся заново при каждом вызове, и номер всегда один и тот же.
