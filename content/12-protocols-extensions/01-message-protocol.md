## @description

### Контекст
В «Почтальоне» уже есть три вида сообщений: текст, фото и голосовое. Каждый описан своей структурой, и данные у них разные: у текста — сам текст, у фото — подпись, у голосового — длительность в секундах.

Экран со списком чатов хочет от любого сообщения всего две вещи: кто его отправил и короткую строку для превью — ту, что видна под названием чата. Тимлид предлагает записать эту договорённость в коде: «Пусть будет протокол `Message`. Каждый вид сообщения подпишется под ним — и экран сможет на это опираться».

### Новое в Swift
**Протокол** — это список требований к типу. Он говорит: «тот, кто подписан на меня, обязательно умеет вот это». Сам протокол ничего не хранит и ничего не делает. Он только описывает, что должно быть. Похоже на должностную инструкцию: в ней написано, что сотрудник умеет, но не написано, кто он.

Вот протокол для значков в профиле:

```swift
protocol ProfileBadge {
    var title: String { get }
    func badgeText() -> String
}
```

В фигурных скобках — два требования.

- **Требование свойства.** `var title: String { get }` значит: у типа есть свойство `title` типа `String`, и его можно прочитать. Слово `var` здесь пишется всегда, но выполнить требование можно и через `let`, и через `var`, и через вычисляемое свойство. Если написать `{ get set }`, свойство обязано ещё и меняться — тогда `let` уже не подойдёт.
- **Требование метода.** `func badgeText() -> String` — только первая строка метода, **без тела** в фигурных скобках. Как именно метод работает, решает каждый тип сам.

Чтобы тип **соответствовал** протоколу (говорят ещё «подписан на протокол»), имя протокола пишут через двоеточие после имени типа и выполняют все требования:

```swift
struct VerifiedBadge: ProfileBadge {
    let title: String

    func badgeText() -> String {
        return "Подтверждён: \(title)"
    }
}

struct SupportBadge: ProfileBadge {
    let title: String
    let replyMinutes: Int

    func badgeText() -> String {
        return "\(title), отвечает за \(replyMinutes) мин."
    }
}
```

У `SupportBadge` есть лишнее свойство `replyMinutes` — это нормально. Протокол задаёт минимум, а не полный список.

Ты уже встречала такую запись: `enum Tariff: CaseIterable` в такси «Ветер». `CaseIterable` — протокол из стандартной библиотеки Swift, просто его требование Swift выполнял за тебя.

> ⚠️ Если тип объявлен с протоколом, но какого-то требования не хватает, Swift не соберёт код: тип «не соответствует протоколу». Это защита: подписался — выполняй.

### Задача
В редакторе три структуры: `TextMessage`, `PhotoMessage` и `VoiceMessage`.

1. Объяви протокол `Message` с двумя требованиями:
   - свойство `sender` типа `String`, только для чтения: `{ get }`;
   - метод `preview()` без параметров, который возвращает `String`.
2. Подпиши все три структуры под протокол `Message`. Свойство `sender` у них уже есть — оно и выполняет первое требование.
3. Допиши каждой структуре метод `preview()`:
   - `TextMessage` возвращает свой `text` без изменений;
   - `PhotoMessage` возвращает `Фото: ` и подпись, а если подпись `caption` пустая — просто `Фото`;
   - `VoiceMessage` возвращает `Голосовое сообщение, `, число секунд и ` сек.`

Проверка подпишет на твой протокол и свой тип сообщения — значит, требования должны быть ровно такими, как в условии.

### Пример
Сценарий внизу редактора должен вывести:

```text
Билол: Купишь хлеб по дороге?
Мама: Фото: Пирог с яблоками
Сестра: Голосовое сообщение, 42 сек.
```

А фото без подписи в превью выглядит так: `PhotoMessage(sender: "Мама", caption: "").preview()` даёт `Фото`.

## @solution
```swift
// Виды сообщений в мессенджере "Почтальон".
// Экрану чатов от любого сообщения нужно одно и то же:
// кто отправил (sender) и короткий текст для списка (preview).

// 1. Объяви протокол Message: свойство sender и метод preview()
protocol Message {
    var sender: String { get }
    func preview() -> String
}

// 2. Подпиши структуры под Message и 3. допиши каждой метод preview()
struct TextMessage: Message {
    let sender: String
    let text: String

    func preview() -> String {
        return text
    }
}

struct PhotoMessage: Message {
    let sender: String
    let caption: String

    func preview() -> String {
        return caption.isEmpty ? "Фото" : "Фото: \(caption)"
    }
}

struct VoiceMessage: Message {
    let sender: String
    let seconds: Int

    func preview() -> String {
        return "Голосовое сообщение, \(seconds) сек."
    }
}

// Сообщения из семейного чата
let hello = TextMessage(sender: "Билол", text: "Купишь хлеб по дороге?")
let photo = PhotoMessage(sender: "Мама", caption: "Пирог с яблоками")
let voice = VoiceMessage(sender: "Сестра", seconds: 42)

print("\(hello.sender): \(hello.preview())")
print("\(photo.sender): \(photo.preview())")
print("\(voice.sender): \(voice.preview())")
```

## @rules
- must: /\bprotocol\s+Message\b/ :: Объяви протокол: `protocol Message { ... }`.
- must: /\bvar\s+sender\s*:\s*String\s*\{\s*get\s*\}/ :: В протоколе требование свойства записывается так: `var sender: String { get }`.

## @hint1
Начни с протокола. Он объявляется словом `protocol`, после него имя и фигурные скобки. Внутри — два требования, каждое на своей строке.

Первое — свойство. Пишется словом `var`, затем имя, двоеточие и тип, а в конце в фигурных скобках слово `get`: свойство должно читаться.

Второе — метод. Это первая строка обычного метода: слово `func`, имя, пустые круглые скобки, стрелка и тип результата. Тела в фигурных скобках у требования нет.

Потом подпиши структуры: после имени каждой поставь двоеточие и имя протокола. Свойство `sender` у них уже есть, а вот метода `preview()` нет — его нужно написать в каждой, уже с телом.

У текстового сообщения метод просто возвращает свойство `text`. У фото — выбор из двух вариантов в зависимости от того, пустая ли подпись: тут пригодится `isEmpty` и тернарный оператор или `if`. У голосового — строка с интерполяцией свойства `seconds`.

## @hint2
Протокол и тип, который на него подписан, выглядят так:

```swift
protocol ProfileBadge {
    var title: String { get }
    func badgeText() -> String
}

struct VerifiedBadge: ProfileBadge {
    let title: String

    func badgeText() -> String {
        return "Подтверждён: \(title)"
    }
}
```

У твоего протокола другое имя и другие требования: свойство `sender` и метод `preview()`.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Протокол `Message` — это договор из двух пунктов: «у тебя есть `sender`, который можно прочитать» и «ты умеешь отдавать `preview()`». Запись `struct TextMessage: Message` — подпись под договором. Swift сразу проверяет, все ли пункты выполнены. Свойство `let sender` подходит под требование `var sender: String { get }`: читать его можно, а большего протокол и не просит. Метод `preview()` каждый тип пишет по-своему, и именно в этом смысл: требование одно, а поведение разное.

**Почему в протоколе `var`, хотя в структурах `let`.** Требования свойств в протоколе всегда пишутся через `var`. Что именно можно делать со свойством, говорит часть в фигурных скобках: `{ get }` — читать. Выполнить такое требование можно чем угодно, что читается: `let`, `var` или вычисляемым свойством.

**Зачем это экрану.** Пока протокол только описан, польза кажется небольшой. Но теперь у трёх разных структур есть общее «лицо». В следующей задаче ты сложишь их в один массив и будешь работать с ними, не разбираясь, где фото, а где текст.

**Типичные ошибки:**

- у требования метода написано тело в фигурных скобках — в протоколе тела у методов не бывает, Swift сообщит об ошибке;
- забыто `{ get }` после типа свойства — Swift требует явно сказать, читается свойство или ещё и меняется;
- `{ get set }` вместо `{ get }` — тогда `let sender` в структурах уже не подходит под требование;
- метод `preview()` написан, но двоеточие с именем протокола после имени структуры забыто — метод есть, а подписи под договором нет.
