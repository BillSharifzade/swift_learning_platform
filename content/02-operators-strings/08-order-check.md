## @description

### Контекст
Финальная задача спринта. Перед тем как заказ уйдёт на склад, приложение должно его проверить. Со склада жалуются: приходят заказы с чужими артикулами и с почтой, на которую невозможно отправить чек.

Тимлид собрала требования в один тикет:

- артикулы «Гардероба» всегда начинаются с `GRD-`;
- в почте должен быть символ `@` и не должно быть пробелов;
- у сотрудников магазина почта заканчивается на `@garderob.ru` — их заказы склад собирает отдельно;
- промокод считается активным, если совпадает с действующим, как бы его ни набрали — большими буквами или маленькими;
- заказ на ноль рублей — признак ошибки, такой отправлять нельзя.

«Ты уже умеешь почти всё, что для этого нужно, — пишет она. — Не хватает только пары инструментов для строк».

### Новое в Swift
**Вопросы к строке.** У строки есть три метода, которые отвечают `true` или `false`. В скобках пишут текст, который нужно искать:

- `hasPrefix(...)` — **начинается** ли строка с этого текста;
- `hasSuffix(...)` — **заканчивается** ли строка этим текстом;
- `contains(...)` — встречается ли этот текст **где-нибудь** в строке.

```swift
let phone = "+79161234567"
print(phone.hasPrefix("+7"))           // true: номер российский

let photoName = "otzyv-platie.png"
print(photoName.hasSuffix(".png"))     // true: это картинка PNG

let address = "Казань, ул. Садовая, 12"
print(address.contains("Казань"))      // true
print(address.contains("Москва"))      // false
```

**Сравнение строк.** Операторы `==` и `!=` работают и со строками. Строки равны, только если совпадают все символы до единого:

```swift
let selectedSize = "M"
print(selectedSize == "M")     // true
print(selectedSize == "m")     // false
print(selectedSize != "L")     // true
```

Большая и маленькая буква для Swift — разные символы. Это касается и сравнения, и всех трёх методов: `"Казань"` и `"казань"` — не одно и то же. Поэтому текст, который ввёл человек, сначала приводят к единому виду через `lowercased()` или `uppercased()` и только потом проверяют:

```swift
let sizeInput = "m"
print(sizeInput.uppercased() == "M")   // true
```

> 💡 Строки можно сравнивать и через `<` и `>` — тогда они сравниваются по алфавиту: `"Казань" < "Москва"` даёт `true`. Это пригодится позже, когда дойдём до сортировки списков.

Символ `@` набирается как Shift + 2 в английской раскладке.

### Что пригодится
Из прошлых задач модуля понадобятся:

- умножение — для суммы заказа;
- сравнение `>` — сумма должна быть больше нуля;
- `&&` и `!` — чтобы соединить несколько условий и записать «нет пробелов»;
- `lowercased()` и `uppercased()` — чтобы привести почту и промокод к единому виду.

### Задача
В редакторе есть данные заказа: `sku` — артикул товара, `emailInput` — почта в том виде, как её ввели, `promoInput` — введённый промокод, `activePromo` — промокод, который действует сейчас (сервер присылает его заглавными буквами), `price` — цена одной вещи, `quantity` — количество. Не переименовывай их — проверка подставит другие значения.

1. Объяви константу `isSkuValid`: `true`, если артикул начинается с `GRD-`.
2. Объяви константу `email` — почту строчными буквами. Все проверки почты делай с ней.
3. Объяви константу `isEmailValid`: `true`, если в `email` есть символ `@` **и нет** пробела.
4. Объяви константу `isStaff`: `true`, если `email` заканчивается на `@garderob.ru`.
5. Объяви константу `isPromoActive`: `true`, если введённый промокод, приведённый к заглавным буквам, равен `activePromo`.
6. Объяви константу `total` — сумму заказа: цена, умноженная на количество.
7. Объяви константу `canSend`: `true`, если артикул верный, **и** почта верная, **и** сумма заказа больше нуля.
8. Заголовок сводки уже выводится. Допиши после него шесть строк, как в примере.

## @solution
```swift
// Входные данные (их подменяет проверка — не переименовывай)
let sku = "GRD-48213"
let emailInput = "Bilol.Style@Mail.Ru"
let promoInput = "vesna25"
let activePromo = "VESNA25"
let price = 2490
let quantity = 2

// 1. Артикул верный, если начинается с "GRD-"
let isSkuValid = sku.hasPrefix("GRD-")

// 2. Почта строчными буквами
let email = emailInput.lowercased()

// 3. Почта верная, если в ней есть "@" и нет пробела
let isEmailValid = email.contains("@") && !email.contains(" ")

// 4. Сотрудник магазина: почта заканчивается на "@garderob.ru"
let isStaff = email.hasSuffix("@garderob.ru")

// 5. Промокод активен: введённый код заглавными буквами равен activePromo
let isPromoActive = promoInput.uppercased() == activePromo

// 6. Сумма заказа: цена, умноженная на количество
let total = price * quantity

// 7. Заказ можно отправить: артикул верный, почта верная, сумма больше нуля
let canSend = isSkuValid && isEmailValid && total > 0

// 8. Сводка: допиши шесть строк после заголовка
print("=== Проверка заказа ===")
print("Артикул \(sku): \(isSkuValid)")
print("Почта \(email): \(isEmailValid)")
print("Сотрудник магазина: \(isStaff)")
print("Промокод активен: \(isPromoActive)")
print("Сумма заказа: \(total) руб.")
print("Можно отправить на склад: \(canSend)")
```

## @hint1
Иди по комментариям в редакторе: каждый шаг — одна константа, одна строка кода.

Артикул. У `sku` через точку вызови метод, который проверяет начало строки. В скобках — текст `GRD-` в кавычках.

Почта. Сначала приведи `emailInput` к строчным буквам и положи результат в `email`. Дальше работай только с `email`.

Верная ли почта. Это два вопроса, соединённые оператором «и». Первый: содержит ли `email` символ `@`. Второй: содержит ли `email` пробел — и тут нужен ответ «нет», поэтому перед вторым вопросом ставится восклицательный знак. Пробел в кавычках — это строка из одного символа.

Сотрудник. Метод, который проверяет конец строки, а в скобках — `@garderob.ru` в кавычках.

Промокод. Приведи `promoInput` к заглавным буквам и сравни результат с `activePromo` двумя знаками равенства.

Сумма — умножение цены на количество.

Можно ли отправить. Три условия через «и»: `isSkuValid`, `isEmailValid` и сравнение `total` с нулём — сумма должна быть строго больше.

Вывод. Шесть команд `print` после заголовка. В строках про артикул и почту по две вставки: сначала само значение, потом результат проверки.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** `sku.hasPrefix("GRD-")` проверяет первые четыре символа артикула. `emailInput.lowercased()` даёт почту строчными буквами: `bilol.style@mail.ru`. Проверка почты состоит из двух частей: `email.contains("@")` — «собачка есть», `!email.contains(" ")` — «пробела нет»; оператор `&&` требует, чтобы выполнялось и то и другое. `email.hasSuffix("@garderob.ru")` смотрит на конец строки. Промокод сначала становится заглавным, а потом сравнивается: `"VESNA25" == "VESNA25"` — это `true`. Сумма — обычное умножение. Последняя константа соединяет три условия в один ответ.

**Почему сначала `lowercased()`, а потом проверки.** Для Swift `Garderob.RU` и `garderob.ru` — разные тексты. Если проверять почту в том виде, как её набрали, сотрудница с адресом `Sklad.Lead@Garderob.RU` не будет распознана. Привести к единому виду один раз и дальше работать с чистым значением — надёжный приём. С промокодом то же самое: без `uppercased()` код `vesna25` не совпал бы с `VESNA25`.

**Почему `hasPrefix` и `hasSuffix`, а не `contains`.** `contains` находит текст в любом месте. Артикул `ZR-GRD-551` содержит `GRD-`, но начинается не с него — это чужой товар. Почта `sale@garderob.ru.com` содержит `@garderob.ru`, но заканчивается иначе — это не сотрудница. Когда важно место, нужен точный вопрос.

**Почему в `canSend` нет `isStaff` и `isPromoActive`.** Заказ без промокода и заказ обычной покупательницы — нормальные заказы. Эти два значения нужны складу и кассе, но на возможность отправки не влияют. Читать требования внимательно и не добавлять лишних условий — тоже часть работы.

**Типичные ошибки:**

- проверки сделаны с `emailInput`, а не с `email` — почта с заглавными буквами проверится неверно;
- забыт `!` перед `email.contains(" ")` — тогда верной будет считаться только почта с пробелом;
- один знак `=` вместо `==` при сравнении промокода;
- `hasprefix` или `HasPrefix` — в названиях методов важен регистр: `hasPrefix`, `hasSuffix`;
- `total >= 0` вместо `total > 0` — заказ на ноль рублей пройдёт проверку.
