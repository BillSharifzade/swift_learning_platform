## @description

### Контекст
За некоторые переводы «Копилка» берёт комиссию, и правила у неё разные. Между своими счетами перевод бесплатный. На карту другого банка — 1% от суммы, но не меньше 30 руб. Скоро появятся новые способы: экспресс-перевод, перевод за границу.

Тимлид объясняет задумку: «Пусть каждое правило комиссии будет отдельной маленькой функцией. А функция итога получает правило как аргумент и просто применяет его. Появится новый способ — допишем ещё одно правило, а расчёт итога трогать не придётся».

### Новое в Swift
До сих пор ты передавала в функции числа, строки и массивы. Но функция в Swift — тоже **значение**. Её можно положить в переменную и передать в другую функцию.

**Тип функции.** У каждого значения есть тип, и у функции тоже. Он записывается так: в скобках типы параметров, потом стрелка и тип результата. Вот два правила начисления бонусных баллов:

```swift
func standardPoints(_ amount: Int) -> Int {
    return amount / 100
}

func premiumPoints(_ amount: Int) -> Int {
    return amount / 50
}
```

Обе функции принимают `Int` и возвращают `Int`. Их тип — `(Int) -> Int`. Раз тип одинаковый, одну можно поставить на место другой.

**Функция в переменной.** Имя функции **без скобок** — это сама функция, как значение. Имя **со скобками** — её вызов:

```swift
var pointsRule: (Int) -> Int = standardPoints
print(pointsRule(2000))   // 20

pointsRule = premiumPoints
print(pointsRule(2000))   // 40
```

Переменная `pointsRule` хранит правило и вызывается как обычная функция. Строка `pointsRule(2000)` одна и та же, а результат зависит от того, какое правило сейчас лежит в переменной.

**Функция как аргумент.** Параметр тоже может иметь тип функции:

```swift
func pointsText(for amount: Int, rule: (Int) -> Int) -> String {
    return "Начислим баллов: \(rule(amount))"
}

print(pointsText(for: 2000, rule: standardPoints))   // Начислим баллов: 20
print(pointsText(for: 2000, rule: premiumPoints))    // Начислим баллов: 40
```

Внутри `pointsText` параметр `rule` вызывается как обычная функция: `rule(amount)`. Какое именно правило ей передали, `pointsText` не знает — и в этом вся польза. Она сработает с любым правилом типа `(Int) -> Int`, даже с тем, которое напишут через год.

> ⚠️ При передаче функции скобки после имени не ставятся: `rule: standardPoints`. Запись `standardPoints()` — это попытка вызвать функцию прямо сейчас.

### Задача
В редакторе есть сумма перевода — `transferAmount`.

1. Объяви функцию `noFee` — правило для перевода между своими счетами. Один параметр `amount` типа `Int`, при вызове без метки. Возвращает `Int`: всегда `0`.
2. Объяви функцию `cardFee` — правило для перевода на карту другого банка. Параметр такой же. Возвращает `Int`: 1% от суммы (`amount / 100`), но не меньше `30`.
3. Объяви функцию `totalWithFee`, которая возвращает `Int`. Параметры:
   - `amount` типа `Int`, при вызове без метки, — сумма перевода;
   - `fee` типа `(Int) -> Int` — правило комиссии.

   Результат — сумма перевода плюс комиссия, посчитанная переданным правилом.
4. Выведи две строки, как в примере. Итог считай вызовами `totalWithFee` для `transferAmount`: сначала с правилом `noFee`, потом с `cardFee`.

### Пример
Вывод программы:

```text
Между своими счетами: 10000 руб.
На карту другого банка: 10100 руб.
```

Проверка вызовет функции и с другими данными, в том числе передаст в `totalWithFee` своё правило:

```swift
cardFee(2900)                       // 30 — сработал минимум
totalWithFee(1000, fee: cardFee)    // 1030
totalWithFee(1000, fee: expressFee) // 1099, если expressFee всегда возвращает 99
```

## @solution
```swift
// Сумма перевода (в рублях)
let transferAmount = 10000

// 1. Правило для перевода между своими счетами: комиссии нет
func noFee(_ amount: Int) -> Int {
    return 0
}

// 2. Правило для перевода на карту другого банка: 1%, но не меньше 30 руб.
func cardFee(_ amount: Int) -> Int {
    let onePercent = amount / 100
    if onePercent < 30 {
        return 30
    }
    return onePercent
}

// 3. Итог перевода: сумма плюс комиссия по переданному правилу
func totalWithFee(_ amount: Int, fee: (Int) -> Int) -> Int {
    return amount + fee(amount)
}

// 4. Выведи итог для обоих правил
print("Между своими счетами: \(totalWithFee(transferAmount, fee: noFee)) руб.")
print("На карту другого банка: \(totalWithFee(transferAmount, fee: cardFee)) руб.")
```

## @rules
- must: /totalWithFee\s*\(\s*transferAmount\s*,\s*fee\s*:\s*noFee\s*\)/ :: Итог для первой строки посчитай вызовом `totalWithFee(transferAmount, fee: noFee)` — имя правила передаётся без скобок.
- must: /totalWithFee\s*\(\s*transferAmount\s*,\s*fee\s*:\s*cardFee\s*\)/ :: Итог для второй строки посчитай вызовом `totalWithFee(transferAmount, fee: cardFee)` — имя правила передаётся без скобок.

## @hint1
Здесь три небольшие функции. Первые две — правила комиссии, и они очень похожи на то, что ты уже писала: получают сумму без метки и возвращают целое число.

`noFee` совсем короткая: какой бы ни была сумма, она возвращает ноль. Параметр в теле не используется — и это нормально. Он нужен, чтобы у всех правил был одинаковый тип.

В `cardFee` сначала посчитай один процент от суммы и сохрани в константу. Потом сравни с минимумом: если получилось меньше тридцати, верни тридцать, иначе — посчитанное значение.

Третья функция, `totalWithFee`, — главная. Её второй параметр называется `fee`, а его тип — не число, а функция: в круглых скобках `Int`, потом стрелка и снова `Int`. В теле вызови `fee` как обычную функцию, передав ей сумму. Получится комиссия. Прибавь её к сумме и верни результат. Ни `noFee`, ни `cardFee` внутри `totalWithFee` упоминать не нужно.

При выводе в `totalWithFee` передаются два аргумента: сумма и имя правила. Имя правила пишется без скобок — ты передаёшь саму функцию, а не результат её вызова.

## @hint2
Параметр с типом функции объявляется и используется так:

```swift
func pointsText(for amount: Int, rule: (Int) -> Int) -> String {
    return "Начислим баллов: \(rule(amount))"
}

print(pointsText(for: 2000, rule: standardPoints))
```

В объявлении тип параметра `rule` — `(Int) -> Int`. В теле `rule(amount)` — вызов переданной функции. При вызове `pointsText` правило передаётся по имени, без скобок.

Твоя `totalWithFee` устроена так же, только возвращает число: сумму плюс то, что посчитало правило.

## @hint3
Правило `noFee` и вывод готовы. Допиши три пропуска:

```swift
func noFee(_ amount: Int) -> Int {
    return 0
}

func cardFee(_ amount: Int) -> Int {
    let onePercent = amount / 100
    if onePercent < 30 {
        return ___
    }
    return onePercent
}

func totalWithFee(_ amount: Int, fee: ___) -> Int {
    return amount + ___
}

print("Между своими счетами: \(totalWithFee(transferAmount, fee: noFee)) руб.")
print("На карту другого банка: \(totalWithFee(transferAmount, fee: cardFee)) руб.")
```

В первом пропуске — минимальная комиссия. Во втором — тип функции, которая принимает `Int` и возвращает `Int`. В третьем — вызов правила `fee` для суммы `amount`.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** `noFee` и `cardFee` — два правила с одинаковым типом `(Int) -> Int`: каждое получает сумму и возвращает комиссию. Функция `totalWithFee` объявляет параметр `fee` именно такого типа. В её теле `fee(amount)` вызывает то правило, которое передали, а результат прибавляется к сумме.

При вызове `totalWithFee(transferAmount, fee: noFee)` в параметр `fee` попадает функция `noFee`. Внутри выполняется `10000 + noFee(10000)`, то есть `10000 + 0`. При вызове с `cardFee` та же самая строка кода считает `10000 + cardFee(10000)`, то есть `10000 + 100`.

**Почему так, а не через `if` или `switch`.** Можно было передавать в `totalWithFee` строку с названием способа и разбирать её внутри. Но тогда с каждым новым способом перевода эту функцию пришлось бы открывать и менять — и каждый раз рисковать сломать старые правила. Сейчас `totalWithFee` не знает ни об одном конкретном правиле. Новый способ — это просто ещё одна маленькая функция. Проверка так и делает: передаёт правила, которых в твоём коде нет, и `totalWithFee` с ними справляется.

**Зачем `noFee` параметр, который не используется.** Чтобы её тип совпадал с типом остальных правил. `totalWithFee` вызывает любое правило одинаково — `fee(amount)`, — поэтому каждое обязано принимать сумму, даже если она ему не нужна.

**Типичные ошибки:**

- скобки при передаче функции: `fee: noFee()` — это вызов, а не сама функция, и Swift попросит недостающий аргумент;
- внутри `totalWithFee` написано `cardFee(amount)` вместо `fee(amount)` — тогда переданное правило игнорируется;
- в типе параметра забыты скобки вокруг `Int`: правильно `(Int) -> Int`;
- в `cardFee` перепутано сравнение: `if onePercent > 30 { return 30 }` превращает минимум в максимум.
