## @description

### Контекст
Следующий экран — лента. Рядом с каждым постом показывается автор. Дизайнер описала правило в макете: «Если у человека есть ник — показываем ник. Если ника нет — имя. Если нет и имени (аккаунт удалён или данные не пришли) — пишем слово Гость. Пустого места рядом с постом быть не должно».

Тимлид добавляет ещё одну мелочь: в настройках можно выбрать, сколько постов загружать за раз. Если человек ничего не выбирал, настройка равна `nil`, и нужно взять 20.

Обе задачи об одном: «возьми значение, а если его нет — возьми запасное».

### Новое в Swift
Через `if let` это записывается в пять строк: проверка, две ветки, два результата. Но ситуация «значение или запасной вариант» встречается так часто, что для неё есть отдельный оператор — два вопросительных знака `??`:

```swift
let status: String? = nil
let text = status ?? "Нет статуса"
```

Читается так: «возьми то, что лежит в `status`, а если там пусто — возьми то, что справа». В `text` окажется `Нет статуса`. А если бы в `status` лежало `"На связи"`, в `text` попало бы оно.

Главное: результат `??` — уже **обычное значение**, не коробочка. У `text` тип `String`, и разворачивать его не нужно.

**Типы должны совпадать.** Справа от `??` стоит значение того же типа, что и внутри коробочки. Для `Int?` запасное значение — число:

```swift
let savedFontSize: Int? = nil
let fontSize = savedFontSize ?? 16      // 16, тип Int
```

**Цепочка.** Запасной вариант сам может быть опционалом. Тогда после него ставят ещё один `??`:

```swift
let workPhone: String? = nil
let homePhone: String? = "555-01-02"
let contact = workPhone ?? homePhone ?? "Телефон не указан"
```

Swift идёт слева направо и берёт первое непустое значение. Здесь это `homePhone`. Последним в цепочке стоит обычное значение — оно сработает, если пусты все коробочки.

**Внутри текста.** `??` можно писать прямо во вставке `\( )`, вместе с кавычками запасного текста:

```swift
print("Статус: \(status ?? "не задан")")
```

> 💡 `??` — самый короткий способ развернуть опционал. Он подходит, когда для случая `nil` есть разумное значение по умолчанию. Если же нужно выполнить разные действия — остаётся `if let`.

### Задача
1. Допиши функцию `displayName(nickname:firstName:)`. Оба параметра — `String?`. Она возвращает `String`: ник, если он есть; иначе имя; а если нет ни того, ни другого — слово `Гость`.
2. Напиши функцию `postsPerPage(_:)`. У неё один параметр типа `Int?` без метки. Она возвращает `Int`: переданное число, а если передан `nil` — число `20`.
3. Напиши функцию `authorLine(nickname:firstName:city:)`. Все три параметра — `String?`. Она возвращает подпись под постом: отображаемое имя, пробел и город в круглых скобках, например `sunny_bilol (Казань)`. Если города нет, в скобках пишется `город не указан`. Имя получай вызовом `displayName`.
4. Во всех трёх функциях используй `??`. Слово `if` в этой задаче не понадобится.

### Пример
```swift
displayName(nickname: "sunny_bilol", firstName: "Билол")  // "sunny_bilol"
displayName(nickname: nil, firstName: "Билол")            // "Билол"
displayName(nickname: nil, firstName: nil)                // "Гость"

postsPerPage(50)     // 50
postsPerPage(nil)    // 20

authorLine(nickname: "sunny_bilol", firstName: "Билол", city: "Казань")  // "sunny_bilol (Казань)"
authorLine(nickname: nil, firstName: nil, city: nil)                     // "Гость (город не указан)"
```

## @solution
```swift
// Имя автора рядом с постом: ник, если его нет — имя, если нет и имени — "Гость"
func displayName(nickname: String?, firstName: String?) -> String {
    return nickname ?? firstName ?? "Гость"
}

// Сколько постов загружать за раз: настройка пользователя или 20.
func postsPerPage(_ setting: Int?) -> Int {
    return setting ?? 20
}

// Подпись под постом: отображаемое имя и город в скобках.
func authorLine(nickname: String?, firstName: String?, city: String?) -> String {
    let name = displayName(nickname: nickname, firstName: firstName)
    return "\(name) (\(city ?? "город не указан"))"
}
```

## @rules
- must: /\?\?/ :: Используй оператор `??` — он подставляет запасное значение вместо `nil`.
- mustnot: /\bif\b/ :: Эта задача решается без `if`: везде, где нужно запасное значение, хватит оператора `??`.

## @hint1
Во всех трёх функциях одна и та же мысль: «возьми значение, а если его нет — возьми запасное». Для этого и нужен оператор из двух вопросительных знаков.

В `displayName` запасных вариантов два, поэтому получится цепочка. Сначала идёт самое желанное значение — ник. За ним через `??` — то, что берём, если ника нет. И в самом конце, ещё через один `??`, — обычная строка со словом «Гость». Всё это одно выражение, его и нужно вернуть вместо заглушки.

`postsPerPage` ещё проще: параметр, оператор и число по умолчанию. Обрати внимание на типы: в коробочке лежит `Int`, значит, и запасное значение — число без кавычек.

В `authorLine` сначала получи имя: вызови `displayName` и передай ей ник и имя, которые пришли в параметрах. Потом собери строку через интерполяцию: имя, пробел, открывающая скобка, город или запасной текст, закрывающая скобка. Запасной текст для города можно подставить прямо внутри вставки.

## @hint2
Цепочка из двух запасных вариантов и `??` внутри строки выглядят так:

```swift
let workPhone: String? = nil
let homePhone: String? = "555-01-02"
let contact = workPhone ?? homePhone ?? "Телефон не указан"

let status: String? = nil
print("Статус: \(status ?? "не задан")")
```

В `displayName` цепочка такая же: два опционала и обычная строка в конце. В `authorLine` запасной текст для города стоит внутри вставки, как у `status`.

## @hint3
Первая функция готова, в двух других остались пропуски:

```swift
func displayName(nickname: String?, firstName: String?) -> String {
    return nickname ?? firstName ?? "Гость"
}

func postsPerPage(_ setting: Int?) -> Int {
    return setting ?? ___
}

func authorLine(nickname: String?, firstName: String?, city: String?) -> String {
    let name = displayName(nickname: ___, firstName: ___)
    return "\(name) (\(city ?? ___))"
}
```

В первом пропуске — число постов по умолчанию. Во втором и третьем — параметры, которые нужно передать дальше. В последнем — текст в кавычках для случая, когда города нет.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** В `displayName` выражение `nickname ?? firstName ?? "Гость"` читается слева направо. Есть ник — берём его, и дальше Swift даже не смотрит. Ника нет — проверяем имя. Нет и имени — остаётся строка `"Гость"`. Она обычная, не опционал, поэтому и весь результат — обычный `String`. В `postsPerPage` то же самое, только короче и с числами. В `authorLine` имя уже готово после вызова `displayName`, а для города запасной текст подставляется прямо внутри вставки.

**Почему `??`, а не `if let`.** Через `if let` функция `displayName` заняла бы около десяти строк с вложенными проверками. Смысл при этом тот же. Когда на случай `nil` есть простое значение по умолчанию, `??` говорит об этом одной строкой — и читающему сразу видно, что возьмётся и в каком порядке.

**Почему в `authorLine` вызывается `displayName`.** Правило «ник, имя или Гость» уже записано в одной функции. Если дизайнер решит заменить слово «Гость» на другое, менять придётся одно место, а не два.

**Чего `??` не умеет.** Он реагирует только на `nil`. Пустая строка `""` — это значение, и `"" ?? "Гость"` даст пустую строку. Если пустой ник нужно считать отсутствующим, понадобится отдельная проверка.

**Типичные ошибки:**

- в конце цепочки нет обычного значения: `nickname ?? firstName` — результат остаётся опционалом, и Swift не даст вернуть его как `String`;
- перепутан порядок: `firstName ?? nickname` — имя станет важнее ника;
- запасное значение не того типа: `setting ?? "20"` — в коробочке число, а справа текст;
- в подписи потерян пробел перед скобкой или сама скобка — проверка сравнивает строки символ в символ.
