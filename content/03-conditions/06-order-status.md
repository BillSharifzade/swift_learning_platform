## @description

### Контекст
После оплаты гость открывает экран «Мой заказ» и следит, что происходит с его едой. Сведения о заказе приложение получает с сервера — так называют компьютер компании, на котором хранятся все заказы. Сервер присылает не готовую фразу, а короткий **код статуса** — английское слово вроде `"cooking"`. Так удобнее: код один, а текст можно показать на любом языке.

Разработчик серверной части прислал список кодов, а дизайнер — тексты для экрана:

- `"new"` — «Заказ принят»;
- `"cooking"` и `"packing"` — «Готовим ваш заказ» (гостю неважно, жарят его блюдо или уже упаковывают);
- `"delivery"` — «Курьер уже в пути»;
- `"done"` — «Заказ доставлен»;
- любой другой код — «Статус уточняется».

Это можно записать цепочкой `else if`, но в ней пришлось бы пять раз повторить `statusCode ==`. Для такого разбора в Swift есть инструмент удобнее.

### Новое в Swift
Оператор `switch` («переключатель») берёт одно значение и сравнивает его с вариантами по очереди:

```swift
let paymentCode = "cash"
var paymentText = ""

switch paymentCode {
case "card":
    paymentText = "Картой онлайн"
case "cash":
    paymentText = "Наличными курьеру"
case "sbp", "qr":
    paymentText = "Через СБП"
default:
    paymentText = "Способ оплаты не выбран"
}

print(paymentText)   // Наличными курьеру
```

Разберём по частям:

- после слова `switch` стоит значение, которое разбираем, затем фигурные скобки;
- каждый вариант начинается словом `case` («случай»), потом идёт значение и **двоеточие**;
- под ним, с отступом, — команды для этого варианта. Отдельные фигурные скобки им не нужны;
- **несколько значений** с одинаковым результатом перечисляют в одном `case` через запятую: `case "sbp", "qr":`;
- `default` («по умолчанию») — ветка для всего, что не подошло ни под один `case`. Она пишется последней.

Swift идёт сверху вниз, находит **первую** подходящую ветку, выполняет её команды и сразу выходит из `switch`. Остальные ветки не выполняются.

Два строгих правила:

1. **`switch` обязан знать ответ для любого значения.** Строк бесконечно много, перечислить все невозможно, поэтому для строк ветка `default` обязательна. Без неё код не соберётся.
2. **В каждой ветке должна быть хотя бы одна команда.** Пустой `case` — ошибка.

> ⚠️ Строки сравниваются буква в букву. `"Cash"` и `"cash"` — разные значения, и первое попадёт в `default`.

### Задача
В редакторе есть код статуса `statusCode`, переменная `statusText` и готовый `print`. Не переименовывай данные — проверка подставит другие коды.

Между объявлением `statusText` и командой `print` напиши `switch` по `statusCode`. Он должен положить в `statusText` текст по таблице:

1. `"new"` — `Заказ принят`
2. `"cooking"` или `"packing"` — `Готовим ваш заказ`. Оба кода запиши в одном `case` через запятую.
3. `"delivery"` — `Курьер уже в пути`
4. `"done"` — `Заказ доставлен`
5. любой другой код — `Статус уточняется`

### Пример
Для данных из редактора (код `"cooking"`):

```text
Статус: Готовим ваш заказ
```

Для кода `"done"`:

```text
Статус: Заказ доставлен
```

А если сервер пришлёт незнакомый код, например `"refund"`:

```text
Статус: Статус уточняется
```

- must: /\bcase\b[^:\n]*,/ :: Коды `"cooking"` и `"packing"` дают один и тот же текст. Объедини их в одном `case` через запятую.

## @hint1
Весь твой код помещается между объявлением `statusText` и последним `print`: это один оператор `switch`.

Начни с первой строки: слово `switch`, имя константы, которую разбираешь, — `statusCode` — и открывающая фигурная скобка. Сразу поставь закрывающую скобку строкой ниже, чтобы не потерять её.

Внутри скобок идут ветки. Каждая начинается словом `case`, после него код статуса в кавычках и двоеточие. На следующей строке, с отступом, — присваивание: в `statusText` кладётся нужный текст. Слово `var` здесь не пишется, переменная уже объявлена выше.

Для готовки и упаковки текст одинаковый, поэтому это одна ветка: после `case` стоят оба кода через запятую.

Последняя ветка — `default` с двоеточием. Она без кода статуса: сюда попадает всё, что не совпало с вариантами выше. В ней тоже присваивание — текст про уточнение статуса.

Коды пиши точно как в таблице, маленькими буквами.

## @hint2
Так `switch` разбирает строку. Обрати внимание на ветку с двумя значениями и на `default` в конце:

```swift
let paymentCode = "cash"
var paymentText = ""

switch paymentCode {
case "card":
    paymentText = "Картой онлайн"
case "sbp", "qr":
    paymentText = "Через СБП"
default:
    paymentText = "Способ оплаты не выбран"
}
```

У тебя веток будет пять: четыре с `case` и одна `default`.

## @hint3
Начало готово. Допиши оставшиеся ветки:

```swift
switch statusCode {
case "new":
    statusText = "Заказ принят"
case "cooking", ___:
    statusText = "Готовим ваш заказ"
case "delivery":
    statusText = ___
case "done":
    statusText = "Заказ доставлен"
___:
    statusText = "Статус уточняется"
}
```

В первом пропуске — второй код, который даёт текст про готовку. Во втором — текст для заказа в пути, в кавычках. В третьем — слово, с которого начинается ветка «для всего остального».

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Swift берёт значение `statusCode` — для данных из редактора это `"cooking"` — и сравнивает его с вариантами сверху вниз. С `"new"` оно не совпадает. Следующая ветка содержит два значения: `"cooking"` и `"packing"`. Совпало первое — этого достаточно. Выполняется присваивание, в `statusText` попадает «Готовим ваш заказ», и Swift сразу выходит из `switch`. Ветки ниже он уже не смотрит. Затем `print` выводит готовый текст.

**Почему `switch`, а не `else if`.** Цепочка `if statusCode == "new" { ... } else if statusCode == "cooking" || statusCode == "packing" { ... }` делает то же самое. Но `switch` показывает суть сразу: «разбираем одно значение по вариантам». Варианты стоят столбиком, как строки таблицы, и добавить новый статус — это дописать две строки.

**Зачем `default`.** Сервер развивается отдельно от приложения. Завтра там появится код `"refund"`, а у гостя на телефоне останется старая версия «Ложки». Благодаря `default` она не сломается и не покажет пустую строку, а честно напишет «Статус уточняется». Swift требует `default` именно поэтому: программа должна знать, что делать с любым значением.

**Почему два кода в одной ветке.** Можно написать отдельный `case "packing":` с тем же текстом. Но тогда фраза повторяется дважды, и однажды её поправят в одном месте, а про второе забудут. Запись через запятую хранит текст в единственном экземпляре.

**Типичные ошибки:**

- забыто двоеточие после значения в `case` или после `default`;
- код написан без кавычек: `case new:` — Swift ищет константу с таким именем;
- `default` пропущен — код не соберётся: `switch` должен покрывать все возможные строки;
- в ветке `case "cooking":` нет команды, а текст написан только под `"packing"` — в Swift ветка не «проваливается» в следующую, пустой `case` считается ошибкой;
- опечатка в коде статуса: `"cookin"` не совпадёт ни с чем и уйдёт в `default`.
