## @description

### Контекст
В «Чернилах» есть заметки под ПИН-кодом: пароль от Wi-Fi, код домофона, номер карты. Чтобы прочитать такую заметку, нужно ввести ПИН-код. После трёх неверных попыток заметка блокируется.

В трекере появился неприятный тикет: «На экране поиска текст закрытой заметки виден без ПИН-кода». Причина нашлась быстро. Разработчик экрана поиска просто написал `note.text` — и Swift ему это позволил, потому что свойство ничем не защищено.

Тимлид просит: «Сделай так, чтобы такой код вообще не собирался. Пусть за секретами следит компилятор, а не наша внимательность».

### Новое в Swift
До сих пор любое свойство твоих типов можно было читать и менять из любого места программы. **Уровень доступа** — это слово перед объявлением, которое говорит, кому разрешено им пользоваться.

Самый строгий уровень — `private`. Такое свойство или метод видны только внутри самого типа, между его фигурными скобками:

```swift
struct Trash {
    private var deletedTitles: [String] = []

    mutating func put(_ title: String) {
        deletedTitles.append(title)   // внутри типа — можно
    }
}

var trash = Trash()
trash.put("Список покупок")
// print(trash.deletedTitles)   // ошибка: свойство закрыто
```

Часто нужно другое: читать значение можно всем, а менять — только самому типу. Для этого есть `private(set)`:

```swift
struct Trash {
    private(set) var count = 0

    mutating func put(_ title: String) {
        count += 1
    }
}

var trash = Trash()
trash.put("Черновик")
print(trash.count)    // 1 — читать можно
// trash.count = 100  // ошибка: менять снаружи нельзя
```

Всего уровней пять, от самого закрытого к самому открытому:

- `private` — только внутри типа (и его расширений в том же файле);
- `fileprivate` — в любом месте того же файла;
- `internal` — во всём модуле. Модуль — это одно приложение или одна библиотека. Этот уровень действует по умолчанию, когда ты ничего не пишешь;
- `public` — можно пользоваться и из других модулей. Так размечают библиотеки;
- `open` — как `public`, но другим модулям ещё разрешено наследоваться от класса и переопределять его методы.

В приложении чаще всего хватает двух: `private` для внутренностей и обычного `internal` для всего остального.

> ⚠️ Если у структуры есть `private`-свойство без значения по умолчанию, её автоматический инициализатор тоже становится закрытым. Поэтому таким структурам пишут свой `init` — в заготовке он уже есть.

> 💡 Правило опытных разработчиков: сначала закрывай всё, что можно. Открыть свойство позже легко. Закрыть то, чем уже пользуется половина приложения, — трудно.

### Задача
В редакторе есть структура `LockedNote`. Доработай её:

1. Закрой свойства `text` и `pin` словом `private`.
2. Свойство `failedAttempts` должно читаться снаружи, но меняться только внутри структуры: `private(set)`.
3. Напиши тело метода `unlock(pin:)`. Он возвращает `String?`:
   - если заметка уже заблокирована (`isBlocked`) — вернуть `nil`, счётчик не менять;
   - если введённый ПИН-код не совпал с `pin` — увеличить `failedAttempts` на 1 и вернуть `nil`;
   - если совпал — обнулить `failedAttempts` и вернуть `text`.
4. Внизу файла есть код экрана поиска. После шага 1 строка `print(wifiNote.text)` перестанет собираться — так и задумано. Удали её.

Свойство `title`, инициализатор и `isBlocked` не меняй.

### Пример
```swift
var note = LockedNote(title: "Код домофона", text: "38к2580", pin: "7302")
note.unlock(pin: "1111")    // nil
note.failedAttempts         // 1
note.unlock(pin: "7302")    // "38к2580"
note.failedAttempts         // 0
// note.text                // не собирается
// note.failedAttempts = 0  // не собирается
```

## @solution
```swift
// Заметка под ПИН-кодом
struct LockedNote {
    // Заголовок виден всем: он показывается в списке заметок
    let title: String
    // Текст и ПИН-код — только для самой заметки
    private let text: String
    private let pin: String
    // Счётчик неверных попыток: читать можно всем, менять — только заметке
    private(set) var failedAttempts = 0

    init(title: String, text: String, pin: String) {
        self.title = title
        self.text = text
        self.pin = pin
    }

    // После трёх неверных попыток заметка блокируется
    var isBlocked: Bool {
        failedAttempts >= 3
    }

    // Возвращает текст, если ПИН-код верный, иначе nil
    mutating func unlock(pin enteredPin: String) -> String? {
        guard !isBlocked else {
            return nil
        }
        guard enteredPin == pin else {
            failedAttempts += 1
            return nil
        }
        failedAttempts = 0
        return text
    }
}

// Экран поиска. Теперь ему доступен только заголовок
var wifiNote = LockedNote(title: "Пароль от Wi-Fi", text: "lavanda-2024", pin: "4821")
print("Найдено: \(wifiNote.title)")
```

## @rules
- must: /\bprivate\s+(?:let|var)\s+text\b/ :: Свойство `text` должно быть закрыто: напиши перед ним `private`.
- must: /\bprivate\s+(?:let|var)\s+pin\b/ :: Свойство `pin` должно быть закрыто: напиши перед ним `private`.
- must: /\bprivate\s*\(\s*set\s*\)\s*var\s+failedAttempts\b/ :: Счётчик `failedAttempts` должен читаться снаружи, но меняться только внутри: объяви его как `private(set) var`.

## @hint1
В задаче две части: расставить уровни доступа и написать метод.

Уровни доступа — это по одному слову перед тремя объявлениями свойств. Текст и ПИН-код не должен видеть никто, кроме самой заметки: перед ними ставится `private`. Счётчик попыток экрану нужен (чтобы показать, сколько попыток осталось), но менять его снаружи нельзя: для этого есть вариант `private(set)`.

Как только `text` станет закрытым, последняя строка файла перестанет собираться. Это не поломка, а именно то, о чём просил тимлид: компилятор поймал код, который лезет к секрету. Эту строку нужно удалить.

Теперь метод. В нём три случая, и порядок важен. Сначала проверь, не заблокирована ли заметка: если да — сразу `nil`. Потом сравни введённый ПИН-код с настоящим: не совпал — прибавь единицу к счётчику и верни `nil`. Если дошла до конца — ПИН-код верный: обнули счётчик и верни текст. Для первых двух проверок удобно использовать `guard`.

## @hint2
Слово доступа пишется перед `let` или `var`:

```swift
struct Trash {
    private var deletedTitles: [String] = []
    private(set) var count = 0
}
```

А метод начинается с ранних выходов. Первая проверка — блокировка:

```swift
guard !isBlocked else {
    return nil
}
```

Вторая проверка устроена так же, только сравнивает `enteredPin` и `pin`, а перед `return nil` увеличивает счётчик.

## @hint3
Свойства после доработки:

```swift
private let text: String
private let pin: String
private(set) var failedAttempts = 0
```

Метод почти готов:

```swift
mutating func unlock(pin enteredPin: String) -> String? {
    guard !isBlocked else {
        return nil

    guard enteredPin == ___ else {
        failedAttempts += ___
        return nil
    }
    failedAttempts = ___
    return ___

```

В пропусках: с чем сравнивается введённый код, на сколько растёт счётчик, каким он становится после успеха и что метод отдаёт при верном ПИН-коде. И не забудь удалить строку `print(wifiNote.text)` внизу файла.

## @hint4
Вот готовое решение:

{{solution}}

**Что изменилось в свойствах.** Перед `text` и `pin` появилось `private`. Теперь обратиться к ним можно только между фигурными скобками `LockedNote`. Метод `unlock` находится внутри, поэтому он по-прежнему видит оба свойства. А экран поиска — снаружи, и строка `print(wifiNote.text)` больше не собирается. Ошибка из тикета стала невозможной: её не пропустит компилятор.

**Почему у счётчика `private(set)`, а не `private`.** Экрану нужно читать `failedAttempts`, чтобы написать «Осталось попыток: 2». Но если бы счётчик можно было менять снаружи, любой код мог бы написать `note.failedAttempts = 0` и подбирать ПИН-код бесконечно. `private(set)` разрешает чтение всем, а запись — только самой структуре.

**Как работает метод.** Первый `guard` отсекает заблокированную заметку: она не открывается никаким кодом, и счётчик не трогается. Второй `guard` сравнивает введённый код с настоящим. При ошибке счётчик растёт, метод возвращает `nil`. Если оба `guard` пройдены, код верный: счётчик обнуляется, текст возвращается. Слово `mutating` нужно, потому что метод меняет свойство структуры.

**Почему `init` написан вручную.** У структуры с `private`-свойствами автоматический инициализатор тоже становится `private`, и создать заметку снаружи было бы нельзя. Свой `init` без слова `private` решает эту проблему.

**Типичные ошибки:**

- сначала сравнить ПИН-коды, а блокировку проверить потом — тогда заблокированная заметка откроется верным кодом;
- написать `private var failedAttempts` — проверка не сможет прочитать счётчик, и экран тоже;
- оставить строку `print(wifiNote.text)` и убрать `private`, чтобы код собрался, — это возвращает исходную ошибку.
