## @description

### Контекст
Прежде чем отправить перевод другому человеку, «Копилка» его проверяет: указан ли получатель, правильная ли сумма, не превышен ли лимит, хватает ли денег на счёте. Если что-то не так, пользователь видит причину отказа.

Тимлид предупреждает заранее: «Только не пиши лесенку из вложенных `if`: через месяц добавятся новые проверки, и в ней никто ничего не найдёт. Сначала по одной отсекаем причины отказа, а в конце остаётся один ровный путь для хорошего случая. Для этого в Swift есть `guard`».

### Новое в Swift
Вот как выглядит проверка снятия наличных, написанная вложенными условиями:

```swift
func withdrawalMessage(amount: Int, available: Int) -> String {
    if amount % 100 == 0 {
        if amount <= available {
            return "Заберите деньги"
        } else {
            return "В банкомате недостаточно купюр"
        }
    } else {
        return "Сумма должна быть кратна 100"
    }
}
```

Проверок всего две, а читать уже трудно: главный результат спрятан в глубине, а текст отказа стоит далеко от своего условия.

Слово `guard` («страж») решает эту проблему. Оно записывает требование: что **должно быть верно**, чтобы функция продолжила работу. Если требование не выполнено, срабатывает блок `else`, и функция из него выходит:

```swift
func withdrawalMessage(amount: Int, available: Int) -> String {
    guard amount % 100 == 0 else {
        return "Сумма должна быть кратна 100"
    }
    guard amount <= available else {
        return "В банкомате недостаточно купюр"
    }
    return "Заберите деньги"
}
```

Читается как список требований: «убедись, что сумма кратна 100, иначе верни отказ. Убедись, что купюр хватает, иначе верни отказ. Всё в порядке — выдаём деньги».

Как устроен `guard`:

- после слова `guard` стоит условие — то, что должно быть **правдой** в хорошем случае;
- затем обязательно идут `else` и фигурные скобки. Этот блок обязан закончить работу функции, обычно командой `return`, — иначе Swift не соберёт код;
- если условие верно, блок `else` пропускается, и выполнение идёт дальше.

Такой приём называют **ранним выходом**: функция прекращает работу, как только понимает, что продолжать нет смысла.

> ⚠️ Самая частая ошибка — перепутать смысл условия. В `if` для отказа ты написала бы «если сумма больше доступной». В `guard` пишется наоборот — то, что нужно для успеха: «сумма не больше доступной».

### Задача
В редакторе уже объявлена функция `validateTransfer`. Её параметры: `amount` — сумма перевода, `recipient` — имя получателя (при вызове метка `to`), `balance` — деньги на счёте, `limit` — наибольшая сумма одного перевода.

Допиши в тело функции четыре проверки через `guard` — именно в таком порядке. Каждая возвращает свой текст отказа:

1. Получатель указан, то есть строка `recipient` не пустая. Иначе — `Укажите получателя`.
2. Сумма больше нуля. Иначе — `Сумма должна быть больше нуля`.
3. Сумма не больше лимита (перевод ровно на сумму лимита разрешён). Иначе — `Превышен лимит перевода`.
4. Сумма не больше баланса (перевести все деньги со счёта можно). Иначе — `Недостаточно средств`.

Если все проверки пройдены, функция возвращает `Перевод разрешён` — эта строка уже есть в заготовке.

Порядок важен: когда нарушено сразу несколько правил, пользователь видит причину первой несработавшей проверки.

### Пример
```swift
validateTransfer(amount: 5000, to: "Билол", balance: 12000, limit: 50000)
// "Перевод разрешён"

validateTransfer(amount: 5000, to: "", balance: 12000, limit: 50000)
// "Укажите получателя"

validateTransfer(amount: 70000, to: "Билол", balance: 12000, limit: 50000)
// "Превышен лимит перевода" — лимит проверяется раньше баланса
```

## @solution
```swift
// Проверяет перевод: возвращает причину отказа или текст "Перевод разрешён"
func validateTransfer(amount: Int, to recipient: String, balance: Int, limit: Int) -> String {
    // Напиши здесь четыре проверки через guard — в том порядке, как в задании
    guard !recipient.isEmpty else {
        return "Укажите получателя"
    }
    guard amount > 0 else {
        return "Сумма должна быть больше нуля"
    }
    guard amount <= limit else {
        return "Превышен лимит перевода"
    }
    guard amount <= balance else {
        return "Недостаточно средств"
    }

    // Все проверки пройдены
    return "Перевод разрешён"
}

// Проба: меняй значения и смотри, что вернёт функция
print(validateTransfer(amount: 5000, to: "Билол", balance: 12000, limit: 50000))
print(validateTransfer(amount: 5000, to: "", balance: 12000, limit: 50000))
```

## @rules
- must: /(\bguard\b[\s\S]*){4}/ :: Каждую из четырёх проверок оформи через `guard` — сейчас их в коде меньше четырёх.

## @hint1
Тебе нужно написать четыре похожих кусочка, один под другим. Каждый — это `guard` с одним требованием и одним текстом отказа.

Для каждой проверки задай себе вопрос: «Что должно быть верно, чтобы перевод можно было продолжать?» Именно это и пишется после слова `guard`. Для первой проверки ответ такой: строка с получателем не пустая. Пустоту строки ты умеешь проверять свойством `isEmpty`, а «не» записывается восклицательным знаком перед условием. Для второй: сумма больше нуля. Для третьей: сумма меньше или равна лимиту. Для четвёртой: сумма меньше или равна балансу.

После условия идёт слово `else` и фигурные скобки. Внутри — `return` с текстом отказа из задания. Этот блок сработает, только если требование не выполнено.

Проверки должны стоять в том же порядке, что и в задании, и все — выше строки с текстом «Перевод разрешён». Тогда до неё дойдут только те переводы, которые прошли всех четырёх «стражей».

## @hint2
Один `guard` — это требование и выход, если оно не выполнено:

```swift
func withdrawalMessage(amount: Int, available: Int) -> String {
    guard amount % 100 == 0 else {
        return "Сумма должна быть кратна 100"
    }
    guard amount <= available else {
        return "В банкомате недостаточно купюр"
    }
    return "Заберите деньги"
}
```

После `guard` написано то, что должно быть правдой в хорошем случае. В твоей функции таких блоков четыре. Первый проверяет строку: `guard !recipient.isEmpty else { ... }`.

## @hint3
Первые две проверки готовы. Допиши условия третьей и четвёртой и текст последнего отказа:

```swift
guard !recipient.isEmpty else {
    return "Укажите получателя"
}
guard amount > 0 else {
    return "Сумма должна быть больше нуля"
}
guard ___ else {
    return "Превышен лимит перевода"
}
guard ___ else {
    return ___
}
```

В первом пропуске — требование «сумма не больше лимита». Во втором — «сумма не больше баланса». Оба пишутся через `<=`, потому что перевод ровно на сумму лимита или баланса разрешён. В третьем пропуске — текст отказа, когда денег не хватает.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Функция идёт сверху вниз и встречает четырёх «стражей». Каждый `guard` проверяет одно требование. Если оно выполнено, блок `else` пропускается и выполнение переходит к следующей строке. Если нет — срабатывает `return` внутри `else`, и функция сразу отдаёт причину отказа. Остальные проверки при этом уже не выполняются.

Поэтому порядок проверок определяет, какое сообщение увидит пользователь. Перевод на 70000 руб. при лимите 50000 и балансе 12000 нарушает два правила, но лимит проверяется раньше — вернётся `Превышен лимит перевода`.

До последней строки, `return "Перевод разрешён"`, доходят только те вызовы, которые прошли все проверки. Она стоит без отступов и условий — это и есть ровный «хороший» путь.

**Почему `guard`, а не `if`.** Через `if` это тоже можно написать: `if recipient.isEmpty { return ... }`. Работать будет так же. Но у `guard` два преимущества. Первое: он читается как требование — «получатель должен быть указан», а не как описание беды. Все условия в функции записаны в одном ключе: что нужно для успеха. Второе: Swift проверяет, что блок `else` действительно выходит из функции. Забытый `return` в `if` — тихая ошибка, а в `guard` — код просто не соберётся.

**Почему `<=`, а не `<`.** Требование звучит как «сумма не больше лимита». Перевод ровно на 50000 при лимите 50000 лимит не превышает. Со строгим знаком `<` такой перевод получил бы отказ — это частая ошибка на границе, и проверка её ловит.

**Типичные ошибки:**

- условие «перевёрнуто», как в `if`: `guard recipient.isEmpty else` — так отказ получат все переводы, где получатель указан;
- пропущено слово `else` после условия;
- в блоке `else` нет `return` — Swift сообщит, что из `guard` нельзя «провалиться» дальше;
- проверка баланса стоит раньше проверки лимита — тексты отказов перепутаются, когда нарушены оба правила.
