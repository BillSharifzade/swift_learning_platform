## @description

### Контекст
Экран регистрации в «Рядом» состоит из трёх полей: имя, пароль и возраст. Пока человек не дотронулся до поля, в нём лежит `nil`. По кнопке «Создать аккаунт» приложение проверяет форму и показывает под ней сообщение: либо что именно не так, либо что аккаунт создан.

Тимлид просит написать эту проверку: «Проверяй поля по порядку и останавливайся на первой проблеме. Человеку удобнее исправлять по одной ошибке за раз».

### Новое в Swift
В «Копилке» ты уже писала `guard`: он проверяет условие в начале функции и сразу выходит, если оно не выполнено. Сегодня — его вариант для опционалов.

Сначала о том, чем неудобен `if let`. Развёрнутое значение живёт только внутри его фигурных скобок. Если полей три, получается «лесенка»: `if let` внутри `if let` внутри `if let`, а главный код уезжает далеко вправо.

`guard let` разворачивает опционал по-другому:

```swift
func greeting(for nickname: String?) -> String {
    guard let nickname else {
        return "Сначала придумайте ник"
    }
    // отсюда и до конца функции nickname — обычный String
    return "Привет, \(nickname)"
}
```

Читается так: «убедись, что в `nickname` есть значение, **иначе** выйди из функции». Если значения нет, выполняется блок `else`, и в нём обязательно должен быть выход — `return`. Если значение есть, оно остаётся доступным **после** `guard`, до самого конца функции. Никакой лесенки: проверки идут столбиком сверху, главный код — внизу.

Как и у `if let`, есть полная запись с новым именем: `guard let name = nickname else { ... }`.

**Несколько условий в одном `guard`.** Часто значение нужно не только достать, но и сразу проверить. Условия перечисляют через запятую:

```swift
func confirmationMessage(code: String?) -> String {
    guard let code, code.count == 6 else {
        return "Код состоит из 6 цифр"
    }
    return "Код \(code) принят"
}
```

Swift идёт слева направо: сначала разворачивает `code`, потом проверяет длину — уже у обычной строки. Если не выполнено хоть одно условие, срабатывает `else`. Так и пустое поле, и неверная длина получают одно общее сообщение.

> 💡 Как выбрать: `if let` — когда без значения можно обойтись и нужно просто сделать что-то иначе. `guard let` — когда без значения продолжать нет смысла.

### Задача
Допиши функцию `registrationMessage(name:password:age:)`. Параметры `name` и `password` имеют тип `String?`, параметр `age` — тип `Int?`. Функция возвращает `String`.

Проверки идут строго в таком порядке:

1. Если имя не заполнено (`nil`) или это пустая строка — вернуть `Введите имя`.
2. Если пароль не заполнен или в нём меньше 8 символов — вернуть `Пароль должен быть не короче 8 символов`.
3. Если возраст не указан или он меньше 14 — вернуть `Регистрация доступна с 14 лет`.
4. Если всё в порядке — вернуть строку вида `Аккаунт создан: Билол, 28`: имя, запятая, пробел, возраст.

Опционалы разворачивай через `guard let`.

### Пример
```swift
registrationMessage(name: "Билол", password: "gornyi-kofe", age: 28)
// "Аккаунт создан: Билол, 28"

registrationMessage(name: nil, password: "gornyi-kofe", age: 28)
// "Введите имя"

registrationMessage(name: "Билол", password: "kofe", age: 28)
// "Пароль должен быть не короче 8 символов"

registrationMessage(name: "Билол", password: "gornyi-kofe", age: nil)
// "Регистрация доступна с 14 лет"
```

## @solution
```swift
// Проверка формы регистрации.
// Поле равно nil, если пользователь его не заполнил
func registrationMessage(name: String?, password: String?, age: Int?) -> String {
    // 1. Имя: заполнено и не пустая строка, иначе "Введите имя"
    guard let name, !name.isEmpty else {
        return "Введите имя"
    }

    // 2. Пароль: заполнен и не короче 8 символов
    guard let password, password.count >= 8 else {
        return "Пароль должен быть не короче 8 символов"
    }

    // 3. Возраст: указан и не меньше 14
    guard let age, age >= 14 else {
        return "Регистрация доступна с 14 лет"
    }

    // 4. Всё в порядке: замени заглушку сообщением об успехе
    return "Аккаунт создан: \(name), \(age)"
}
```

## @rules
- must: /\bguard\s+let\b/ :: Разворачивай поля формы через `guard let` — в коде его не видно.
- mustnot: /\bif\s+let\b/ :: В этой задаче вместо `if let` используй `guard let`: так проверки идут столбиком, без вложенности.

## @hint1
В функции будет три `guard` подряд — по одному на каждое поле — и в самом конце `return` с сообщением об успехе.

Первый `guard` отвечает за имя. В нём два условия через запятую. Сначала имя разворачивается: `let` и название параметра. Потом уже развёрнутое имя проверяется: оно не должно быть пустой строкой. Тут пригодится свойство `isEmpty` и знак отрицания `!` перед ним. После условий идёт `else` и блок, в котором функция возвращает текст «Введите имя».

Второй `guard` такой же, но для пароля: развернуть и проверить, что символов не меньше восьми. Количество символов даёт свойство `count`.

Третий — для возраста: развернуть и проверить, что он не меньше 14.

После трёх проверок `name` и `age` — обычные значения, не опционалы. Их можно вставить в итоговую строку через интерполяцию. Заглушку `return ""` замени этой строкой.

## @hint2
Вот `guard let` с двумя условиями — на примере кода подтверждения:

```swift
guard let code, code.count == 6 else {
    return "Код состоит из 6 цифр"
}
// здесь code — обычный String
```

Первое условие достаёт значение из коробочки, второе проверяет его. У тебя таких `guard` три: для `name`, `password` и `age`. Условия после запятой у каждого свои.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Каждый `guard` — пропускной пункт. `guard let name, !name.isEmpty` сначала достаёт имя из коробочки, потом проверяет, что оно не пустое. Если что-то из этого не получилось, выполняется `else`, и функция сразу возвращает сообщение об ошибке. До следующих проверок дело не доходит — поэтому человек видит только первую проблему. Если всё хорошо, выполнение идёт дальше, а `name` с этого места — обычный `String`.

**Почему `guard let`, а не `if let`.** Значения `name` и `age` нужны в самой последней строке. `if let` отдаёт развёрнутое значение только внутрь своих скобок, поэтому итоговый `return` пришлось бы прятать на третий уровень вложенности. `guard let` оставляет значение доступным до конца функции. Код читается сверху вниз: сначала все причины отказа, потом успешный результат.

**Почему условия через запятую.** Сообщение для пустого поля и для слишком короткого пароля одно и то же. Нет смысла писать два `guard` с одинаковым текстом. Условие после запятой может пользоваться тем, что развёрнуто перед ней: `password.count` считается уже у обычной строки.

**Типичные ошибки:**

- в блоке `else` нет `return` — Swift требует, чтобы `guard` заканчивался выходом из функции;
- проверка записана наоборот: `guard let age, age < 14 else` — в `guard` пишут условие, при котором всё **хорошо**;
- `password.count > 8` вместо `>= 8` — пароль ровно из восьми символов будет отклонён;
- проверки стоят в другом порядке — тогда при нескольких ошибках покажется не то сообщение.
