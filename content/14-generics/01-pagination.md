## @description

### Контекст
Первый тикет в трекере «Каркаса»: «В "Волне" есть функция `trackPage`, которая отдаёт треки страницами. В "Ярмарке" её скопировали для товаров, в "Почтальоне" — для сообщений. На прошлой неделе нашли ошибку и чинили её в трёх местах. Нужна одна функция для списка любого типа».

Тимлид добавляет: «Копии отличаются только типами — `[String]`, `[Product]`, `[Message]`. Логика у них одна и та же. Это ровно тот случай, для которого придуманы дженерики».

### Новое в Swift
Функция, которую ты писала до сих пор, работает с конкретными типами. Если параметр объявлен как `[String]`, массив чисел в неё уже не передать — нужна копия функции с `[Int]`.

**Обобщённая функция** (по-английски generic, отсюда «дженерик») пишется один раз для любого типа. Сразу после имени функции в угловых скобках объявляют **параметр типа** — имя-заполнитель. Дальше в объявлении и в теле функции его используют как обычный тип.

Пример: экран загрузки показывает «скелет» — несколько одинаковых серых строк-заглушек, пока не пришли данные. Заглушкой может быть что угодно:

```swift
func placeholders<T>(_ sample: T, count: Int) -> [T] {
    var result: [T] = []
    while result.count < count {
        result.append(sample)
    }
    return result
}
```

`<T>` означает: «у этой функции есть параметр типа `T`». Параметр `sample` имеет тип `T`, результат — массив `[T]`.

Какой тип окажется на месте `T`, решается при каждом вызове. Swift смотрит на аргументы и подставляет нужный тип сам:

```swift
let rows = placeholders("Загрузка", count: 3)   // T — это String, результат [String]
let sums = placeholders(0, count: 2)            // T — это Int, результат [Int]
```

Имя параметра типа может быть любым. Короткое `T` (от type) — традиция, но часто пишут и говорящие имена: `Item`, `Element`, `Value`. Главное — с большой буквы, как у всех типов.

**Что можно делать с `T` внутри функции.** Только то, что умеет любой тип: хранить в переменной, класть в массив, возвращать, передавать дальше. Сравнить два значения через `==` или сложить через `+` нельзя — Swift не знает, умеет ли это тот тип, который подставят. Как это разрешить, ты узнаешь через пару задач. Для постраничной выдачи хватит и этого: она только отбирает элементы, не заглядывая в них.

> 💡 Ты уже пользовалась дженериками. `[String]` — это короткая запись `Array<String>`, а `Set<String>` ты писала в модуле про коллекции. Массив, множество, словарь и опционал — обобщённые типы стандартной библиотеки.

> ⚠️ Если забыть `<T>` после имени функции, Swift сообщит, что не знает тип `T`. Параметр типа нужно сначала объявить — так же, как обычный параметр.

### Задача
В редакторе есть старая функция `trackPage(_:number:size:)` из «Волны». Она работает только со строками. Не удаляй её — она пригодится как образец.

1. Объяви обобщённую функцию `page(_:number:size:)`, которая возвращает массив того же типа, что и получила. Параметры:
   - список элементов любого типа — при вызове без метки;
   - `number` типа `Int` — номер страницы, считая с 1;
   - `size` типа `Int` — сколько элементов на странице.

   Правила те же, что у `trackPage`: на первой странице элементы с индексами от `0` до `size - 1`, на второй — следующие `size` штук и так далее. Последняя страница может быть неполной. Если такой страницы нет или `number` либо `size` меньше 1 — пустой массив.
2. Объяви обобщённую функцию `pageCount(_:size:)`, которая возвращает `Int` — сколько всего страниц. Список передаётся без метки, `size` — с меткой. Для пустого списка страниц `0`. Если `size` меньше 1 — тоже `0`.

Имя параметра типа выбери сама. Проверка вызовет функции со строками, с числами и со своими структурами.

### Пример
```swift
let tracks = ["Рассвет", "Море", "Дорога домой", "Ночной город", "Осень"]

page(tracks, number: 2, size: 2)      // ["Дорога домой", "Ночной город"]
page(tracks, number: 3, size: 2)      // ["Осень"] — последняя страница неполная
page(tracks, number: 4, size: 2)      // [] — такой страницы нет
page([990, 1490, 250], number: 1, size: 2)   // [990, 1490]

pageCount(tracks, size: 2)            // 3
pageCount([990, 1490, 250, 75], size: 2)     // 2
let noTracks: [String] = []
pageCount(noTracks, size: 2)          // 0
```

// Старая версия из «Волны»: умеет листать только строки
func trackPage(_ tracks: [String], number: Int, size: Int) -> [String] {
    guard number >= 1, size >= 1 else {
        return []
    }
    let start = (number - 1) * size
    let end = start + size
    var result: [String] = []
    for (index, track) in tracks.enumerated() {
        if index >= start && index < end {
            result.append(track)
        }
    }
    return result
}

```swift
// Старая версия из «Волны»: умеет листать только строки
func trackPage(_ tracks: [String], number: Int, size: Int) -> [String] {
    guard number >= 1, size >= 1 else {
        return []
    }
    let start = (number - 1) * size
    let end = start + size
    var result: [String] = []
    for (index, track) in tracks.enumerated() {
        if index >= start && index < end {
            result.append(track)
        }
    }
    return result
}

// 1. Обобщённая функция page: страница списка любого типа
func page<Item>(_ items: [Item], number: Int, size: Int) -> [Item] {
    guard number >= 1, size >= 1 else {
        return []
    }
    let start = (number - 1) * size
    let end = start + size
    var result: [Item] = []
    for (index, item) in items.enumerated() {
        if index >= start && index < end {
            result.append(item)
        }
    }
    return result
}

// 2. Обобщённая функция pageCount: сколько всего страниц
func pageCount<Item>(_ items: [Item], size: Int) -> Int {
    guard size >= 1 else {
        return 0
    }
    var pages = items.count / size
    if items.count % size > 0 {
        pages += 1
    }
    return pages
}
```

## @rules
- must: /func\s+page\s*<\s*\w+\s*>/ :: Объяви `page` как обобщённую функцию: сразу после имени — параметр типа в угловых скобках, например `func page<Item>(...)`.
- must: /func\s+pageCount\s*<\s*\w+\s*>/ :: Объяви `pageCount` как обобщённую функцию: сразу после имени — параметр типа в угловых скобках.

## @hint1
Начни с `page`. Её тело уже написано — это тело `trackPage`. Скопируй функцию целиком, переименуй и сделай обобщённой.

Для этого сразу после имени, до круглых скобок, объяви в угловых скобках параметр типа — например, `Item`. Потом пройди по объявлению и телу и замени все `String`, которые означают «элемент списка», на `Item`. Таких мест три: тип параметра со списком, тип результата и тип пустого массива `result` внутри. Имена `tracks` и `track` лучше тоже заменить на нейтральные `items` и `item`: функция больше не знает, что листает треки.

`pageCount` тоже обобщённая, с тем же параметром типа. Сначала через `guard` отсеки размер меньше 1 — верни ноль. Потом посчитай полные страницы: количество элементов, делённое нацело на размер страницы. Если остаток от деления больше нуля, добавь ещё одну, неполную страницу. Для пустого списка оба числа окажутся нулями — отдельная проверка не нужна.

## @hint2
Обобщённая функция отличается от обычной угловыми скобками после имени. Вот как выглядит обобщённое начало `page`:

```swift
func page<Item>(_ items: [Item], number: Int, size: Int) -> [Item] {
    // тело как у trackPage, но с [Item] вместо [String]
}
```

А страницы с округлением вверх считаются через деление нацело и остаток:

```swift
var pages = items.count / size
if items.count % size > 0 {
    pages += 1
}
```

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** Запись `func page<Item>` объявляет параметр типа `Item`. Это не настоящий тип, а заполнитель. Когда приложение вызывает `page(tracks, number: 2, size: 2)`, Swift видит, что `tracks` — это `[String]`, и подставляет `String` на место `Item` везде: в параметр, в результат, в `result`. Для массива цен подставится `Int`, для массива сообщений — структура сообщения. Код написан один раз, а работает для всех.

Тело функции не изменилось по сравнению с `trackPage` — и в этом весь смысл. Пагинация никогда не заглядывала внутрь элементов: она только смотрит на индексы и перекладывает элементы в новый массив. Это умеет любой тип, поэтому никаких дополнительных условий на `Item` не нужно.

**Как считаются страницы.** `items.count / size` — деление нацело, оно отбрасывает остаток: 5 треков по 2 — это 2 полные страницы. Остаток `5 % 2` равен 1 — значит, есть ещё одна неполная страница, итого 3. Для 6 элементов по 3 остаток 0, и лишняя страница не добавляется. `guard` в начале защищает от деления на ноль: без него `size: 0` уронил бы программу.

**Почему параметр типа у `pageCount`, хотя элементы ей не нужны.** Функция смотрит только на `count`, но получить она должна массив любого типа. Без `<Item>` пришлось бы снова выбирать конкретный тип.

**Типичные ошибки:**

- забыт `<Item>` после имени — Swift сообщит, что не знает тип `Item`;
- `var result: [String] = []` осталось от старой функции — Swift не даст положить в массив строк элемент типа `Item`;
- в `pageCount` забыта неполная страница — для 5 треков по 2 получится 2 вместо 3;
- нет `guard` в `pageCount` — при `size: 0` программа упадёт с делением на ноль.
