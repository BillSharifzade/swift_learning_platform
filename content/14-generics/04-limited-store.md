## @description

### Контекст
Следующий тикет пришёл от двух команд сразу. «Ярмарке» нужен блок «Вы недавно смотрели»: последние 20 товаров, ключ — числовой id товара. «Почтальону» нужны черновики сообщений: текст недописанного сообщения для каждого чата, ключ — строковый id чата, и не больше 50 черновиков, чтобы не забивать память телефона.

Тимлид замечает общее: «Это одно и то же хранилище "ключ — значение" с лимитом. Когда места нет, выбрасываем самую старую запись. Только у "Ярмарки" ключи числа, а у "Почтальона" строки. Значит, параметров типа будет два».

### Новое в Swift
Параметров типа может быть несколько. Они перечисляются в угловых скобках через запятую, и у каждого может быть своё ограничение.

Пример: непрочитанные уведомления, сгруппированные по чатам. Группа служит ключом словаря, поэтому она обязана быть `Hashable`. А элементом группы может быть что угодно:

```swift
struct Grouped<Group: Hashable, Item> {
    var groups: [Group: [Item]] = [:]

    mutating func add(_ item: Item, to group: Group) {
        groups[group, default: []].append(item)
    }

    func items(in group: Group) -> [Item] {
        return groups[group] ?? []
    }
}
```

Ограничение стоит только у `Group`: ему нужно быть ключом. `Item` просто хранится в массиве — для этого никаких умений не требуется. Хорошее правило: ставь ограничение только там, где без него код не соберётся. Каждое лишнее ограничение сужает круг типов, с которыми можно работать.

При создании типы указываются **в том же порядке**, в каком объявлены параметры:

```swift
var unread = Grouped<String, String>()       // группа — название чата, элемент — текст
unread.add("Созвон в 18:00", to: "Работа")
unread.add("Купи хлеб", to: "Семья")
unread.items(in: "Работа")    // ["Созвон в 18:00"]
unread.items(in: "Спорт")     // []

var marks = Grouped<Int, Double>()           // группа — номер недели, элемент — оценка
```

`Grouped<String, String>` и `Grouped<Int, Double>` — снова два разных типа из одного чертежа. Если перепутать порядок и написать `Grouped<Double, Int>`, Swift возразит: `Double` не `Hashable`, ключом быть не может.

> 💡 Сравнить опционал с `nil` можно для значения любого типа: `values[key] != nil` работает, даже если сам `Value` не умеет `==`. Это удобный способ спросить «есть ли такой ключ».

### Задача
Объяви обобщённую структуру `LimitedStore` с двумя параметрами типа: сначала `Key` — тип ключа (он должен быть `Hashable`), потом `Value` — тип значения (любой).

1. Свойства:
   - `limit` типа `Int` — константа, сколько записей можно хранить; задаётся при создании;
   - `values` типа `[Key: Value]` — сами записи, по умолчанию пустой словарь;
   - `order` типа `[Key]` — ключи от самого старого к самому новому, по умолчанию пустой массив.
2. Метод `set(_:for:)`: значение без метки, ключ с меткой `for`.
   - Если `limit` меньше 1, метод ничего не делает.
   - Если такой ключ уже есть, значение заменяется, а ключ переезжает в конец `order` — запись стала самой свежей.
   - Если ключа нет, а записей уже `limit` штук, сначала удаляется самая старая запись — первый ключ из `order` — и из `order`, и из `values`.
   - Новый ключ добавляется в конец `order`.
3. Метод `value(for:)` возвращает `Value?` — значение по ключу или `nil`. Порядок он не меняет.
4. Вычисляемое свойство `count` типа `Int` — сколько записей сейчас хранится.

Создаваться хранилище будет так: `LimitedStore<String, String>(limit: 50)`.

### Пример
```swift
var drafts = LimitedStore<String, String>(limit: 2)
drafts.set("Привет! Завтра в силе?", for: "chat-7")
drafts.set("Счёт во вложении", for: "chat-12")
drafts.set("Привет! Завтра в 10?", for: "chat-7")   // обновили — chat-7 теперь самый свежий
drafts.order                    // ["chat-12", "chat-7"]

drafts.set("Купить корм", for: "chat-3")           // места нет — уходит самый старый, chat-12
drafts.order                    // ["chat-7", "chat-3"]
drafts.value(for: "chat-12")    // nil
drafts.count                    // 2
```

## @solution
```swift
// Хранилище «ключ — значение» с лимитом записей.
// Добавь параметры типа Key (Hashable) и Value
struct LimitedStore<Key: Hashable, Value> {
    // 1. Лимит, записи и порядок ключей (от старых к новым)
    let limit: Int
    var values: [Key: Value] = [:]
    var order: [Key] = []

    // 2. Сохранить значение: обновить или добавить, при нехватке места убрать самую старую запись
    mutating func set(_ value: Value, for key: Key) {
        guard limit >= 1 else {
            return
        }
        if values[key] != nil {
            order = order.filter { $0 != key }
        } else if order.count >= limit {
            let oldest = order.remove(at: 0)
            values.removeValue(forKey: oldest)
        }
        values[key] = value
        order.append(key)
    }

    // 3. Значение по ключу
    func value(for key: Key) -> Value? {
        return values[key]
    }

    // 4. Сколько записей сейчас хранится
    var count: Int {
        values.count
    }
}
```

## @rules
- must: /struct\s+LimitedStore\s*<\s*Key\s*:\s*Hashable\s*,\s*Value\s*>/ :: Объяви у `LimitedStore` два параметра типа в таком порядке: `<Key: Hashable, Value>`.
- must: /let\s+limit\s*:\s*Int/ :: Лимит не меняется после создания — объяви его константой: `let limit: Int`.

## @hint1
Начни с объявления: в угловых скобках после имени — два параметра типа через запятую. Первый — тип ключа, с ограничением `Hashable`, потому что ключи будут лежать в словаре. Второй — тип значения, без ограничений.

Свойства: лимит — константа без значения по умолчанию, её задают при создании. Словарь записей и массив ключей — переменные, по умолчанию пустые. Тип словаря — от `Key` к `Value`, тип массива — массив `Key`.

Метод `set` меняет свойства, значит, он `mutating`. Внутри по шагам:

1. Через `guard` отсеки лимит меньше единицы — просто выйди.
2. Если ключ уже есть в словаре (значение по ключу не равно `nil`), убери этот ключ из `order` — например, отфильтруй массив, оставив все ключи, кроме этого.
3. Иначе, если ключей уже столько, сколько разрешает лимит, удали первый ключ из `order` и соответствующую запись из `values`.
4. В любом случае запиши значение в словарь и добавь ключ в конец `order`.

`value(for:)` просто читает словарь. `count` — количество записей в словаре.

## @hint2
Два параметра типа объявляются через запятую, ограничение — только у ключа:

```swift
struct LimitedStore<Key: Hashable, Value> {
    let limit: Int
    var values: [Key: Value] = [:]
    var order: [Key] = []
}
```

А самая старая запись удаляется так: `remove(at: 0)` убирает первый элемент массива и возвращает его.

```swift
let oldest = order.remove(at: 0)
values.removeValue(forKey: oldest)
```

## @hint3
Свойства и простые методы готовы. Заполни пропуски в `set`:

```swift
mutating func set(_ value: Value, for key: Key) {
    guard limit >= 1 else {
        return
    }
    if values[key] != nil {
        order = order.filter { ___ }
    } else if ___ {
        let oldest = order.remove(at: 0)
        values.removeValue(forKey: oldest)
    }
    values[key] = value
    ___
}
```

В первом пропуске — условие «этот ключ не равен `key`». Во втором — «ключей уже не меньше лимита». В третьем — добавление ключа в конец порядка.

## @hint4
Вот готовое решение:

{{solution}}

**Как это работает.** `LimitedStore<Key: Hashable, Value>` — чертёж с двумя «дырками». Когда «Почтальон» пишет `LimitedStore<String, String>(limit: 50)`, ключи и значения становятся строками. Когда «Ярмарка» пишет `LimitedStore<Int, Product>(limit: 20)` — ключи числами, значения товарами. Порядок в угловых скобках важен: первым всегда идёт тип ключа.

Ограничение `Hashable` стоит только у `Key`. Без него не собрался бы словарь `[Key: Value]`. А значения хранятся «как есть», поэтому `Value` может быть чем угодно — даже типом, который не умеет сравниваться. Именно поэтому наличие ключа проверяется через `values[key] != nil`, а не через сравнение значений.

`set` разбирает три случая. Ключ уже есть — `filter` убирает его из середины `order`, и в конце метода он добавится заново, последним. Ключа нет и места нет — `order.remove(at: 0)` достаёт самый старый ключ, и его запись удаляется из словаря. Ключа нет и место есть — ничего удалять не нужно. Последние две строки общие для всех случаев, поэтому стоят после `if`.

Почему `>=`, а не `==`: условие срабатывает ровно на границе, когда записей уже `limit`, и при этом защищает от любых неожиданностей.

**Типичные ошибки:**

- ограничение `Hashable` поставлено у `Value` вместо `Key` — словарь не соберётся;
- при обновлении ключ не удалён из `order` — он окажется там дважды;
- самая старая запись удалена из `order`, но осталась в `values` — `count` перестанет совпадать с лимитом;
- проверка места стоит до проверки «ключ уже есть» без `else` — тогда обновление в полном хранилище зря выбросит старую запись.
